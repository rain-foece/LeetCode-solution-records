# 多数元素（Majority Element）题解

> 题目链接：[LeetCode 169. Majority Element](https://leetcode.cn/problems/majority-element/)

## 题目描述

给定一个大小为 `n` 的数组 `nums`，返回其中的**多数元素**。多数元素是指在数组中出现次数**大于 ⌊ n/2 ⌋** 的元素。

你可以假设数组是非空的，并且给定的数组总是存在多数元素。

**示例 1：**

```
输入：nums = [3,2,3]
输出：3
```

**示例 2：**

```
输入：nums = [2,2,1,1,1,2,2]
输出：2
```

---

## 题引：L 朝代末年家族乱斗

> 我们注意到，多数元素的个数比其他元素加起来还多。
>
> 原来是消耗战！
>
> 想象一下 L 朝代末年家族乱斗：我们只需要用 `blood` 表示当前 top1 家族的血量。如果下一个数是这个家族的，那么这个家族的血量 +1；如果不是就 -1。血量归零就换下一个家族，取缔成功。
>
> 很明显，最强的家族总会留到最后。

---

## 核心思路：Boyer-Moore 投票算法

这道题最优雅的解法是 Boyer-Moore 投票算法，核心思想就是**消耗战**：

- 多数元素的数量 > 其他所有元素的数量之和。
- 让不同元素两两抵消（同归于尽），最后活下来的必定是多数元素。

具体操作：
1. 维护一个候选人 `ans` 和血量 `blood`。
2. 遍历数组，遇到和 `ans` 相同的元素则 `blood + 1`，不同则 `blood - 1`。
3. 当 `blood` 降到 0 时，说明当前候选人被消耗殆尽，下一个元素取而代之。

为什么这样是对的？因为多数元素超过半数，即使所有其他元素都来围攻它，它也能用数量优势把对方耗死。

---

## 代码

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        int ans = nums[0], blood = 0;
        for (int i : nums) {
            if (i == ans) ++blood;
            else --blood;
            if (blood == 0) {
                ans = i;
                ++blood;
            }
        }
        return ans;
    }
};
```

---

## 代码分析

以 `nums = [2, 2, 1, 1, 1, 2, 2]` 为例：

| 步骤 | i | ans | blood | 操作 |
|:---:|:---:|:---:|:---:|------|
| 初始 | — | 2 | 0 | ans 初始化为 2 |
| 1 | 2 | 2 | **1** | `i == ans`，blood +1 |
| 2 | 2 | 2 | **2** | `i == ans`，blood +1 |
| 3 | 1 | 2 | **1** | `i != ans`，blood -1 |
| 4 | 1 | 2 | **0** | `i != ans`，blood -1 → 归零！切换候选人 |
| 5 | 1 | 1 | **1** | 切换为 1，blood = 1 |
| 6 | 2 | 1 | **0** | `i != ans`，blood -1 → 归零！切换候选人 |
| 7 | 2 | 2 | **1** | 切换为 2，blood = 1 |

最终 `ans = 2`，正是多数元素。2 出现了 4 次，比其他元素（1 出现 3 次）只多一个，但就是这一个优势让它笑到了最后。

## 复杂度分析

| 指标 | 值 |
|:---|:---|
| 时间复杂度 | O(n) |
| 空间复杂度 | O(1) |

只遍历一次数组，只用两个变量 `ans` 和 `blood`，严格 O(1) 额外空间。

---

## 拓展：为什么必须存在多数元素？

如果题目不保证多数元素存在（比如 `[1, 2, 3]`），Boyer-Moore 算法会返回最后一个候选人，但这个人未必是多数。此时需要**第二轮遍历**验证候选人的出现次数是否真的 > n/2。

本题明确保证了多数元素一定存在，所以一轮遍历即可。

---

## 总结

这道题是 Boyer-Moore 投票算法的经典模板，核心就一句话：**多数元素的数量超过其他所有元素之和，所以消耗战必胜**。

| 对比 | 136. 只出现一次的数字 | 169. 多数元素 |
|:---|:---|:---|
| 技巧 | 异或运算 | 投票算法 |
| 核心原理 | 相同归零 | 两两抵消 |
| 空间 | O(1) | O(1) |
| 数学本质 | `a ^ a = 0` | `count(majority) > sum(count(others))` |

两道题都是 O(n) 时间 + O(1) 空间的极致优化，思路都是"让相同的互相抵消，剩下那个就是答案"。136 靠异或让数字自己抵消，169 靠血量让不同元素互相消耗。
