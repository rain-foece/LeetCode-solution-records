# 下一个排列（Next Permutation）题解

> 题目链接：[LeetCode 31. Next Permutation](https://leetcode.cn/problems/next-permutation/)

## 题目描述

整数数组的一个**排列**就是将其所有成员以序列或线性顺序排列。

例如，`arr = [1,2,3]`，以下这些都可以视作 `arr` 的排列：`[1,2,3]`、`[1,3,2]`、`[3,1,2]`、`[2,3,1]`。

整数数组的**下一个排列**是指其整数的下一个字典序更大的排列。更正式地，如果数组的所有排列根据其字典顺序从小到大排列在一个容器中，那么数组的**下一个排列**就是在这个有序容器中排在它后面的那个排列。如果不存在下一个更大的排列，那么这个数组必须重排为字典序最小的排列（即，其元素按升序排列）。

**示例 1：**

```
输入：nums = [1,2,3]
输出：[1,3,2]
```

**示例 2：**

```
输入：nums = [3,2,1]
输出：[1,2,3]
```

**示例 3：**

```
输入：nums = [1,1,5]
输出：[1,5,1]
```

---

## 核心思路

下一个排列需要满足一个"条件"和一个"尽量"：

1. **条件**：要比原排列字典序来得大（除非原排列已经是最大排列）
2. **尽量**：满足条件下尽可能地小

这对应算法的两个步骤：

- **第一步**：找比原排列大的排列 → 把某个**后置大数**和某个**前置小数**交换
- **第二步**：让找到的排列尽可能地小 → 对交换后的后半段做最小化处理

### 为什么必须相邻比较？

从右往左找到第一个递增对 `nums[i] < nums[i+1]`。这个位置 `i` 就是**第一个可以被替换的前置小数**：

- `i` 右边的元素是递减的（因为一路扫过来都是 `>=`）
- 递减意味着 `[i+1, n-1]` 已经是这个后缀的最大排列，光靠调整后半段已经无法变大了
- 必须把 `nums[i]` 换成一个更大的数，才能让整个排列变大

找到 `i` 后，在 `[i+1, n-1]` 中从右往左找第一个比 `nums[i]` 大的数 `nums[j]`（因为递减，所以第一个比它大的就是最小的那个），交换二者。

交换后，`[i+1, n-1]` 仍然是递减的，直接反转即可得到这个后缀的最小排列。

## 代码

```cpp
class Solution {
public:
    void nextPermutation(vector<int>& nums) {
        int n = nums.size();

        // 第一步：从右到左找到第一个小于 nums[i+1] 的数 nums[i]
        int i = n - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) {
            --i;
        }

        // 如果找到了，进入第二步；否则跳过第二步，反转整个数组
        if (i >= 0) {
            // 第二步：从右到左找到 nums[i] 右边最小的大于 nums[i] 的数 nums[j]
            int j = n - 1;
            while (nums[j] <= nums[i]) {
                --j;
            }
            // 交换 nums[i] 和 nums[j]
            swap(nums[i], nums[j]);
        }

        // 第三步：反转 [i+1, n-1]（如果上面跳过第二步，此时 i = -1）
        reverse(nums.begin() + i + 1, nums.end());
    }
};
```

## 代码分析

算法分为三步，逻辑清晰：

| 步骤 | 操作 | 目的 |
|:---:|------|------|
| 1 | 从右找 `nums[i] < nums[i+1]` 的位置 `i` | 定位第一个可以增大的"前置小数" |
| 2 | 从右找 `nums[j] > nums[i]` 的位置 `j`，交换 | 用最小的"后置大数"替换 `nums[i]` |
| 3 | 反转 `[i+1, n-1]` | 将递减后缀变为递增，得到最小排列 |

如果第一步找不到 `i`（即 `i = -1`），说明整个数组是递减的，已经是最大排列，直接反转整个数组即可得到最小排列。

### 逐轮推演

以 `nums = [1, 2, 4, 3]` 为例：

**第一步：找 `i`**

```
1  2  4  3
   ↑  ↑
   i i+1
```

从右往左扫描：`4 >= 3`（递减，继续），`2 < 4`（找到递增对！），`i = 1`。

**第二步：找 `j` 并交换**

```
1  2  4  3
   ↑     ↑
   i     j
```

在 `[2, n-1]` 即 `[4, 3]` 中从右找第一个大于 `nums[1] = 2` 的数：`3 > 2`，`j = 3`。

交换 `nums[1]` 和 `nums[3]`：

```
1  3  4  2
```

**第三步：反转后缀**

```
1  3 | 4  2
      | 后缀
反转后：
1  3 | 2  4
```

结果：`[1, 3, 2, 4]`。

验证：`[1,2,4,3]` 的所有排列按字典序排列：`[1,2,4,3]` → `[1,3,2,4]` → `[1,3,4,2]` → `[1,4,2,3]` → ...，下一个确实是 `[1,3,2,4]`。

### 边界情况

以 `nums = [3, 2, 1]`（最大排列）为例：

```
3  2  1
```

第一步：`2 >= 1`（递减），`3 >= 2`（递减），`i = -1`。

`i < 0`，跳过第二步，直接反转整个数组：`[1, 2, 3]`，即最小排列。

## 复杂度分析

| 指标 | 值 |
|:---|:---|
| 时间复杂度 | O(n) |
| 空间复杂度 | O(1) |

两步扫描各 O(n)，反转 O(n)，整体 O(n)。只用了一个 `i` 和 `j` 变量，原地操作。

**拓展**：第二步找 `j` 时，由于 `[i+1, n-1]` 是递减的，可以用二分查找在 O(log n) 时间内找到 `j`。但整体复杂度仍是 O(n)（反转操作无法优化），所以二分只是常数优化。

---

## 总结

这道题是字典序排列的经典算法，三步走：

1. **从右找"上山点"**：`nums[i] < nums[i+1]`，这是可以被替换的最小位置
2. **从右找"最小的大数"**：`nums[j] > nums[i]`，用最小的代价让排列变大
3. **反转后缀**：后半段已经是递减的，反转即得最小排列

关键洞察：第一步保证 `i` 之后是递减的，所以找到的 `j` 就是后缀中比 `nums[i]` 大的最小数。交换后后缀仍递减，反转就是最小化。整个算法一气呵成，没有多余操作。
