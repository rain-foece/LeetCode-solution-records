# 环形链表 II（Linked List Cycle II）题解

> 题目链接：[LeetCode 142. Linked List Cycle II](https://leetcode.cn/problems/linked-list-cycle-ii/)

## 题目描述

给定一个链表的头节点 `head`，返回链表开始入环的第一个节点。如果链表无环，则返回 `null`。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（索引从 0 开始）。如果 `pos` 是 `-1`，则在该链表中没有环。注意：`pos` 不作为参数进行传递，仅仅是为了标识链表的实际情况。

**不允许修改链表。**

**示例 1：**

```
输入：head = [3,2,0,-4], pos = 1
输出：返回索引为 1 的链表节点
解释：链表中有一个环，其尾部连接到第二个节点。
```

**示例 2：**

```
输入：head = [1,2], pos = 0
输出：返回索引为 0 的链表节点
解释：链表中有一个环，其尾部连接到第一个节点。
```

**示例 3：**

```
输入：head = [1], pos = -1
输出：返回 null
解释：链表中没有环。
```

---

## 核心思路

这种题一看就是快慢指针问题。整个算法分为两个阶段：

**阶段一：判断是否有环。** 快指针每次走两步，慢指针每次走一步。如果有环，两者必然相遇（就像操场跑圈，快的人一定会追上慢的人）。如果无环，快指针会先走到 `null`。

**阶段二：找到入环点。** 相遇后，把快指针移回链表头，然后快慢指针**同步每次走一步**。再次相遇的点，就是入环的第一个节点。

第二个阶段听起来很神奇——为什么这样就能找到入环点？下面给出数学证明。

---

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode(int x) : val(x), next(NULL) {}
 * };
 */
class Solution {
public:
    ListNode *detectCycle(ListNode *head) {
        ListNode *fast = head;
        ListNode *slow = head;

        // 阶段一：快慢指针判断是否有环
        while (fast && fast->next) {
            slow = slow->next;              // 慢指针走一步
            fast = fast->next->next;        // 快指针走两步

            if (slow == fast) {             // 相遇，有环

                // 阶段二：找入环点
                fast = head;                // 快指针回到起点
                while (fast != slow) {
                    fast = fast->next;      // 两个指针同步走一步
                    slow = slow->next;
                }
                return fast;                // 再次相遇处即为入环点
            }
        }
        return NULL;                        // 无环
    }
};
```

## 数学证明：为什么第二阶段能找到入环点？

设链表结构如下：

```
head → ... → (入环点 A) → ... → (相遇点 B) → ... → 回到 A
   |←  a  →|       |←   b  →|       |←   c  →|
```

- `a`：从 `head` 到入环点 `A` 的距离（不含 `A`）
- `b`：从入环点 `A` 到相遇点 `B` 的距离（含 `B`）
- `c`：从相遇点 `B` 绕回入环点 `A` 的距离（不含 `A` 和 `B`）
- 环长 = `b + c`

**第一阶段相遇时：**

慢指针走了 `a + b` 步，快指针走了 `a + b + k(b + c)` 步（`k` 是快指针多绕的圈数）。

因为快指针速度是慢指针的两倍：`2(a + b) = a + b + k(b + c)`

化简得：`a + b = k(b + c)` → `a = k(b + c) - b = (k - 1)(b + c) + c`

**关键结论：`a = c + (k - 1) × 环长`**

也就是说，从头节点到入环点的距离 `a`，等于从相遇点绕回入环点的距离 `c` 加上若干整圈。

**第二阶段：**

把快指针移回 `head`，两个指针同步每次走一步。慢指针从 `B` 走 `c` 步到达入环点 `A`，快指针从 `head` 走 `a` 步也到达入环点 `A`——因为 `a = c + 整圈`，所以两者在 `A` 必然相遇（慢指针可能多绕了圈）。

## 逐轮推演

以 `head = [3 → 2 → 0 → -4 → (回到 2)]` 为例，`pos = 1`（入环点是 `2`）：

```
链表：3 → 2 → 0 → -4
         ↑__________|
```

**阶段一：快慢指针**

| 步数 | slow 位置 | fast 位置 | 说明 |
|------|----------|----------|------|
| 初始 | 3 | 3 | |
| 1 | 2 | 0 | slow 走一步，fast 走两步 |
| 2 | 0 | 2 | slow 走一步，fast 走两步 |
| 3 | -4 | -4 | slow 走一步，fast 走两步 → **相遇！** |

相遇点在 `-4`。

**阶段二：找入环点**

把 `fast` 移回 `head`（节点 `3`），`slow` 留在 `-4`，两者同步每次走一步：

| 步数 | slow 位置 | fast 位置 | 说明 |
|------|----------|----------|------|
| 0 | -4 | 3 | 初始 |
| 1 | 2 | 2 | **相遇！** |

相遇点在 `2`，正是入环点。返回节点 `2`。

---

## 复杂度分析

- **时间复杂度**：O(n)。第一阶段快慢指针最多走 O(n) 步，第二阶段最多走 O(n) 步。
- **空间复杂度**：O(1)。只用了两个指针。

---

## 总结

这道题是快慢指针的经典应用。巧妙之处在于第二阶段——第一次相遇后，把快指针移回头节点，两指针同步走，再次相遇就是入环点。这个结论不是凭空猜出来的，而是有严格的数学推导支撑。

理解它的关键在于记住一个公式：**`a = c + 整圈`**。头到入环点的距离，恰好等于相遇点绕回入环点的距离加上若干整圈。所以从头和从相遇点同时出发，必然在入环点汇合。
