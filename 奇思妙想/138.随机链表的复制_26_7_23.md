# 随机链表的复制（Copy List with Random Pointer）题解

> 题目链接：[LeetCode 138. Copy List with Random Pointer](https://leetcode.cn/problems/copy-list-with-random-pointer/)

## 题目描述

给你一个长度为 `n` 的链表，每个节点包含一个额外增加的随机指针 `random`，该指针可以指向链表中的任何节点或空节点。

构造这个链表的**深拷贝**。深拷贝应该正好由 `n` 个全新节点组成，其中每个新节点的值都设为其对应的原节点的值。新节点的 `next` 指针和 `random` 指针也都应指向复制链表中的新节点，并使原链表和复制链表中的这些指针能够表示相同的链表状态。**复制链表中的指针都不应指向原链表中的节点**。

例如，如果原链表中有 `X` 和 `Y` 两个节点，其中 `X.random --> Y`。那么在复制链表中对应的两个节点 `x` 和 `y`，同样有 `x.random --> y`。

返回复制链表的头节点。

**示例 1：**

```
输入：head = [[7,null],[13,0],[11,4],[10,2],[1,0]]
输出：[[7,null],[13,0],[11,4],[10,2],[1,0]]
```

**示例 2：**

```
输入：head = [[1,1],[2,1]]
输出：[[1,1],[2,1]]
```

---

## 核心思路概览

本文将从两个版本展开，将空间复杂度从 O(n) 优化到 O(1)：

| 版本 | 方法 | 核心思想 |
|------|------|----------|
| 版本一 | 递归 + 哈希表 | 用哈希表记录「原节点 → 新节点」的映射，递归复制 |
| 版本二 | 交错链表（灵神） | 把新节点插在原节点后面，利用 `原节点.next = 新节点` 充当映射，空间 O(1) |

---

## 版本一：递归 + 哈希表

### 思路

这道题如果没有 `random` 指针，就是普通的链表复制。但有了 `random` 指针后，问题变复杂了——我们复制 `random` 时，需要知道原节点 `random` 指向的节点，在新链表中对应哪个节点。

最直接的想法：用一个哈希表记录「原节点 → 新节点」的映射。递归过程中，先检查当前节点是否已经复制过（在哈希表中），如果没复制过就创建新节点、存入哈希表，然后递归复制 `next` 和 `random`。

这个想法只要想到了就能实现。

### 代码

```cpp
/*
// Definition for a Node.
class Node {
public:
    int val;
    Node* next;
    Node* random;

    Node(int _val) {
        val = _val;
        next = NULL;
        random = NULL;
    }
};
*/

class Solution {
public:
    unordered_map<Node*, Node*> hash;       // 原节点 → 新节点

    Node* copyRandomList(Node* head) {
        if (!head) return nullptr;

        if (!hash.count(head)) {            // 还没复制过这个节点
            Node *newhead = new Node(head->val);
            hash[head] = newhead;           // 记录映射
            newhead->next = copyRandomList(head->next);    // 递归复制 next
            newhead->random = copyRandomList(head->random); // 递归复制 random
        }
        return hash[head];                  // 返回已复制的新节点
    }
};
```

### 分析

递归版非常简洁，哈希表保证了每个节点只被复制一次。`hash.count(head)` 检查是否已复制，避免了重复创建和死循环（比如 `random` 指回前面的节点时）。

- **时间复杂度**：O(n)，每个节点只复制一次。
- **空间复杂度**：O(n)，哈希表存 n 个映射，递归栈深度 O(n)。

**优点**：思路直观，代码简洁，递归逻辑清晰。

**缺点**：递归栈开销大，哈希表占用 O(n) 额外空间。有没有办法优化呢？

## 版本二：交错链表（灵神）

> 思路来源：[灵茶山艾府 - 不用哈希表的做法](https://leetcode.cn/problems/copy-list-with-random-pointer/solutions/2993775/bu-yong-ha-xi-biao-de-zuo-fa-pythonjavac-nzdo/)

### 思路

灵神真的是天才！

哈希表的作用是记录「原节点 → 新节点」的映射。但如果我们能**不借助额外空间**来建立这个映射呢？

答案是：**把新节点直接插在原节点的后面**，让链表变成交错结构：

```
原链表： 1 → 2 → 3
交错后： 1 → 1' → 2 → 2' → 3 → 3'
```

这样一来，**原节点的下一个节点，就是它对应的新节点**。不需要哈希表，映射关系天然存在！

整个算法分三步：

1. **插入**：遍历原链表，在每个原节点后面插入一个复制节点。
2. **复制 random**：遍历交错链表，对于每个原节点，如果它有 `random`，那么新节点的 `random` 就是 `原节点.random.next`（因为 `random` 指向的原节点后面紧跟着它的复制节点）。
3. **分离**：把交错链表拆成原链表和新链表，还原原链表，返回新链表。

### 代码

```cpp
class Solution {
public:
    Node* copyRandomList(Node* head) {
        if (!head) return nullptr;

        // 第一步：在每个原节点后面插入新节点
        // 1 → 2 → 3  →  1 → 1' → 2 → 2' → 3 → 3'
        Node *cur = head;
        while (cur) {
            Node *newNode = new Node(cur->val);
            newNode->next = cur->next;
            cur->next = newNode;
            cur = newNode->next;              // 跳到下一个原节点
        }

        // 第二步：设置新节点的 random 指针
        // 如果 cur.random = X，则 cur.next.random = X.next（即 X 的复制节点）
        cur = head;
        while (cur) {
            if (cur->random) {
                cur->next->random = cur->random->next;
            }
            cur = cur->next->next;            // 跳到下一个原节点
        }

        // 第三步：分离两个链表（类似 328. 奇偶链表）
        Node *dummy = new Node(0);            // 新链表的哑节点
        Node *copyCur = dummy;
        cur = head;
        while (cur) {
            copyCur->next = cur->next;        // 摘出新节点
            copyCur = copyCur->next;
            cur->next = cur->next->next;      // 恢复原链表
            cur = cur->next;
        }

        return dummy->next;
    }
};
```

### 分析

#### 第一步：插入新节点

```
cur = head;
while (cur) {
    newNode = new Node(cur->val);
    newNode->next = cur->next;
    cur->next = newNode;
    cur = newNode->next;  // 跳过刚插入的新节点，到下一个原节点
}
```

每一步操作：

```
cur → next → ...        cur → newNode → next → ...
       ↓          →         ↓
     原链表               newNode 插入后
```

`cur = newNode->next` 确保下次循环处理的是下一个原节点，不会把新节点也处理一遍。

#### 第二步：复制 random 指针

```
cur = head;
while (cur) {
    if (cur->random) {
        cur->next->random = cur->random->next;
    }
    cur = cur->next->next;
}
```

这是最精妙的一步！假设原节点 `A` 的 `random` 指向 `B`：

```
A → A' → ... → B → B' → ...
```

那么 `A->random = B`，`A->random->next = B'`。所以 `A->next->random = A->random->next = B'`，即新节点 `A'` 的 `random` 正确指向了新节点 `B'`。

不需要哈希表查询，只需要一次 `next` 跳转，因为复制节点就紧跟在原节点后面！

#### 第三步：分离链表

```
cur = head;
dummy → ?
while (cur) {
    copyCur->next = cur->next;    // 摘下新节点，接到新链表
    cur->next = cur->next->next;  // 原节点跳过新节点，恢复原链表
    cur = cur->next;              // 移动到下一个原节点
    copyCur = copyCur->next;      // 移动到新链表末尾
}
```

本质就是 [328. 奇偶链表](https://leetcode.cn/problems/odd-even-linked-list/) 的分离操作。`cur->next` 总是新节点，`cur->next->next` 总是下一个原节点。

## 逐轮推演

以 `head = [[7,null],[13,0],[11,4],[10,2],[1,0]]` 为例，即：

```
7 → 13 → 11 → 10 → 1
↓    ↓    ↓    ↓    ↓
Ø    7    1    11   7
```

**第一步：插入**

| 步骤 | cur | newNode | 操作 | 链表状态 |
|------|-----|---------|------|----------|
| 初始 | 7 | — | — | 7→13→11→10→1 |
| 1 | 7 | 7' | 7'插在7后 | 7→7'→13→11→10→1 |
| 2 | 13 | 13' | 13'插在13后 | 7→7'→13→13'→11→10→1 |
| 3 | 11 | 11' | 11'插在11后 | 7→7'→13→13'→11→11'→10→1 |
| 4 | 10 | 10' | 10'插在10后 | 7→7'→13→13'→11→11'→10→10'→1 |
| 5 | 1 | 1' | 1'插在1后 | 7→7'→13→13'→11→11'→10→10'→1→1' |

**第二步：复制 random**

| cur | cur.random | cur.random.next | cur.next(新节点) | 设置 |
|-----|-----------|-----------------|-----------------|------|
| 7 | null | — | 7' | 7'.random = null |
| 13 | 7 | 7' | 13' | 13'.random = 7' |
| 11 | 1 | 1' | 11' | 11'.random = 1' |
| 10 | 11 | 11' | 10' | 10'.random = 11' |
| 1 | 7 | 7' | 1' | 1'.random = 7' |

**第三步：分离**

| 步骤 | cur | cur.next(新节点) | cur.next.next(下一个原节点) | 新链表 |
|------|-----|-----------------|--------------------------|--------|
| 1 | 7 | 7' | 13 | 7' |
| 2 | 13 | 13' | 11 | 7'→13' |
| 3 | 11 | 11' | 10 | 7'→13'→11' |
| 4 | 10 | 10' | 1 | 7'→13'→11'→10' |
| 5 | 1 | 1' | null | 7'→13'→11'→10'→1' |

最终返回新链表：`7'→13'→11'→10'→1'`，各节点的 `random` 均正确指向新链表中的对应节点。

## 复杂度分析

- **时间复杂度**：O(n)，三步遍历，每步 O(n)。
- **空间复杂度**：O(1)，只用了几个指针，返回值不计入空间。

## 总结

两个版本的核心问题都是同一个：**如何知道原节点的 random 在新链表中对应哪个节点？**

版本一用哈希表直接做映射，版本二则用了一个更巧妙的方法——**把新节点插在原节点后面，让「原节点.next = 新节点」这个关系天然充当映射**。不需要额外的哈希表，也不需要递归，三步走完，空间 O(1)。

灵神这个思路的精妙之处在于：它把「映射」这种抽象的数据结构，用链表本身的拓扑结构来表达。这种「用数据结构本身来编码信息」的技巧，在 [41. 缺失的第一个正数](../思路解析/41.缺失的第一个正数_26_7_22.md)（原地哈希）和 [73. 矩阵置零](../思路解析/73.矩阵置零_26_7_22.md)（牺牲第一行/列做标记）中都出现过，是原地算法的经典范式。

和 [25. K 个一组翻转链表](25.K个一组翻转链表_26_7_23.md) 一样，版本二也大量使用了哑节点（dummy）来统一分离操作。链表题中，哑节点几乎是一个「标配」——当你需要操作头节点时，它能让所有节点的处理逻辑保持一致。
