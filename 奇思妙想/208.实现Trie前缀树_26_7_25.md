# 实现 Trie（前缀树）题解

> 题目链接：[LeetCode 208. Implement Trie (Prefix Tree)](https://leetcode.cn/problems/implement-trie-prefix-tree/)

## 题目描述

**Trie**（发音类似 "try"）或者说**前缀树**是一种树形数据结构，用于高效地存储和检索字符串数据集中的键。这一数据结构有相当多的应用情景，例如自动补全和拼写检查。

请你实现 Trie 类：

- `Trie()` 初始化前缀树对象。
- `void insert(String word)` 向前缀树中插入字符串 `word`。
- `boolean search(String word)` 如果字符串 `word` 在前缀树中，返回 `true`；否则，返回 `false`。
- `boolean startsWith(String prefix)` 如果之前已经插入的字符串 `word` 的前缀之一为 `prefix`，返回 `true`；否则，返回 `false`。

**示例：**

```
输入：
["Trie", "insert", "search", "search", "startsWith", "insert", "search"]
[[], ["apple"], ["apple"], ["app"], ["app"], ["app"], ["app"]]
输出：
[null, null, true, false, true, null, true]

解释：
Trie trie = new Trie();
trie.insert("apple");
trie.search("apple");   // 返回 true
trie.search("app");     // 返回 false
trie.startsWith("app"); // 返回 true
trie.insert("app");
trie.search("app");     // 返回 true
```

## 核心思路

这道题很多人拿到都一脸雾水——「前缀树」是什么？怎么实现？我也是学习了题解后才想到这么奇妙的方法。

其实 Trie 的本质就是一棵**26 叉树**。每个节点有 26 个孩子指针，分别对应 26 个小写字母 `a-z`。从根节点开始，沿着字符串的每个字符一路走下去，路径上的节点就构成了这个字符串。

举个例子，插入 `"apple"` 和 `"app"` 后，Trie 的结构如下：

```
root
 └─ a
     └─ p
         └─ p (isEnd=true, "app"的终点)
             └─ l
                 └─ e (isEnd=true, "apple"的终点)
```

插入 `"app"` 时，`a → p → p` 这条路径已经存在，不需要新建节点，只需在最后一个 `p` 上标记 `isEnd = true`。

**关键设计**：用 `next[c - 'a']` 来索引。`c - 'a'` 把字符 `'a'` 到 `'z'` 映射到索引 `0` 到 `25`，天然充当了数组下标。

---

## 代码

```cpp
class Trie {
private:
    bool isEnd;                  // 标记当前节点是否是一个完整单词的结尾
    Trie *next[26];              // 26 个孩子，对应 a-z

public:
    Trie() {
        isEnd = false;
        memset(next, 0, sizeof(next));  // 所有孩子指针初始化为 nullptr
    }

    void insert(string word) {
        Trie *node = this;
        for (char c : word) {
            int idx = c - 'a';           // 字符映射到索引 0-25
            if (node->next[idx] == NULL) {
                node->next[idx] = new Trie();  // 没有就新建节点
            }
            node = node->next[idx];      // 沿路径前进
        }
        node->isEnd = true;              // 单词结尾标记
    }

    bool search(string word) {
        Trie *node = this;
        for (char c : word) {
            int idx = c - 'a';
            if (!node->next[idx]) return false;  // 路径断了，不存在
            node = node->next[idx];
        }
        return node->isEnd;              // 必须恰好是完整单词
    }

    bool startsWith(string prefix) {
        Trie *node = this;
        for (char c : prefix) {
            int idx = c - 'a';
            if (!node->next[idx]) return false;  // 路径断了，前缀不存在
            node = node->next[idx];
        }
        return true;                     // 只要路径存在即可，不要求是完整单词
    }
};
```

## 代码分析

### 26 叉树的结构

每个 Trie 节点包含两个核心成员：

```cpp
bool isEnd;          // 当前节点是一个完整单词的结尾吗？
Trie *next[26];      // 26 个分支，对应 26 个小写字母
```

`next` 数组的索引就是 `c - 'a'`，这是一个非常巧妙的映射：

| 字符 | `c - 'a'` | 索引 |
|------|-----------|------|
| `'a'` | 0 | 0 |
| `'b'` | 1 | 1 |
| `'c'` | 2 | 2 |
| ... | ... | ... |
| `'z'` | 25 | 25 |

不需要哈希表，不需要 `switch-case`，一行 `c - 'a'` 就完成了字符到索引的映射。

### `insert`：沿途建节点

```cpp
void insert(string word) {
    Trie *node = this;
    for (char c : word) {
        if (node->next[c - 'a'] == NULL) {
            node->next[c - 'a'] = new Trie();  // 新建分支
        }
        node = node->next[c - 'a'];
    }
    node->isEnd = true;  // 最后一个节点打上"单词结尾"标记
}
```

逻辑很简单：沿着 word 的每个字符往下走，如果某条分支不存在就新建，走到底后标记 `isEnd = true`。

注意：即使 word 的某个前缀已经存在（比如先插 `"apple"` 再插 `"app"`），中间路径上的节点不会重复创建，只是走到已有的节点上，最后在 `"app"` 的最后一个 `p` 上标记 `isEnd`。

### `search`：必须精准匹配

```cpp
bool search(string word) {
    Trie *node = this;
    for (char c : word) {
        if (!node->next[c - 'a']) return false;  // 路径中断
        node = node->next[c - 'a'];
    }
    return node->isEnd;  // 必须走到一个完整单词的结尾
}
```

和 `insert` 几乎一样，只是把「新建节点」换成了「检查是否为空」。最后返回 `node->isEnd`，确保 `word` 是一个完整插入过的单词，而不是某个更长单词的前缀。

### `startsWith`：只要路径存在

```cpp
bool startsWith(string prefix) {
    Trie *node = this;
    for (char c : prefix) {
        if (!node->next[c - 'a']) return false;
        node = node->next[c - 'a'];
    }
    return true;  // 不需要 isEnd，前缀不一定是完整单词
}
```

和 `search` 的唯一区别是：最后直接返回 `true`，不检查 `isEnd`。因为前缀不需要是完整单词——只要路径存在就行。

### `search` 和 `startsWith` 的差异

这是面试中常被问到的问题。两者的区别仅在于最后一行：

```cpp
// search：必须恰好是完整单词
return node->isEnd;

// startsWith：只要路径存在即可
return true;
```

## 逐轮推演

以插入 `"apple"` 和 `"app"`，然后查询为例：

**插入 `"apple"`：**

```
root  →  a  →  p  →  p  →  l  →  e (isEnd=true)
```

**插入 `"app"`：**

```
root  →  a  →  p  →  p (isEnd=true)
                         →  l  →  e (isEnd=true)
```

`a → p → p` 已存在，不新建节点，只在第二个 `p` 上标记 `isEnd`。

**查询 `search("app")`：**

```
root → a → p → p (isEnd=true) → 返回 true
```

**查询 `search("ap")`：**

```
root → a → p (isEnd=false) → 返回 false
```

路径存在，但 `p` 不是单词结尾。

**查询 `startsWith("ap")`：**

```
root → a → p → 返回 true
```

路径存在即可，不检查 `isEnd`。

**查询 `startsWith("apl")`：**

```
root → a → p → p → l → 返回 true
```

**查询 `search("apx")`：**

```
root → a → p → x(不存在) → 返回 false
```

## 复杂度分析

设插入的单词总长度为 `L`，要查询的单词长度为 `W`。

- **时间复杂度**：
  - `insert`：O(L)，每个字符走一步。
  - `search`：O(W)。
  - `startsWith`：O(W)。
- **空间复杂度**：O(T × 26)，其中 T 是所有插入单词的节点总数。最坏情况下每个字符都新建一个节点，T = 所有插入单词的字符总数。每个节点有 26 个指针，但很多指针是空的。

---

## 总结

Trie 的核心思想就是**用空间换时间**——把字符串的公共前缀压缩在同一条路径上，查询时只需逐字符往下走，不需要比较字符串。这种「26 叉树」的设计非常巧妙，用 `c - 'a'` 把字符映射到数组索引，省去了复杂的哈希或查找逻辑。

和哈希表对比：

| 对比维度 | Trie | 哈希表 |
|---------|------|--------|
| 查询完整单词 | O(W) | O(1) 平均 |
| 前缀匹配 | O(W) | 不支持 |
| 空间 | 每个节点 26 个指针 | 每个键一个桶 |
| 适用场景 | 自动补全、拼写检查、前缀统计 | 精确查找 |

Trie 的独特优势是**前缀匹配**——哈希表做不到 `startsWith`。这使得 Trie 在自动补全、拼写检查、IP 路由最长前缀匹配等场景中不可替代。

这种「用树结构编码字符串」的思想，和 [138. 随机链表的复制](../链表/138.随机链表的复制_26_7_23.md) 中「用链表拓扑编码映射」的思路一脉相承——都是用数据结构本身来存储信息，而不是依赖外部的哈希表。
