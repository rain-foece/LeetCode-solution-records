# 颜色分类（Sort Colors）题解

> 题目链接：[LeetCode 75. Sort Colors](https://leetcode.cn/problems/sort-colors/)

## 题目描述

给定一个包含红色、白色和蓝色、共 `n` 个元素的数组 `nums`，**原地**对它们进行排序，使得相同颜色的元素相邻，并按照红色、白色、蓝色顺序排列。

我们使用整数 `0`、`1` 和 `2` 分别表示红色、白色和蓝色。

必须在不使用库内置的 `sort` 函数的情况下解决这个问题。

**示例 1：**

```
输入：nums = [2,0,2,1,1,0]
输出：[0,0,1,1,2,2]
```

**示例 2：**

```
输入：nums = [2,0,1]
输出：[0,1,2]
```

## 题引：灾难救援

> 想象一下，灾难来临，A、B 两支救援队前往保护灾民，但是远处的一场爆炸产生的冲击波，瞬间将原本的队伍拆乱。这时队长（`p`）就需要分别从队伍的两侧向中间整顿队伍。
>
> 队长选择从左到右整队，首先他找了两个坐标 `L` 和 `R`，用来记录找到的灾民的两端。而队长就开始向后寻找救援队员，一旦发现救援队员，就把队员和所在救援队相应坐标的灾民调换，随后将坐标收缩，直到队长找到 `R`，证明整个队伍整编完毕。
>
> 当灾难来临，总有人不顾一切地保护你！

---

## 核心思路：三指针（荷兰国旗问题）

这道题是经典的**荷兰国旗问题**（Dutch National Flag Problem），用三个指针一次遍历完成原地排序：

| 指针 | 含义 | 维护的区域 |
|:---:|------|------|
| `left` | 0 的右边界 | `[0, left)` 全是 0 |
| `right` | 2 的左边界 | `(right, n-1]` 全是 2 |
| `p` | 当前扫描位置 | `[left, p)` 全是 1，`[p, right]` 待处理 |

队长的策略：
- 遇到 **0**（救援队 A）：换到 `left` 位置，`left` 和 `p` 都右移。因为换过来的一定是 1（`[left, p)` 区间全是 1，`p` 已经扫描过了），所以 `p` 可以安全前进。
- 遇到 **2**（救援队 B）：换到 `right` 位置，`right` 左移。注意 `p` **不能**前进，因为换过来的值还没被检查过。
- 遇到 **1**（灾民）：原地不动，`p` 右移即可。

## 代码

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;
        int p = 0;
        while (p <= right) {
            if (nums[p] == 0) {
                swap(nums[p], nums[left]);
                ++left;
                ++p;
            } else if (nums[p] == 2) {
                swap(nums[p], nums[right]);
                --right;
            } else {
                ++p;
            }
        }
    }
};
```

---

## 代码分析

**为什么 `nums[p] == 0` 时 `p` 可以前进，而 `nums[p] == 2` 时不行？**

- 当 `nums[p] == 0` 时，`swap(nums[p], nums[left])` 换过来的是 `nums[left]`。由于 `p >= left` 且 `[left, p)` 区间的元素已经全部被扫描过，必定是 1，所以换过来的值一定是 1，`p` 可以安全前进。
- 当 `nums[p] == 2` 时，`swap(nums[p], nums[right])` 换过来的是 `nums[right]`。这个值来自未扫描区域，可能是 0、1 或 2，必须留在原地等待下一轮检查，所以 `p` 不能前进。

### 逐轮推演

以 `nums = [2, 0, 2, 1, 1, 0]` 为例：

| 轮次 | p | left | right | nums | 操作 |
|:---:|:---:|:---:|:---:|------|------|
| 初始 | 0 | 0 | 5 | `[2, 0, 2, 1, 1, 0]` | — |
| 1 | 0 | 0 | 5 | `[2, 0, 2, 1, 1, 0]` | `nums[0]=2`，与 `right` 交换，`right--` |
| 2 | 0 | 0 | 4 | `[0, 0, 2, 1, 1, 2]` | `nums[0]=0`，与 `left` 交换，`left++`，`p++` |
| 3 | 1 | 1 | 4 | `[0, 0, 2, 1, 1, 2]` | `nums[1]=0`，与 `left` 交换，`left++`，`p++` |
| 4 | 2 | 2 | 4 | `[0, 0, 2, 1, 1, 2]` | `nums[2]=2`，与 `right` 交换，`right--` |
| 5 | 2 | 2 | 3 | `[0, 0, 1, 1, 2, 2]` | `nums[2]=1`，`p++` |
| 6 | 3 | 2 | 3 | `[0, 0, 1, 1, 2, 2]` | `nums[3]=1`，`p++` |
| 结束 | 4 | 2 | 3 | `[0, 0, 1, 1, 2, 2]` | `p > right`，结束 |

最终 `nums = [0, 0, 1, 1, 2, 2]`，原地排序完成。

**关键观察**：第 2 轮 `nums[0]` 从 2 变成了 0（因为 `right` 换过来的），而 `p` 没有前进，所以 0 在下一轮被正确处理。这就是为什么 `nums[p] == 2` 时不能 `p++`。

## 复杂度分析

| 指标 | 值 |
|:---|:---|
| 时间复杂度 | O(n) |
| 空间复杂度 | O(1) |

只遍历一次数组，`left` 和 `right` 相向收缩，每个元素最多被交换一次。

## 总结

这道题是荷兰国旗问题的标准模板，三指针一气呵成：

| 指针 | 角色 | 移动规则 |
|:---:|------|------|
| `left` | 0 的边界哨兵 | 只在换入 0 时右移 |
| `right` | 2 的边界哨兵 | 只在换入 2 时左移 |
| `p` | 扫描队长 | 遇 0 和 1 前进，遇 2 不动 |

只有一个易错点：**`nums[p] == 2` 时 `p` 不能前进**，因为 `right` 换过来的值还未被检查。

这道题和 283. 移动零 思路类似——283 是把 0 挪到最后（两指针），75 是把 0 挪到最前、2 挪到最后（三指针）。两者的本质都是**分区**（partition），只是分区数量从 2 个变成了 3 个。
