# 无重复字符的最长子串（Longest Substring Without Repeating Characters）题解

> 题目链接：[LeetCode 3. Longest Substring Without Repeating Characters](https://leetcode.cn/problems/longest-substring-without-repeating-characters/)

## 题目描述

给定一个字符串 `s`，请你找出其中不含有重复字符的**最长子串**的长度。

**示例 1：**

```
输入：s = "abcabcbb"
输出：3
解释：因为无重复字符的最长子串是 "abc"，所以其长度为 3。
```

**示例 2：**

```
输入：s = "bbbbb"
输出：1
解释：因为无重复字符的最长子串是 "b"，所以其长度为 1。
```

**示例 3：**

```
输入：s = "pwwkew"
输出：3
解释：因为无重复字符的最长子串是 "wke"，所以其长度为 3。
     请注意，你的答案必须是子串的长度，"pwke" 是一个子序列，不是子串。
```

> **注意**：这里要求的是「子串」而非「子序列」。子串要求字符在原字符串中连续，而子序列不需要。关于子序列与子串的区别，可以参考[最长公共子序列题解](../动态规划/1143.最长公共子序列_26_6_7.md)。

## 核心思路

这道题是滑动窗口的经典应用。我们维护一个窗口 `[l, r]`，窗口内的字符全部不重复。用一个右指针 `r` 不断向右探索，会遇到两种情况：

- **情况一**：`s[r]` 在当前窗口中未出现过。直接扩展窗口，更新答案。
- **情况二**：`s[r]` 在当前窗口中已经出现了。由于窗口是向后延伸的，前面出现的重复字符必须被排除。我们需要把左边界 `l` 移动到重复字符上一次出现位置的**后一位**，从而保证窗口内不再有重复。

搞清楚了这两个情况，整个题目的框架就有了。

## 代码

```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        if (s.empty()) return 0;

        unordered_map<char, int> hash;  // 记录每个字符最后一次出现的位置
        int n = s.size(), ans = 0;
        int l = 0;                      // 窗口左边界

        for (int r = 0; r < n; ++r) {
            char c = s[r];

            // 如果 c 在窗口内出现过（hash[c] >= l），则收缩左边界
            if (hash.count(c) && hash[c] >= l) {
                l = hash[c] + 1;         // 跳到重复字符的后一位
            }

            hash[c] = r;                 // 更新 c 的最新位置
            ans = max(ans, r - l + 1);   // 更新答案
        }
        return ans;
    }
};
```

## 代码分析

### 数据结构选择

用 `unordered_map<char, int>` 来记录每个字符**最后一次出现的位置**。为什么不用 `unordered_set` 只记录「是否出现过」？因为当遇到重复字符时，我们需要知道它**上一次出现的位置**，才能把左边界 `l` 精确地跳过去。如果只知道「出现过」而不知道「在哪」，就无法确定新的左边界。

### 关键条件：`hash[c] >= l`

这一行是整个算法的灵魂。

```cpp
if (hash.count(c) && hash[c] >= l) {
    l = hash[c] + 1;
}
```

先看 `hash.count(c)`：判断字符 `c` 是否在之前出现过。但光知道「出现过」还不够——如果 `c` 上一次出现的位置在 `l` 之前（即窗口之外），那么它对当前窗口没有影响，不需要收缩左边界。

所以 `hash[c] >= l` 这个条件确保了：**只有当重复字符确实出现在当前窗口内部时，才需要收缩左边界**。

如果满足条件，`l = hash[c] + 1` 将左边界跳到重复字符的后一位，窗口内的字符再次全部不重复。

### 为什么不需要从 hash 中删除元素？

你可能会想：左边界 `l` 移动后，[old_l, new_l) 之间的字符不就被"丢弃"了吗？为什么不需要从 hash 中删除它们？

因为我们用 `hash[c] >= l` 来判断字符是否在窗口内。那些被丢弃的字符，虽然还留在 hash 中，但它们的位置已经小于 `l`，所以 `hash[c] >= l` 这个条件不会触发，它们就相当于"不存在"了。这是一种懒惰删除的策略，非常巧妙。

## 逐轮推演

以 `s = "abcabcbb"` 为例：

| 轮次 | r | s[r] | hash 内容 | l | hash[c]>=l? | 窗口 | ans |
|------|---|------|-----------|----|------------|------|-----|
| 1 | 0 | a | `{a:0}` | 0 | — | `[0,0]="a"` | 1 |
| 2 | 1 | b | `{a:0,b:1}` | 0 | — | `[0,1]="ab"` | 2 |
| 3 | 2 | c | `{a:0,b:1,c:2}` | 0 | — | `[0,2]="abc"` | 3 |
| 4 | 3 | a | `{a:0,b:1,c:2}` | 0 | a=0≥0 → l=1 | `[1,3]="bca"` | 3 |
| | | | `{a:3,b:1,c:2}` | 1 | | | |
| 5 | 4 | b | `{a:3,b:1,c:2}` | 1 | b=1≥1 → l=2 | `[2,4]="cab"` | 3 |
| | | | `{a:3,b:4,c:2}` | 2 | | | |
| 6 | 5 | c | `{a:3,b:4,c:2}` | 2 | c=2≥2 → l=3 | `[3,5]="abc"` | 3 |
| | | | `{a:3,b:4,c:5}` | 3 | | | |
| 7 | 6 | b | `{a:3,b:4,c:5}` | 3 | b=4≥3 → l=5 | `[5,6]="cb"` | 3 |
| | | | `{a:3,b:6,c:5}` | 5 | | | |
| 8 | 7 | b | `{a:3,b:6,c:5}` | 5 | b=6≥5 → l=7 | `[7,7]="b"` | 3 |
| | | | `{a:3,b:7,c:5}` | 7 | | | |

最终 `ans = 3`，即子串 `"abc"`。

## 复杂度分析

- **时间复杂度**：O(n)。右指针 `r` 遍历一次字符串，每次哈希表操作 O(1)。
- **空间复杂度**：O(|Σ|)，其中 |Σ| 是字符集大小。哈希表最多存储所有不同字符的位置，对于 ASCII 字符集是常数级 O(128)，对于 Unicode 则取决于实际字符种类。

## 总结

这道题的核心是**滑动窗口**，而滑动窗口的核心在于两个指针的协作：

- `r` 负责探索，每次循环必定前进一步，不断扩大窗口。
- `l` 只在遇到窗口内重复字符时才前移，收缩窗口以保证无重复。

两个关键细节值得注意：

1. **`hash[c] >= l`**：判断重复字符是否真的在窗口内，而不是在已经被丢弃的历史位置中。
2. **懒惰删除**：不主动从 hash 中删除过期元素，而是通过 `>= l` 来隐式判定，节省了删除操作的开销。

这两点结合起来，让代码既简洁又高效，是滑动窗口类问题的经典范式。
