# 最小覆盖子串（Minimum Window Substring）题解

> 题目链接：[LeetCode 76. Minimum Window Substring](https://leetcode.cn/problems/minimum-window-substring/)

## 题目描述

给定两个字符串 `s` 和 `t`，返回 `s` 中涵盖 `t` 所有字符的最小子串。如果 `s` 中不存在涵盖 `t` 所有字符的子串，则返回空字符串 `""`。

**示例 1：**

```
输入：s = "ADOBECODEBANC", t = "ABC"
输出："BANC"
```

**示例 2：**

```
输入：s = "a", t = "a"
输出："a"
```

**示例 3：**

```
输入：s = "a", t = "aa"
输出：""
```

---

## 核心思路

这道题是滑动窗口的进阶应用。和 [3. 无重复字符的最长子串](../双指针/3.无重复字符的最长子串_26_7_21.md) 一样，右指针扩展、左指针收缩。但难点在于如何高效判断窗口是否「覆盖」了 `t` 中的所有字符（包括重复字符）。

一个极其巧妙的做法是用一个 `diff` 数组，把「还需要多少」和「已经有多少」**合并到一个变量**中，同时用一个 `count` 来追踪已满足的字符种类数。

---

## 代码

```cpp
class Solution {
public:
    string minWindow(string s, string t) {
        int n = s.size(), l = 0, kinds = 0, count = 0;
        int diff[128] = {0};                 // 差值数组，覆盖所有 ASCII 字符

        // 初始化：t 中每个字符"欠"的数量用负数表示
        for (char c : t) {
            if (diff[c] == 0) {
                ++kinds;                     // 统计 t 中不同字符的种类数
            }
            --diff[c];                       // 负数 = 还差几个
        }

        int ans_l = -1, ans_r = n;           // 记录最短窗口

        for (int r = 0; r < n; ++r) {
            // 右指针扩展：当前字符进入窗口
            ++diff[s[r]];
            if (diff[s[r]] == 0) {
                ++count;                     // 该字符从"欠"变为"刚好"，满足种类 +1
            }

            // 窗口已覆盖所有字符，尝试收缩左边界
            while (count >= kinds) {
                if (r - l < ans_r - ans_l) {
                    ans_l = l;               // 更新最短窗口
                    ans_r = r;
                }

                // 左指针收缩：当前字符离开窗口
                if (diff[s[l]] == 0) --count; // 从"刚好"变为"欠"
                --diff[s[l]];
                ++l;
            }
        }

        return ans_l < 0 ? "" : s.substr(ans_l, ans_r - ans_l + 1);
    }
};
```

---

## 代码分析

### diff 数组：一个变量，三种含义

这是整个算法最精妙的设计。`diff[c]` 同时承载三种语义：

| diff[c] 的值 | 含义 |
|-------------|------|
| 负数 | 窗口中还**缺少** `abs(diff[c])` 个字符 `c` |
| 0 | 窗口中**刚好满足**字符 `c` 的需求 |
| 正数 | 窗口中**超出**了字符 `c` 的需求 |

以 `t = "ABC"` 为例，初始化后：`diff['A'] = -1, diff['B'] = -1, diff['C'] = -1`。随着右指针扩展，`diff[s[r]]` 每次加 1。当 `diff['A']` 从 -1 变成 0 时，说明 A 的缺口被填平了，`count++`。

### count 和 kinds：追踪覆盖状态

- `kinds`：`t` 中**不同字符的种类数**（`t = "AABC"` 时 `kinds = 3`，因为只有 A、B、C 三种）
- `count`：当前窗口中，**已经满足需求的字符种类数**

当 `count == kinds` 时，窗口有效。之后收缩左边界，如果某个字符从 `diff[c] == 0` 变为 `diff[c] == -1`（即从"刚好"变为"欠"），`count--`，窗口失效。

### 为什么用 128 而不是 26？

题目中 `s` 和 `t` 可以包含大写字母（示例中就有），128 覆盖了所有标准 ASCII 字符。

### 收缩时 count 的判断

```cpp
if (diff[s[l]] == 0) --count;
```

当 `diff[s[l]] == 0` 时，该字符在窗口中**刚好满足需求**。它离开后就会从"刚好"变成"不足"，所以 `count--`。如果 `diff[s[l]] > 0`，说明窗口中有多余的该字符，离开一个不影响覆盖，`count` 不变。

## 逐轮推演

以 `s = "ADOBECODEBANC", t = "ABC"` 为例，`kinds = 3`：

| 轮次 | r | 窗口 | count | 有效? | 收缩 | ans |
|------|---|------|-------|-------|------|-----|
| 初始 | — | — | 0 | 否 | — | — |
| 1 | 0 | `[0,0]="A"` | 1 | 否 | — | — |
| 2 | 1 | `[0,1]="AD"` | 1 | 否 | — | — |
| 3 | 2 | `[0,2]="ADO"` | 1 | 否 | — | — |
| 4 | 3 | `[0,3]="ADOB"` | 2 | 否 | — | — |
| 5 | 4 | `[0,4]="ADOBE"` | 2 | 否 | — | — |
| 6 | 5 | `[0,5]="ADOBEC"` | 3 | **是** | 收缩至 l=1 | `[0,5]` |
| 7~9 | 6~8 | 窗口扩展中 | 2 | 否 | — | — |
| 10 | 9 | `[1,9]="DOBECODEB"` | 2 | 否 | — | — |
| 11 | 10 | `[1,10]="DOBECODEBA"` | 3 | **是** | 收缩至 l=4 | — |
| 12 | 11 | `[4,11]="ECODEBAN"` | 2 | 否 | — | — |
| 13 | 12 | `[4,12]="ECODEBANC"` | 3 | **是** | 收缩至 l=9 | `[9,12]` |

最终 `ans = [9, 12]`，即 `"BANC"`，长度 4。

## 复杂度分析

- **时间复杂度**：O(n)。右指针遍历一次，左指针也只前进不后退，每个字符最多被访问两次。
- **空间复杂度**：O(1)。`diff[128]` 是固定大小，与输入规模无关。

---

## 总结

这道题的核心在于 `diff` 数组的设计——用一个变量承载「需要 / 刚好 / 超出」三种状态，配合 `count` 追踪满足的字符种类数，让覆盖判断变成 O(1) 操作。这种「负值表示需求，0 表示刚好满足」的计数技巧，在涉及字符频率的滑动窗口问题中非常实用。

理解它的关键点：

1. **`diff` 的三种语义**：负 = 欠，0 = 刚好，正 = 多余
2. **`count` 只在 `diff` 跨越 0 时变化**：从负到 0 时 `count++`，从 0 到负时 `count--`
3. **收缩时不需要清理 `diff`**：超出窗口的字符 `diff` 值为负，不会被误判为满足
