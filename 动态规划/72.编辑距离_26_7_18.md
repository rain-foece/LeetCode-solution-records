# 编辑距离（Edit Distance）题解

> 题目链接：[LeetCode 72. Edit Distance](https://leetcode.cn/problems/edit-distance/)

## 题目描述

给你两个单词 `word1` 和 `word2`，请返回将 `word1` 转换成 `word2` 所使用的最少操作数。

你可以对一个单词进行如下三种操作：

- 插入一个字符
- 删除一个字符
- 替换一个字符

**示例 1：**

```
输入：word1 = "horse", word2 = "ros"
输出：3
解释：
horse -> rorse (将 'h' 替换为 'r')
rorse -> rose (删除 'r')
rose -> ros (删除 'e')
```

**示例 2：**

```
输入：word1 = "intention", word2 = "execution"
输出：5
```

---

## 核心思路概览

编辑距离是动态规划的经典问题，本文将从四个递进的版本展开：

| 版本 | 方法 | 核心思想 |
|------|------|----------|
| 版本一 | 递归 + 记忆化搜索 | 自顶向下，用 `memo` 数组缓存已计算结果，**引用**是关键 |
| 版本二 | 二维 DP 递推 | 1:1 翻译为自底向上的二维 DP，消除递归栈开销 |
| 版本三 | 滚动数组优化 | 观察到每轮只依赖前一行，用两行轮转将空间降至 O(m) |
| 版本四 | 单数组 + 临时变量 | 进一步发现只需两个临时变量保存被覆盖的值，空间不变但更精巧 |

下面逐一分析。

---

## 版本一：递归 + 记忆化搜索

### 思路

定义 `dfs(i, j)` 表示将 `s[0..i]` 转换为 `t[0..j]` 所需的最少操作数。每一次操作都有四种选择：

- **不变**：如果 `s[i] == t[j]`，直接递归到 `dfs(i-1, j-1)`，无需操作。
- **删除**：删除 `s[i]`，问题变为 `dfs(i-1, j) + 1`。
- **插入**：在 `s` 末尾插入 `t[j]`，问题变为 `dfs(i, j-1) + 1`。
- **替换**：将 `s[i]` 替换为 `t[j]`，问题变为 `dfs(i-1, j-1) + 1`。

由于递归会产生大量重复计算，我们用 `memo` 数组做记忆化。**这里 `int& res = memo[i][j]` 的引用是关键** — 修改 `res` 即直接修改 `memo[i][j]`，省去重复的数组下标访问，代码也更简洁。

### 代码

```cpp
class Solution {
public:
    int minDistance(string s, string t) {
        int n = s.size(), m = t.size();
        vector<vector<int>> memo(n, vector<int>(m, -1));  // -1 表示未计算

        auto dfs = [&](this auto&& dfs, int i, int j) -> int {
            if (i < 0) return j + 1;  // s 为空，需要插入 t[0..j] 的所有字符
            if (j < 0) return i + 1;  // t 为空，需要删除 s[0..i] 的所有字符

            int& res = memo[i][j];  // 引用！修改 res 即修改 memo[i][j]
            if (res != -1) return res;  // 已计算过，直接返回

            if (s[i] == t[j])
                return res = dfs(i - 1, j - 1);  // 末尾相同，无需操作

            return res = min({dfs(i - 1, j),      // 删除 s[i]
                              dfs(i, j - 1),      // 插入 t[j]
                              dfs(i - 1, j - 1)}) // 替换 s[i] 为 t[j]
                       + 1;
        };

        return dfs(n - 1, m - 1);
    }
};
```

### 分析

这个版本是编辑距离最直观的表达，几乎就是状态转移方程的直接翻译。

**递归基**：当 `i < 0`（`s` 为空）时，需要把 `t[0..j]` 全部插入，操作数为 `j + 1`；当 `j < 0`（`t` 为空）时，需要把 `s[0..i]` 全部删除，操作数为 `i + 1`。

**状态转移**：末尾字符相同时，无需任何操作，直接对齐前一位；末尾不同时，取删除、插入、替换三种操作中的最小值再加一。

**关于引用**：`int& res = memo[i][j]` 这一行是写法上的点睛之笔。如果不使用引用，后续每次读写 `memo[i][j]` 都需要两次索引运算，且代码中 `memo[i][j]` 反复出现，可读性差。用引用绑定后，`res` 就是 `memo[i][j]` 的别名，赋值 `res = ...` 同时完成了缓存和返回，一举两得。

**复杂度**：时间 O(nm)，空间 O(nm)。每个状态只计算一次，记忆化确保了这一点。

**优点**：思路清晰，代码几乎就是状态转移方程的直译，适合入门理解。

**缺点**：递归调用栈开销较大，在极端输入下可能触发栈溢出。

## 版本二：二维 DP 递推

### 思路

版本一是「自顶向下」的递归，版本二将其 1:1 翻译为「自底向上」的递推。用二维数组 `dp[i][j]` 表示将 `s[0..i-1]` 转换为 `t[0..j-1]` 的最少操作数。

这里 `dp` 的下标从 1 开始（0 留给空串哨兵），所以 `dp[i][j]` 对应版本一中 `s[i-1]` 与 `t[j-1]` 的比较。

### 代码

```cpp
class Solution {
public:
    int minDistance(string s, string t) {
        int n = s.size(), m = t.size();
        vector dp(n + 1, vector<int>(m + 1, 0));

        // 初始化：s 为空或 t 为空的情况
        for (int i = 1; i <= n; ++i) dp[i][0] = i;  // 删除所有字符
        for (int j = 1; j <= m; ++j) dp[0][j] = j;  // 插入所有字符

        for (int i = 1; i <= n; ++i) {
            for (int j = 1; j <= m; ++j) {
                if (s[i - 1] == t[j - 1])
                    dp[i][j] = dp[i - 1][j - 1];  // 末尾相同，无需操作
                else
                    dp[i][j] = min({dp[i - 1][j - 1],  // 替换
                                    dp[i - 1][j],      // 删除
                                    dp[i][j - 1]})     // 插入
                             + 1;
            }
        }
        return dp[n][m];
    }
};
```

### 分析

这版去掉了递归开销，改为双层循环递增填充 `dp` 表。初始化时，`dp[i][0] = i` 表示将长度为 `i` 的 `s` 转换为空串需要 `i` 次删除；`dp[0][j] = j` 表示将空串转换为长度为 `j` 的 `t` 需要 `j` 次插入。

状态转移的对应关系：

| 版本一（递归） | 版本二（递推） | 含义 |
|---|---|---|
| `dfs(i-1, j-1)` | `dp[i-1][j-1]` | 替换 / 匹配 |
| `dfs(i-1, j)` | `dp[i-1][j]` | 删除 |
| `dfs(i, j-1)` | `dp[i][j-1]` | 插入 |

双层循环保证每个状态依赖的子问题都已求解。时间 O(nm)，空间 O(nm)。

**优点**：无递归栈开销，代码结构清晰，是后续空间优化的基础。

**缺点**：O(nm) 的空间在处理长字符串时比较浪费。

## 版本三：滚动数组优化

### 思路

观察版本二的递推式，`dp[i][j]` 只依赖三个值：

```
dp[i-1][j-1]  （左上角，替换）
dp[i-1][j]    （正上方，删除）
dp[i][j-1]    （正左方，插入）
```

也就是说，计算第 `i` 行时**只需要第 `i-1` 行的数据**，更早的行完全用不到。因此我们可以用两个数组轮转：一个保存上一行，一个计算当前行，将空间从 O(nm) 压缩到 O(2m)。

轮转的写法是 `i % 2` 和 `(i + 1) % 2` 交替，像滚动条一样来回切换，形象地称为「滚动数组」。

### 代码

```cpp
class Solution {
public:
    int minDistance(string s, string t) {
        int n = s.length(), m = t.length();
        vector dp(2, vector<int>(m + 1));

        // 初始化第一行：s 为空时，全部插入
        for (int j = 0; j < m; j++) {
            dp[0][j + 1] = j + 1;
        }

        for (int i = 0; i < n; i++) {
            dp[(i + 1) % 2][0] = i + 1;  // 当前行的第 0 列：t 为空，全部删除
            for (int j = 0; j < m; j++) {
                dp[(i + 1) % 2][j + 1] = s[i] == t[j]
                    ? dp[i % 2][j]                                      // 匹配，取左上角
                    : min({dp[i % 2][j + 1],                            // 删除（正上方）
                           dp[(i + 1) % 2][j],                          // 插入（正左方）
                           dp[i % 2][j]})                               // 替换（左上角）
                      + 1;
            }
        }
        return dp[n % 2][m];
    }
};
```

### 分析

滚动数组的核心在于 `i % 2` 和 `(i + 1) % 2` 的交替 —— 当 `i` 为偶数时，上一行在 `dp[0]`，当前行写 `dp[1]`；当 `i` 为奇数时则反过来。两个数组像传送带一样轮转，每次只保留最近两行的数据。

注意这里的索引方式与版本二略有不同：版本二用 `dp[i][j]` 表示 `s[0..i-1]` 与 `t[0..j-1]`，而版本三用 `dp[i % 2][j]` 的映射。但本质完全一致，只是把二维下标 `i` 压缩到了 `i % 2`。

**复杂度**：时间 O(nm)，空间 O(m)。

**优点**：空间从 O(nm) 直降到 O(m)，且改动量小，只需在版本二的基础上把 `dp[i]` 替换为 `dp[i % 2]`、`dp[i-1]` 替换为 `dp[(i+1) % 2]`。

**缺点**：`% 2` 的取模运算和行索引切换让代码可读性有所下降。

## 版本四：单数组 + 两个临时变量（终极优化）

### 思路

版本三用两个数组轮转，但我们再仔细看：每次计算 `dp[i][j]` 时，需要的是：

- `dp[i-1][j-1]` — 左上角（上一行的前一列）
- `dp[i-1][j]` — 正上方（上一行的当前列，更新前）
- `dp[i][j-1]` — 正左方（当前行的前一列，已更新）

如果我们只用一个数组 `dp`，在更新 `dp[j]` 时：
- **正上方**就是当前的 `dp[j]`（还未被覆盖，是旧值）
- **正左方**就是 `dp[j-1]`（已被更新为新值）
- **左上角**已经被 `dp[j-1]` 的更新覆盖掉了，这正是问题所在！

解决方法：用两个临时变量 `pre` 和 `now`：
- `pre`：保存 `dp[i-1][j-1]`（左上角），在每一轮 `j` 循环中更新
- `now`：暂存即将被覆盖的 `dp[j]`（即 `dp[i-1][j]`，正上方），用于下一轮作为左上角

### 代码

```cpp
class Solution {
public:
    int minDistance(string s, string t) {
        int n = s.size(), m = t.size();
        vector<int> dp(m + 1, 0);

        // 初始化：s 为空时，全部插入
        for (int j = 0; j <= m; ++j) dp[j] = j;

        for (int i = 1; i <= n; ++i) {
            int pre = dp[0];  // pre 保存左上角 dp[i-1][j-1]，初始为 dp[i-1][0]
            dp[0] = i;        // 当前行第 0 列：t 为空，全部删除

            for (int j = 1; j <= m; ++j) {
                int now = dp[j];  // 暂存正上方 dp[i-1][j]，它即将被覆盖
                if (s[i - 1] == t[j - 1])
                    dp[j] = pre;  // 匹配，直接取左上角
                else
                    dp[j] = min({dp[j - 1],   // 插入（正左方，已更新）
                                 pre,         // 替换（左上角，由 pre 保存）
                                 now})        // 删除（正上方，由 now 暂存）
                          + 1;
                pre = now;  // 为下一列 j+1 准备左上角
            }
        }
        return dp[m];
    }
};
```

### 逐轮推演

以 `s = "horse"`, `t = "ros"` 为例，`dp` 初始为 `[0, 1, 2, 3]`。

**i = 1（处理 s[0] = 'h'）**：

| j | pre (左上角) | now (旧 dp[j]) | 更新 dp[j] | 新 pre |
|---|-------------|----------------|-----------|--------|
| 1 | dp[0]=0 | dp[1]=1 | h≠r → min(0,0,1)+1=1 | 1 |
| 2 | 1 | dp[2]=2 | h≠o → min(1,1,2)+1=2 | 2 |
| 3 | 2 | dp[3]=3 | h≠s → min(2,2,3)+1=3 | 3 |

一轮后 `dp = [1, 1, 2, 3]`，正确。

**i = 2（处理 s[1] = 'o'）**：

| j | pre | now | 更新 dp[j] | 新 pre |
|---|-----|-----|-----------|--------|
| 1 | dp[0]=1 | dp[1]=1 | o≠r → min(1,1,1)+1=2 | 1 |
| 2 | 1 | dp[2]=2 | o==o → pre=1 | 2 |
| 3 | 2 | dp[3]=3 | o≠s → min(1,2,3)+1=2 | 3 |

一轮后 `dp = [2, 2, 1, 2]`，正确。

**i = 3（处理 s[2] = 'r'）**：

| j | pre | now | 更新 dp[j] | 新 pre |
|---|-----|-----|-----------|--------|
| 1 | dp[0]=2 | dp[1]=2 | r==r → pre=2 | 2 |
| 2 | 2 | dp[2]=1 | r≠o → min(2,2,1)+1=2 | 1 |
| 3 | 1 | dp[3]=2 | r≠s → min(2,1,2)+1=2 | 2 |

一轮后 `dp = [3, 2, 2, 2]`，正确。

**i = 4, 5** 依此类推，最终 `dp[3] = 3`，即将 "horse" 转为 "ros" 需要 3 步。

**复杂度**：时间 O(nm)，空间 O(m)。

**关键点**：`pre` 和 `now` 两个变量各司其职 —— `pre` 始终持有左上角的值，`now` 在 `dp[j]` 被覆盖前抢救出正上方的值，然后 `pre = now` 让这个值在下一列成为新的左上角。理解了这个接力过程，就理解了整个优化。

## 补充：还可以更省空间吗？

我们还可以选择 `s` 和 `t` 中较短的那个作为 `dp` 数组的长度，这样空间复杂度可以降到 O(min(n, m))。不过这点优化在实际中通常不是必须的，本文不再展开实现。感兴趣的读者可以自行尝试，本质上就是把 `m` 替换为 `min(n, m)` 并在外层循环中做相应的角色互换。

## 总结

四个版本展示了编辑距离问题从直观到高效的完整优化路径：

1. **版本一**（递归 + 记忆化）：自顶向下，直接表达状态转移方程，`引用` 的运用让代码简洁优雅，适合入门理解。
2. **版本二**（二维 DP）：去掉递归栈开销，翻译为标准递推，是后续优化的跳板。
3. **版本三**（滚动数组）：利用「只依赖前一行」的性质，用两行轮转将空间从 O(nm) 降到 O(m)。
4. **版本四**（单数组 + 临时变量）：进一步发现只需两个临时变量就能补偿被覆盖的值，用单个数组完成迭代，代码精巧且空间最优。

理解版本四是本文的核心目标 —— 关键在于想清楚 `pre`（左上角）和 `now`（正上方）在滚动更新中的角色，以及它们如何在每一列之间传递。一旦掌握这个技巧，其他类似的二维 DP 空间优化问题也能举一反三。
