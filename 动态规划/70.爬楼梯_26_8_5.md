# 爬楼梯（Climbing Stairs）题解

> 题目链接：[LeetCode 70. Climbing Stairs](https://leetcode.cn/problems/climbing-stairs/)

## 题目描述

假设你正在爬楼梯。需要 `n` 阶你才能到达楼顶。

每次你可以爬 1 或 2 个台阶。你有多少种不同的方法可以爬到楼顶呢？

`1 <= n <= 45`

**示例 1：**

```
输入：n = 2
输出：2
解释：有两种方法可以爬到楼顶。
1. 1 阶 + 1 阶
2. 2 阶
```

**示例 2：**

```
输入：n = 3
输出：3
解释：有三种方法可以爬到楼顶。
1. 1 阶 + 1 阶 + 1 阶
2. 1 阶 + 2 阶
3. 2 阶 + 1 阶
```

---

## 核心思路

这是一道经典的动态规划题目。我们首先想到的是递归，因为递归思路更容易。

假设我们在第 `n` 阶，那上一步在哪呢？只有两种可能：

- 在 `n-1` 阶跳了 1 下到 `n`
- 在 `n-2` 阶跳了 2 下到 `n`

设 `dp(n)` 为跳到第 `n` 阶的方法数，那么就有递推式：

```
dp(n) = dp(n-1) + dp(n-2)
```

边界条件：`dp(1) = 1`（只有跳 1 阶一种方法），`dp(2) = 2`（1+1 或 2）。

这其实就是斐波那契数列。下面从递归到递推，再到空间优化，层层递进。

---

## 版本一：递归

```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n == 1) return 1;
        if (n == 2) return 2;
        return climbStairs(n - 1) + climbStairs(n - 2);
    }
};
```

### 代码分析

递归直接翻译了数学定义：`dp(n) = dp(n-1) + dp(n-2)`。边界 `n=1` 返回 1，`n=2` 返回 2。

递归思路最直观，但问题也很明显：大量重复计算。例如算 `dp(5)` 时需要 `dp(4)` 和 `dp(3)`，算 `dp(4)` 又需要 `dp(3)` 和 `dp(2)`，`dp(3)` 被重复计算了多次。时间复杂度 O(2^n)，`n=45` 时会超时。

---

## 版本二：递推（DP 数组）

我们知道递归会出现不可避免的栈开销，但是递推就没有。能不能翻译成递推呢？

```cpp
class Solution {
public:
    int climbStairs(int n) {
        vector<int> dp(n);
        dp[0] = 1;                            // 第 1 阶
        for (int i = 1; i < n; ++i) {
            if (i == 1) {
                dp[i] = 2;                    // 第 2 阶
                continue;
            }
            dp[i] = dp[i - 1] + dp[i - 2];   // 递推
        }
        return dp[n - 1];
    }
};
```

### 代码分析

`dp[i]` 表示跳到第 `i+1` 阶的方法数。从 `dp[0]` 开始自底向上递推，每个状态只依赖前两个状态，不再有重复计算。

- `dp[0] = 1`：第 1 阶，1 种方法。
- `dp[1] = 2`：第 2 阶，2 种方法。
- `dp[i] = dp[i-1] + dp[i-2]`：第 `i+1` 阶，从前两阶转移过来。

时间复杂度 O(n)，空间复杂度 O(n)。

---

## 版本三：空间优化（O(1)）

我们发现，`dp[i] = dp[i-1] + dp[i-2]` 好像只用到前两位，其余的已经计算过的就没有保留的必要了。所以可以继续压缩空间，空间复杂度降到常数级。

```cpp
class Solution {
public:
    int climbStairs(int n) {
        int pre = 1, cur = 1;                  // pre = dp[i-2], cur = dp[i-1]
        for (int i = 2; i <= n; ++i) {
            int tmp = cur;
            cur += pre;                        // cur = dp[i-1] + dp[i-2]
            pre = tmp;
        }
        return cur;
    }
};
```

### 代码分析

用两个变量模拟 DP 数组的滚动：

- `pre`：`dp[i-2]`（上上个状态）
- `cur`：`dp[i-1]`（上一个状态）

每轮迭代，`cur = cur + pre` 就是 `dp[i] = dp[i-1] + dp[i-2]`，然后 `pre` 更新为旧的 `cur`。

**初始化**：`pre = 1`（即 `dp[0]`，第 1 阶），`cur = 1`（即 `dp[1]`，第 2 阶……等等，为什么是 1？）。

实际上这里用了一个小技巧：令 `dp(0) = 1`（表示"原地不动"也是一种方法），那么 `dp(2) = dp(1) + dp(0) = 1 + 1 = 2`，递推式依然成立。所以 `pre = 1`（`dp(0)`），`cur = 1`（`dp(1)`），从 `i=2` 开始递推，`n=1` 时直接返回 `cur = 1`。

---

## 逐轮推演

以 `n = 5` 为例，使用版本三：

| 轮次 | i | pre（dp[i-2]） | cur（更新前） | cur（更新后 = cur+pre） | 操作 |
|:---:|:---:|:---:|:---:|:---:|------|
| 初始 | — | 1 | 1 | — | pre=dp(0)=1, cur=dp(1)=1 |
| 1 | 2 | 1 | 1 | 1+1=2 | pre=1, cur=2（dp(2)=2） |
| 2 | 3 | 1 | 2 | 2+1=3 | pre=2, cur=3（dp(3)=3） |
| 3 | 4 | 2 | 3 | 3+2=5 | pre=3, cur=5（dp(4)=5） |
| 4 | 5 | 3 | 5 | 5+3=8 | pre=5, cur=8（dp(5)=8） |

返回 `cur = 8`。

验证：5 阶楼梯的爬法：`11111`、`1112`、`1121`、`1211`、`2111`、`122`、`212`、`221`，共 8 种。

---

## 复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 | 说明 |
|:---:|:---:|:---:|------|
| 版本一（递归） | O(2^n) | O(n) | 重复计算，会超时 |
| 版本二（DP 数组） | O(n) | O(n) | 自底向上递推 |
| 版本三（滚动变量） | O(n) | O(1) | 最优解 |

---

## 总结

这道题是动态规划的入门题，核心是发现状态转移方程 `dp(n) = dp(n-1) + dp(n-2)`。三个版本层层递进：

1. **递归**：思路最直观，但重复计算导致指数级复杂度。
2. **递推**：自底向上，用数组存储中间结果，消除重复计算。
3. **滚动变量**：发现只依赖前两个状态，用两个变量替代整个数组。

和 72. 编辑距离（二维 DP）相比，70 是一维 DP 的最简形式，状态转移只依赖前两项。这种"滚动变量"优化的思想在 155. 最小栈（`preMin[i]` 只依赖 `preMin[i-1]`）中也有体现，本质都是发现 DP 只依赖最近的几个状态，从而省去数组空间。
