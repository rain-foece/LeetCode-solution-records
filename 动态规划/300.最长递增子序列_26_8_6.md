# 最长递增子序列（Longest Increasing Subsequence）题解

> 题目链接：[LeetCode 300. Longest Increasing Subsequence](https://leetcode.cn/problems/longest-increasing-subsequence/)

## 题目描述

给你一个整数数组 `nums`，找到其中最长严格递增子序列的长度。

**子序列**是由数组派生而来的序列，删除（或不删除）数组中的元素而不改变其余元素的顺序。例如，`[3,6,2,7]` 是数组 `[0,3,1,6,2,2,7]` 的子序列。

- `1 <= nums.length <= 2500`
- `-10⁴ <= nums[i] <= 10⁴`

**示例 1：**

```
输入：nums = [10,9,2,5,3,7,101,18]
输出：4
解释：最长递增子序列是 [2,3,7,101]，因此长度为 4 。
```

**示例 2：**

```
输入：nums = [0,1,0,3,2,3]
输出：4
```

**示例 3：**

```
输入：nums = [7,7,7,7,7,7,7]
输出：1
```

---

## 核心思路

这是一个很经典的贪心 + 动态规划题目。我们从递归找思路，逐步优化到 O(n log n)。

---

## 版本一：递归 + 记忆化

对于某个下标 `i`，如何确定以它结尾的最长递增子序列的长度？我们只需要遍历所有小于 `i` 的下标 `j`，如果有 `nums[i] > nums[j]`，就返回 `dfs(j) + 1`。

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int n = nums.size();
        vector<int> memo(n);

        auto dfs = [&](this auto&& dfs, int i) -> int {
            int& res = memo[i];          // 注意这里是引用
            if (res > 0) {               // 之前计算过
                return res;
            }
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    res = max(res, dfs(j));
                }
            }
            res++;                        // 加一提到循环外面
            return res;
        };

        int ans = 0;
        for (int i = 0; i < n; i++) {
            ans = max(ans, dfs(i));
        }
        return ans;
    }
};
```

### 代码分析

- `dfs(i)` 返回以 `nums[i]` 结尾的 LIS 长度。
- 遍历 `j < i`，如果 `nums[j] < nums[i]`，则 `nums[i]` 可以接在 `nums[j]` 后面，长度 = `dfs(j) + 1`。
- `memo` 记忆化，避免重复计算。`res > 0` 表示已计算过（因为 LIS 长度至少为 1）。
- 最终答案取所有 `dfs(i)` 的最大值。

## 版本二：递推（DP）

翻译成递推，同样肥肠简单：

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int n = nums.size();
        vector<int> dp(n, 0);

        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    dp[i] = max(dp[i], dp[j]);
                }
            }
            dp[i]++;
        }
        return ranges::max(dp);
    }
};
```

### 代码分析

- `dp[i]`：以 `nums[i]` 结尾的 LIS 长度。
- `dp[i] = max(dp[j]) + 1`，其中 `j < i` 且 `nums[j] < nums[i]`。
- 时间复杂度 O(n²)，空间 O(n)。

## 版本三：贪心 + 辅助数组

还能不能再优化呢？这都给我干 O(n²) 了！！！

我们发现，其实每一次内循环的本质都是在找已经计算好的**部分最小值**。这是很明显的贪心思想。

我们考虑另起一个辅助数组 `t`，用于记录我们发现的**每个长度的最长递增子序列的最小末值**。这句话很值得体味。

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        vector<int> t;
        t.push_back(nums[0]);
        int n = nums.size();

        for (int i = 1; i < n; ++i) {
            int len = t.size(), flag = 0;
            for (int j = 0; j < len; ++j) {
                if (nums[i] <= t[j]) {
                    t[j] = nums[i];        // 替换第一个 ≥ nums[i] 的位置
                    flag = 1;
                    break;
                }
            }
            if (flag == 0) t.push_back(nums[i]);  // 比所有都大，扩展长度
        }
        return t.size();
    }
};
```

### 贪心思想

`t[j]` 表示：长度为 `j+1` 的递增子序列的**最小可能末值**。

为什么"最小末值"更优？因为末值越小，后面能接的元素就越多，序列越有可能更长。

例如 `nums = [2, 5, 3]`：
- 处理 `2`：`t = [2]`
- 处理 `5`：`5 > 2`，扩展：`t = [2, 5]`（长度为 2 的序列末值最小为 5）
- 处理 `3`：`3 ≤ 5`，替换 `t[1] = 3`：`t = [2, 3]`（长度为 2 的序列末值最小变为 3）

`t` 数组始终是**严格递增**的（因为每次替换都保证 `t[j]` 被更小的值替代，且新扩展的值一定大于所有已有值）。

## 版本四：贪心 + 二分

递增？单调？二分？我们已经究得真元了！

既然 `t` 是递增的，找"第一个 ≥ nums[i] 的位置"可以用二分查找，把内层循环从 O(n) 降到 O(log n)：

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        vector<int> t;
        t.push_back(nums[0]);
        int n = nums.size();

        for (int i = 1; i < n; ++i) {
            int right = t.size() - 1;
            int left = 0;

            // 二分查找第一个 ≥ nums[i] 的位置
            while (left <= right) {
                int mid = (left + right) >> 1;
                if (t[mid] == nums[i]) {
                    left = mid;
                    break;
                }
                if (t[mid] > nums[i])
                    right = mid - 1;
                else
                    left = mid + 1;
            }

            if (left == t.size())
                t.push_back(nums[i]);      // 比所有都大，扩展
            else
                t[left] = nums[i];         // 替换
        }
        return t.size();
    }
};
```

### 代码分析

**二分查找**：在递增数组 `t` 中找第一个 `≥ nums[i]` 的位置 `left`。

- 如果 `left == t.size()`：`nums[i]` 比 `t` 中所有元素都大，扩展 `t`。
- 否则：`t[left]` 是第一个 `≥ nums[i]` 的位置，用 `nums[i]` 替换它（降低该长度子序列的末值）。

**注意**：这里 `t` 数组**不是**真正的 LIS，只是记录了各长度 LIS 的最小末值。`t.size()` 才是 LIS 的长度。

## 版本五：原地修改（O(1) 额外空间）

空间复杂度还是 O(n)，其实可以直接原地修改数组，把空间复杂度降到常数级别：

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int len = 1;                                // 当前 t 数组的长度

        for (int i = 1; i < nums.size(); ++i) {
            // 二分查找第一个 ≥ nums[i] 的位置，在 nums[0..len-1] 中
            int left = 0, right = len - 1;
            while (left <= right) {
                int mid = (left + right) >> 1;
                if (nums[mid] == nums[i]) {
                    left = mid;
                    break;
                }
                if (nums[mid] > nums[i])
                    right = mid - 1;
                else
                    left = mid + 1;
            }

            if (left == len)
                nums[len++] = nums[i];              // 扩展，len 自增
            else
                nums[left] = nums[i];               // 替换
        }
        return len;
    }
};
```

### 代码分析

直接在 `nums` 的前半部分维护 `t` 数组，`len` 记录当前 `t` 的长度。`nums[0..len-1]` 就是 `t`，`nums[len..]` 是尚未处理的元素。由于 `left ≤ len` 且每次只修改 `nums[left]`，而 `left` 要么在 `[0, len-1]` 内（替换），要么等于 `len`（扩展），不会破坏尚未遍历的元素。

## 逐轮推演

以 `nums = [10, 9, 2, 5, 3, 7, 101, 18]` 为例，使用版本四：

| 轮次 | i | nums[i] | 二分查找 | left | 操作 | t |
|:---:|:---:|:---:|:---|:---:|------|:---|
| 初始 | — | — | — | — | — | `[10]` |
| 1 | 1 | 9 | 9 < 10 → left=0 | 0 | 替换 t[0] | `[9]` |
| 2 | 2 | 2 | 2 < 9 → left=0 | 0 | 替换 t[0] | `[2]` |
| 3 | 3 | 5 | 5 > 2 → left=1 | 1 | 扩展 | `[2, 5]` |
| 4 | 4 | 3 | 3 ≤ 5, 3 > 2 → left=1 | 1 | 替换 t[1] | `[2, 3]` |
| 5 | 5 | 7 | 7 > 3 → left=2 | 2 | 扩展 | `[2, 3, 7]` |
| 6 | 6 | 101 | 101 > 7 → left=3 | 3 | 扩展 | `[2, 3, 7, 101]` |
| 7 | 7 | 18 | 18 ≤ 101, 18 > 7 → left=3 | 3 | 替换 t[3] | `[2, 3, 7, 18]` |

`t.size() = 4`，LIS 长度为 4。注意真正的 LIS 是 `[2, 3, 7, 101]`，而 `t = [2, 3, 7, 18]` 只是末值数组，不是实际子序列。

## 复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 | 说明 |
|:---:|:---:|:---:|------|
| 版本一（递归+记忆化） | O(n²) | O(n) | 自顶向下 |
| 版本二（递推 DP） | O(n²) | O(n) | 自底向上 |
| 版本三（贪心+线性扫描） | O(n²) | O(n) | 贪心思想，但内层仍是 O(n) |
| 版本四（贪心+二分） | O(n log n) | O(n) | 最优时间复杂度 |
| 版本五（原地修改） | O(n log n) | O(1) | 最优时空 |

## 总结

这道题的优化路径非常经典，体现了"DP → 贪心 → 二分"的层层递进：

1. **DP**：`dp[i] = max(dp[j]) + 1`，O(n²)，直观但慢。
2. **贪心**：维护"各长度 LIS 的最小末值"数组 `t`，末值越小越有潜力。
3. **二分**：`t` 递增，用二分找替换位置，O(n log n)。
4. **原地**：`t` 直接建在 `nums` 上，O(1) 额外空间。

核心洞察：**我们不需要知道 LIS 具体长什么样，只需要知道每个长度能"多低"地结尾**。`t` 数组的递增性保证了二分的正确性，而贪心选择（总是保留最小末值）保证了最终长度最优。

与 139. 单词拆分（bool DP）、279. 完全平方数（min DP）不同，300 的优化体现了"换个角度看问题"的力量——从"以 i 结尾的 LIS"到"各长度 LIS 的最小末值"，视角一变，复杂度就降了。
