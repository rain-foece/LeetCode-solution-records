# 最长公共子序列（Longest Common Subsequence）题解

> 题目链接：[LeetCode 1143. Longest Common Subsequence](https://leetcode.cn/problems/longest-common-subsequence/)

## 题目描述

给定两个字符串 `text1` 和 `text2`，返回这两个字符串的最长**公共子序列**的长度。如果不存在公共子序列，返回 `0`。

一个字符串的**子序列**是指这样一个新的字符串：它是由原字符串在不改变字符的相对顺序的情况下删除某些字符（也可以不删除任何字符）后组成的新字符串。

例如，`"ace"` 是 `"abcde"` 的子序列，但 `"aec"` 不是 `"abcde"` 的子序列。

两个字符串的**公共子序列**是这两个字符串所共同拥有的子序列。

**示例 1：**

```
输入：text1 = "abcde", text2 = "ace"
输出：3
解释：最长公共子序列是 "ace"，它的长度为 3。
```

**示例 2：**

```
输入：text1 = "abc", text2 = "abc"
输出：3
解释：最长公共子序列是 "abc"，它的长度为 3。
```

**示例 3：**

```
输入：text1 = "abc", text2 = "def"
输出：0
解释：两个字符串没有公共子序列，返回 0。
```

## 核心思路

典型的动态规划问题。

设 `f[i][j]` 表示 `s[0..i-1]` 与 `t[0..j-1]` 的最长公共子序列长度。对于字符 `s[i-1]` 和 `t[j-1]`：

- 如果 `s[i-1] == t[j-1]`：这两个字符必然可以纳入 LCS，`f[i][j] = f[i-1][j-1] + 1`。
- 如果 `s[i-1] != t[j-1]`：两个字符不可能同时出现在 LCS 中，`f[i][j] = max(f[i-1][j], f[i][j-1])`。

状态依赖关系：

```
        f[i-1][j-1]    f[i-1][j]
              ↘            ↓
        f[i][j-1]   →  f[i][j]
```

每个状态依赖**左上角**、**正上方**、**正左方**三个值，这是后续空间优化的难点所在。

---

## 版本一：二维 DP

### 代码

```cpp
class Solution {
public:
    int longestCommonSubsequence(string s, string t) {
        int n = s.size(), m = t.size();
        vector f(n + 1, vector<int>(m + 1, 0));
        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < m; ++j) {
                f[i + 1][j + 1] = s[i] == t[j]
                    ? f[i][j] + 1
                    : max(f[i][j + 1], f[i + 1][j]);
            }
        }
        return f[n][m];
    }
};
```

### 代码分析

- `f[i+1][j+1]` 对应 `s[0..i]` 与 `t[0..j]` 的 LCS 长度。`+1` 偏移在数组左侧和上侧预留了哨兵行/列 `f[0][*] = 0`、`f[*][0] = 0`，省去边界判断。
- 状态转移的对应关系：
  - `f[i][j]` → 左上角 `f[i-1][j-1]`
  - `f[i][j+1]` → 正上方 `f[i-1][j]`
  - `f[i+1][j]` → 正左方 `f[i][j-1]`

时间复杂度 O(nm)，空间复杂度 O(nm)。

### 逐轮推演

以 `s = "abcde"`, `t = "ace"` 为例：

| i\j | 0 (哨兵) | 1 (a) | 2 (c) | 3 (e) |
|:---:|:---:|:---:|:---:|:---:|
| 0 (哨兵) | 0 | 0 | 0 | 0 |
| 1 (a) | 0 | **1** | 1 | 1 |
| 2 (b) | 0 | 1 | 1 | 1 |
| 3 (c) | 0 | 1 | **2** | 2 |
| 4 (d) | 0 | 1 | 2 | 2 |
| 5 (e) | 0 | 1 | 2 | **3** |

关键步骤：
- `f[1][1]`：`s[0]='a' == t[0]='a'` → `f[0][0]+1 = 1`
- `f[3][2]`：`s[2]='c' == t[1]='c'` → `f[2][1]+1 = 2`
- `f[5][3]`：`s[4]='e' == t[2]='e'` → `f[4][2]+1 = 3`

最终 `f[5][3] = 3`，LCS 为 `"ace"`。

## 版本二：双数组轮转

### 核心思路

二维 DP 中，每一行只依赖上一行，因此可以用两个数组轮转。`f[0]` 存上一行，`f[1]` 存当前行，`(i+1)%2` 和 `i%2` 交替使用。

### 代码

```cpp
class Solution {
public:
    int longestCommonSubsequence(string s, string t) {
        int n = s.size(), m = t.size();
        vector f(2, vector<int>(m + 1));
        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < m; ++j) {
                f[(i + 1) % 2][j + 1] = s[i] == t[j]
                    ? f[i % 2][j] + 1
                    : max(f[i % 2][j + 1], f[(i + 1) % 2][j]);
            }
        }
        return f[n % 2][m];
    }
};
```

### 代码分析

- `f[i % 2]` 是上一行，`f[(i+1) % 2]` 是当前行。
- `f[i % 2][j]` → 左上角
- `f[i % 2][j+1]` → 正上方（上一行同列）
- `f[(i+1) % 2][j]` → 正左方（当前行上一列，刚更新过）
- 最后返回 `f[n % 2][m]`（取决于 n 的奇偶性，最后一行的结果）。

时间复杂度 O(nm)，空间复杂度 O(2m) = O(m)。

## 版本三：单数组原地迭代（`col_j` 技巧）

### 核心思路

我们注意到，其实完全没必要用两个数组——能不能只用一个数组原地迭代？

问题的核心矛盾在于：当我们准备更新 `dp[j+1]` 时，需要的左上角 `f[i][j]`（即更新前的 `dp[j]`）已经在上一列被覆盖了。所以必须用一个变量 `col_j` 在覆盖前把它保存下来。

具体流程：

- `col_j`：保存 `f[i][j]`（左上角），每轮循环初值为 0（哨兵列）。
- `tmp`：暂存 `dp[j+1]` 的旧值（即 `f[i][j+1]`，正上方），因为它将是下一列的左上角。
- 更新：`dp[j+1] = (s[i]==t[j]) ? col_j+1 : max(dp[j+1], dp[j])`
- 更新完 `dp[j+1]` 后，`col_j = tmp`（为下一列准备左上角）。

### 代码

```cpp
class Solution {
public:
    int longestCommonSubsequence(string s, string t) {
        int m = t.size();
        vector<int> dp(m + 1, 0);           // 在最前面加入哨兵节点 0

        for (char c : s) {
            for (int j = 0, col_j = 0; j < m; ++j) {
                // col_j 为 dp[j] 的克隆（即 f[i][j]），
                // 因为 dp[j] 被覆盖后就无法调用了，所以必须记录
                int tmp = dp[j + 1];         // 暂存 f[i][j+1]，下一轮它就是左上角
                dp[j + 1] = (c == t[j])
                    ? col_j + 1              // 匹配：左上角 + 1
                    : max(dp[j + 1], dp[j]); // 不匹配：取上方和左方的较大值
                col_j = tmp;                 // 为下一列提供左上角
            }
        }
        return dp[m];
    }
};
```

### 逐轮推演

以 `s = "abc"`, `t = "abc"` 为例，`dp` 初始 `[0, 0, 0, 0]`。

**i=0（处理 s[0]='a'）**：

| j | col_j (`f[i][j]`) | tmp (旧 `dp[j+1]`) | 更新 `dp[j+1]` | 新 col_j | dp 数组 |
|:---:|:---:|:---:|------|:---:|:---|
| 初始 | — | — | — | 0 | `[0, 0, 0, 0]` |
| 0 | 0 | 0 | `a==a` → 0+1=**1** | 0 | `[0, 1, 0, 0]` |
| 1 | 0 | 0 | `a!=b` → max(0,1)=**1** | 0 | `[0, 1, 1, 0]` |
| 2 | 0 | 0 | `a!=c` → max(0,1)=**1** | 0 | `[0, 1, 1, 1]` |

**i=1（处理 s[1]='b'）**：

| j | col_j | tmp | 更新 `dp[j+1]` | 新 col_j | dp 数组 |
|:---:|:---:|:---:|------|:---:|:---|
| 初始 | — | — | — | 0 | `[0, 1, 1, 1]` |
| 0 | 0 | 1 | `b!=a` → max(1,0)=**1** | 1 | `[0, 1, 1, 1]` |
| 1 | 1 | 1 | `b==b` → 1+1=**2** | 1 | `[0, 1, 2, 1]` |
| 2 | 1 | 1 | `b!=c` → max(1,2)=**2** | 1 | `[0, 1, 2, 2]` |

**i=2（处理 s[2]='c'）**：

| j | col_j | tmp | 更新 `dp[j+1]` | 新 col_j | dp 数组 |
|:---:|:---:|:---:|------|:---:|:---|
| 初始 | — | — | — | 0 | `[0, 1, 2, 2]` |
| 0 | 0 | 1 | `c!=a` → max(1,0)=**1** | 1 | `[0, 1, 2, 2]` |
| 1 | 1 | 2 | `c!=b` → max(2,1)=**2** | 2 | `[0, 1, 2, 2]` |
| 2 | 2 | 2 | `c==c` → 2+1=**3** | 2 | `[0, 1, 2, 3]` |

最终 `dp[3] = 3`。

整个过程中，`col_j` 始终在 `dp[j]` 被覆盖前保存了 `f[i][j]`，保证下一列匹配时可以正确取到左上角的值。

## 复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
|:---:|:---:|:---:|
| 版本一（二维 DP） | O(nm) | O(nm) |
| 版本二（双数组轮转） | O(nm) | O(2m) = O(m) |
| 版本三（单数组 + col_j） | O(nm) | O(m) |

三个版本时间复杂度相同，空间从 O(nm) 一路压缩到 O(m)。版本三用 `col_j` 一个变量就省掉了一个数组，是空间优化的极致。

## 总结

这道题是 LCS 的经典模板，四个版本一脉相承：

1. **二维 DP**：直接翻译状态转移方程，`f[i][j]` 依赖左上、正上、正左三个方向。
2. **双数组轮转**：发现每行只依赖上一行，用两个数组交替，空间降到 O(m)。
3. **单数组 + col_j**：进一步压缩到只用一个数组。关键难点在于左上角的值会被覆盖，引入 `col_j` 变量在覆盖前保存之。

理解 `col_j` 的作用是这道题空间优化的核心：`col_j` 始终保存着 `f[i][j]`（即更新前的 `dp[j]`），在匹配时提供左上角的值。每轮循环用 `tmp` 暂存旧值、更新 `dp[j+1]`、再把 `tmp` 赋给 `col_j`，三段式操作干净利落。

这道题和 72. 编辑距离的 DP 结构非常相似——都是两个字符串的双序列 DP，状态转移都依赖左上、正上、正左三个方向。区别在于 LCS 是求最长公共部分，编辑距离是求最小操作次数，一个取 max，一个取 min。两者可以对照学习。
