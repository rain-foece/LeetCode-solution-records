# 最长公共子序列（LCS）题解

## 题目描述

给定两个字符串 `s` 和 `t`，求它们的最长公共子序列（Longest Common Subsequence）的长度。

**注意**：这里要求的是「子序列」而非「子数组」。子序列不要求元素在原字符串中连续，只要保持相对顺序即可；而子数组（子串）则必须连续。这个区别直接决定了状态转移方程的设计，也是后续空间优化难度的根源所在。

---

## 核心思路概览

本文将从四个递进的版本展开：

| 版本 | 方法 | 核心思想 |
|------|------|----------|
| 版本一 | 递归 + 记忆化搜索 | 自顶向下，用 `mem` 数组缓存已计算结果 |
| 版本二 | 动态规划递推 | 1:1 翻译为自底向上的二维 DP |
| 版本三 | 空间优化至 O(m) | 通过一个 `col_j` 变量巧妙保存被覆盖的值，实现单个 `dp` 数组原地更新 |
| 版本四 | 微优化 | 用 range-for 省去 `n` 的计算和 `s[i]` 的索引 |

下面逐一分析。

---

## 版本一：递归 + 记忆化搜索

### 代码

```cpp
class Solution {
public:
    int longestCommonSubsequence(string s, string t) {
        int n = s.size(), m = t.size();
        vector<vector<int>> mem(n, vector<int>(m, -1));  // 记忆化搜索，减小递归开销

        auto dfs = [&](this auto&& dfs, int i, int j) -> int {
            if (i < 0 || j < 0) return 0;  // 递归终点

            int& res = mem[i][j];           // 引用，修改 res 即修改 mem[i][j]
            if (res != -1) return res;      // 之前计算过，直接返回

            return res = (s[i] == t[j]) ? dfs(i - 1, j - 1) + 1
                                        : max(dfs(i - 1, j), dfs(i, j - 1));
        };
        return dfs(n - 1, m - 1);
    }
};
```

### 分析

这个版本直观地反映了 LCS 问题的子问题结构。定义 `dfs(i, j)` 表示 `s[0..i]` 与 `t[0..j]` 的最长公共子序列长度：

- **递归基**：`i < 0` 或 `j < 0` 时，至少一个字符串为空，LCS 长度为 0。
- **状态转移**：
  - 如果 `s[i] == t[j]`，这两个字符必然可以纳入 LCS，问题缩小为 `dfs(i-1, j-1) + 1`。
  - 如果 `s[i] != t[j]`，则两个字符不可能同时出现在 LCS 中，取「舍弃 s[i]」和「舍弃 t[j]」两种情况的较大值：`max(dfs(i-1, j), dfs(i, j-1))`。

**关于记忆化**：每个状态 `(i, j)` 只会被计算一次，之后直接从 `mem` 数组中读取。时间复杂度 O(nm)，空间复杂度 O(nm)。

**优点**：思路清晰，代码几乎就是状态转移方程的直译，适合入门理解。

**缺点**：递归调用栈开销较大，在极端输入下可能触发栈溢出；且需要 O(nm) 的空间。

## 版本二：1:1 翻译为动态规划递推

### 代码

```cpp
class Solution {
public:
    int longestCommonSubsequence(string s, string t) {
        int n = s.size(), m = t.size();
        vector f(n + 1, vector<int>(m + 1));
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                f[i + 1][j + 1] = s[i] == t[j] ? f[i][j] + 1
                                                : max(f[i][j + 1], f[i + 1][j]);
            }
        }
        return f[n][m];
    }
};
```

### 分析

这一版是版本一的直接逆翻译——将「自顶向下的递归」改写成「自底向上的递推」。

这里 `f[i+1][j+1]` 对应版本一中 `s[0..i]` 与 `t[0..j]` 的 LCS 长度。之所以使用 `i+1` 和 `j+1` 的偏移，是为了在数组左侧和上侧预留一行/一列的哨兵 0（即 `f[0][*] = 0`、`f[*][0] = 0`），从而省去递归版本中 `i<0 || j<0` 的边界判断。

状态转移的对应关系非常直接：

- 版本一：`dfs(i-1, j-1)` → 版本二：`f[i][j]`
- 版本一：`dfs(i-1, j)` → 版本二：`f[i][j+1]`
- 版本一：`dfs(i, j-1)` → 版本二：`f[i+1][j]`

双层循环按 `i` 递增、`j` 递增的顺序计算，保证每个状态所需的子问题都已被求解。时间 O(nm)，空间 O(nm)。

## 版本三：空间优化至 O(m)（本篇重点）

### 为什么不能直接优化？

观察版本二的递推式：

```
f[i+1][j+1] = s[i] == t[j] ? f[i][j] + 1 : max(f[i][j+1], f[i+1][j])
```

每个 `f[i+1][j+1]` 的求解依赖三个值：

```
              f[i][j]          f[i][j+1]
                 ↘               ↓
              f[i+1][j]  →  f[i+1][j+1]
```

如果只要「子数组」的 LCS（即要求连续），递推式是 `f[i+1][j+1] = s[i]==t[j] ? f[i][j]+1 : 0`，只依赖左上角的 `f[i][j]`，那直接用一个一维数组逆序遍历就能解决。但子序列的递推同时需要「正上方」`f[i][j+1]` 和「正左方」`f[i+1][j]`，这就麻烦多了。

最容易想到的方案是用两个数组轮转（保存上一行和当前行），空间 O(2m)。但我们的目标是只用一个长度为 `m+1` 的数组 `dp` 原地迭代。

问题的核心矛盾在于：

- 当我们准备计算 `f[i+1][j+1]`（即更新 `dp[j+1]`）时，
- 我们需要的 `f[i][j]`（即左上角）已经在上一次循环中被 `f[i+1][j]` 覆盖掉了。

换句话说，`dp[j]` 在更新后变成了 `f[i+1][j]`，而原始的 `f[i][j]` 已经丢失。但匹配时需要的是 `f[i][j] + 1`，这就必须想办法在覆盖前把 `f[i][j]` 保存下来。

### 解决方案：引入 `col_j`

我们用一个变量 `col_j` 来保存即将被覆盖的 `f[i][j]`，在每一列处理完后更新它。具体流程如下：

设当前正在处理 `s[i]`（即外层循环第 `i` 轮），内层循环的 `dp` 数组在更新前体现的是第 `i` 行的结果，即 `dp[k] = f[i][k]`。

在遍历每一列 `j` 时，我们需要的是：

- **左上角** `f[i][j]`：已经保存在 `col_j` 中（上一轮循环结束时更新好的）。
- **正上方** `f[i][j+1]`：这就是当前的 `dp[j+1]`（还未被更新，仍是旧值）。
- **正左方** `f[i+1][j]`：这就是上一列刚更新完的 `dp[j]`（已经是新值）。

因此状态转移可以直接写成：

```
dp[j+1] = (s[i] == t[j]) ? col_j + 1 : max(dp[j+1], dp[j])
```

更新完 `dp[j+1]` 后，它由 `f[i][j+1]` 变成了 `f[i+1][j+1]`。但注意，**原始的 `dp[j+1]`（即 `f[i][j+1]`）将是下一列 `j+1` 的左上角**，所以必须在覆盖前用 `tmp` 把它暂存下来，然后在末尾赋值给 `col_j`。

### 代码

```cpp
class Solution {
public:
    int longestCommonSubsequence(string s, string t) {
        int n = s.size(), m = t.size();
        vector<int> dp(m + 1, 0);  // 在最前面加入哨兵节点 0

        for (int i = 0; i < n; ++i) {
            for (int j = 0, col_j = 0; j < m; ++j) {
                // col_j 为 dp[j] 的克隆（即 f[i][j]），
                // 因为 dp[j] 被覆盖后就无法调用了，所以必须提前保存
                int tmp = dp[j + 1];  // 暂存 f[i][j+1]，下一轮它就是左上角
                dp[j + 1] = (s[i] == t[j]) ? col_j + 1
                                           : max(dp[j + 1], dp[j]);
                col_j = tmp;  // 为下一列提供左上角
            }
        }
        return dp[m];
    }
};
```

### 逐轮推演

假设 `s = "abc"`, `t = "abc"`，`dp` 初始为 `[0, 0, 0, 0]`。

**i = 0（处理 s[0] = 'a'）**：

| j | col_j (f[i][j]) | tmp (旧 dp[j+1]) | 更新 dp[j+1] | 新 col_j |
|---|-----------------|-------------------|-------------|----------|
| 0 | 0 | dp[1]=0 | s[0]==t[0] → 0+1=1 | 0 |
| 1 | 0 | dp[2]=0 | s[0]!=t[1] → max(0,1)=1 | 0 |
| 2 | 0 | dp[3]=0 | s[0]!=t[2] → max(0,1)=1 | 0 |

一轮后 `dp = [0, 1, 1, 1]`，`f[1][*] = [0, 1, 1, 1]`，正确。

**i = 1（处理 s[1] = 'b'）**：

| j | col_j | tmp | 更新 dp[j+1] | 新 col_j |
|---|-------|-----|-------------|----------|
| 0 | 0 | dp[1]=1 | s[1]!=t[0] → max(1,0)=1 | 1 |
| 1 | 1 | dp[2]=1 | s[1]==t[1] → 1+1=2 | 1 |
| 2 | 1 | dp[3]=1 | s[1]!=t[2] → max(1,2)=2 | 1 |

一轮后 `dp = [0, 1, 2, 2]`，正确。

**i = 2（处理 s[2] = 'c'）**：

| j | col_j | tmp | 更新 dp[j+1] | 新 col_j |
|---|-------|-----|-------------|----------|
| 0 | 0 | dp[1]=1 | s[2]!=t[0] → max(1,0)=1 | 1 |
| 1 | 1 | dp[2]=2 | s[2]!=t[1] → max(2,2)=2 | 2 |
| 2 | 2 | dp[3]=2 | s[2]==t[2] → 2+1=3 | 2 |

最终 `dp = [0, 1, 2, 3]`，`dp[3] = 3`，结果正确。

整个过程中，`col_j` 始终在`dp[j]`被覆盖前保存了 `f[i][j]`，保证下一列匹配时可以正确取到左上角的值。

**时间复杂度**：O(nm)，**空间复杂度**：O(m)。

## 版本四：微优化——省去 `n` 的计算

### 代码

```cpp
class Solution {
public:
    int longestCommonSubsequence(string s, string t) {
        int m = t.size();
        vector<int> dp(m + 1, 0);  // 在最前面加入哨兵节点 0

        for (char c : s) {
            for (int j = 0, col_j = 0; j < m; ++j) {
                int tmp = dp[j + 1];
                dp[j + 1] = (c == t[j]) ? col_j + 1
                                        : max(dp[j + 1], dp[j]);
                col_j = tmp;
            }
        }
        return dp[m];
    }
};
```

### 分析

这一版与版本三在算法上完全等价，唯一的改动是将外层循环从索引遍历 `for (int i = 0; i < n; ++i)` 改为了 range-for `for (char c : s)`。

这样做的直接效果是：
- 不需要计算 `n = s.size()`，省去一行代码和一次函数调用。
- 内层直接用 `c` 代替 `s[i]`，少一次索引运算。

属于一种「顺手」级别的优化，对性能几乎没有可见影响，但代码看起来更加简洁流畅。

---

## 总结

四个版本一脉相承，体现了从「直观递归」到「高效迭代」的完整优化路径：

1. **版本一**用递归 + 记忆化直接表达状态转移方程，最好理解。
2. **版本二**去掉递归开销，翻译为标准二维 DP，作为空间优化的跳板。
3. **版本三**通过引入 `col_j` 变量巧妙地解决了左上角值被覆盖的问题，将空间从 O(nm) 压缩到 O(m)，是本文的核心内容。
4. **版本四**在版本三的基础上用 range-for 做了风格层面的简化。

理解版本三的关键在于抓住两点：每个状态依赖哪些子问题、在滚动更新中哪个值会被覆盖从而必须提前保存。一旦想通了 `col_j` 的作用，整个优化思路就豁然开朗了。
