# 分割等和子集（Partition Equal Subset Sum）题解

> 题目链接：[LeetCode 416. Partition Equal Subset Sum](https://leetcode.cn/problems/partition-equal-subset-sum/)

## 题目描述

给你一个**只包含正整数**的**非空**数组 `nums`。请你判断是否可以将这个数组分割成两个子集，使得两个子集的元素和相等。

**示例 1：**

```
输入：nums = [1,5,11,5]
输出：true
解释：数组可以分割成 [1, 5, 5] 和 [11] 。
```

**示例 2：**

```
输入：nums = [1,2,3,5]
输出：false
解释：数组不能分割成两个元素和相等的子集。
```

---

## 核心思路

分割成两个和相等的子集，等价于：**是否存在一个子集，其和为总和的一半**？

设总和为 `sum`。如果 `sum` 是奇数，直接返回 `false`（不可能平分）。否则问题转化为 0-1 背包：从 `nums` 中选若干个数，能否恰好装满容量为 `sum/2` 的背包？

这道题的本质是**选或不选**——每个元素互相独立，只需依次考虑每个元素选还是不选。这和 300. 最长递增子序列的"枚举选哪个"是两种不同的 DP 模式，我们在最后详细对比。

## 版本一：记忆化搜索 + 递归

```cpp
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int sum = 0, n = nums.size();
        for (int x : nums) sum += x;
        if (sum % 2 != 0) return false;
        sum /= 2;

        vector<vector<int>> memo(n, vector<int>(sum + 1, -1));

        auto dfs = [&](this auto&& dfs, int i, int j) -> bool {
            if (i < 0) return j == 0;               // 没有元素了，容量必须刚好用完
            int& res = memo[i][j];
            if (res != -1) return res;

            if (j < nums[i])                        // 容量不够，只能不选
                return res = dfs(i - 1, j);

            return res = dfs(i - 1, j) || dfs(i - 1, j - nums[i]);  // 不选 或 选
        };

        return dfs(n - 1, sum);
    }
};
```

### 代码分析

**`dfs(i, j)`**：考虑前 `i` 个元素（下标 0~i），能否凑出和为 `j`。

**递归基**：`i < 0` 时，没有元素了，只有当 `j == 0`（刚好凑满）才返回 `true`。

**状态转移**：

- `j < nums[i]`：容量不够，只能**不选**当前元素，`dfs(i-1, j)`。
- 否则：**不选**（`dfs(i-1, j)`）或**选**（`dfs(i-1, j-nums[i])`），有一条路通就行。

**记忆化**：`memo[i][j]` 用 `-1` 表示未计算，避免重复递归。

## 版本二：递推（DP）

翻译成递推：

```cpp
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int sum = 0, n = nums.size();
        for (int x : nums) sum += x;
        if (sum % 2 != 0) return false;
        sum /= 2;

        vector<bool> dp(sum + 1, false);
        dp[0] = true;                                // 容量 0，什么也不选

        for (int i = 0; i < n; ++i) {
            for (int j = sum; j >= nums[i]; --j) {   // 倒序遍历！
                dp[j] = dp[j] || dp[j - nums[i]];    // 不选 或 选
                if (dp[sum]) return true;            // 提前返回
            }
        }
        return false;
    }
};
```

### 代码分析

**为什么倒序遍历？** 这是 0-1 背包的关键。`dp[j - nums[i]]` 必须来自上一轮（未考虑当前元素的状态）。如果正序遍历，`dp[j - nums[i]]` 可能已经被当前元素更新过，导致一个元素被多次使用（变成完全背包）。

**一维数组**：`dp[j]` 表示能否凑出和为 `j`。空间从 O(n·sum) 降到 O(sum)。

**提前返回**：`if (dp[sum]) return true`，一旦目标容量被满足，立即返回。

## 版本三：bitset 优化

其实 bool 类型我们大可以直接用 `bitset` 来最优化：

```cpp
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int sum = 0, n = nums.size();
        for (int x : nums) sum += x;
        if (sum % 2 != 0) return false;
        sum /= 2;

        bitset<10001> dp(1);                         // 只有 dp[0] = 1
        for (int x : nums) {
            dp |= dp << x;                           // 不选 | 选
            if (dp[sum]) return true;
        }
        return false;
    }
};
```

### 代码分析

`bitset` 把整个 DP 数组压缩成二进制位，`dp[k] = 1` 表示能凑出和为 `k`。

**`dp |= dp << x`** 这一行就是整个 DP 的核心：

- `dp`：不选当前元素，所有已有方案保持不变。
- `dp << x`：选当前元素，所有已有方案的和加上 `x`。
- `|=`：两者取并集（任意一条路通就行）。

例如 `dp = 000...01001`（能凑出 0 和 3），`x = 2`，则 `dp << 2 = 000...100100`（能凑出 2 和 5），`dp |= dp<<2` 后能凑出 `{0, 2, 3, 5}`。

一行代码替代了版本二的整个内层循环，且位运算天然并行，常数极小。`bitset<10001>` 是因为 `n ≤ 200`，`nums[i] ≤ 100`，`sum/2 ≤ 10000`。

## 逐轮推演

以 `nums = [1, 5, 11, 5]` 为例，`sum = 22`，`target = 11`。

**版本二推演**：

| 轮次 | i | nums[i] | 遍历 j（倒序） | dp 变化 |
|:---:|:---:|:---:|:---|:---|
| 初始 | — | — | — | dp[0]=true, 其余 false |
| 1 | 0 | 1 | j=11→1 | dp[1]=true |
| 2 | 1 | 5 | j=11→5 | dp[5]=true, dp[6]=true |
| 3 | 2 | 11 | j=11 | dp[11]=dp[11] \|\| dp[0]=true → 提前返回 |

`dp[11] = true`，返回 `true`。对应子集 `[11]` 和 `[1, 5, 5]`。

**版本三推演**：

| 轮次 | x | dp（二进制表示） | 能凑出的和 |
|:---:|:---:|:---|:---|
| 初始 | — | `...0001` | {0} |
| 1 | 1 | dp \|= dp<<1 → `...0011` | {0, 1} |
| 2 | 5 | dp \|= dp<<5 → `...0100011` | {0, 1, 5, 6} |
| 3 | 11 | dp \|= dp<<11 → dp[11]=1 | 检测到 dp[11]=1，返回 true |

---

以 `nums = [1, 2, 3, 5]` 为例，`sum = 11`（奇数），直接返回 `false`。

|:---:|:---:|:---:|------|

## 总结：选或不选 vs 枚举选哪个

这道题的本质是**选或不选**，而 300. 最长递增子序列的本质是**枚举选哪个**。我们如何去区分这两种题呢？

**相邻无关子序列问题**（比如本题和 0-1 背包），适合「选或不选」。每个元素互相独立，只需依次考虑每个元素选或不选。状态转移：

```
dfs(i, j) = dfs(i-1, j) || dfs(i-1, j-nums[i])   // 不选 或 选
```

**相邻相关子序列问题**（比如 300. 最长递增子序列），适合「枚举选哪个」。我们需要知道子序列中相邻两个数的关系。对于 300 来说，枚举 `nums[i]` 必选，然后枚举前一个必选的数，方便比大小。状态转移：

```
dfs(i) = max(dfs(j)) + 1,  j < i 且 nums[j] < nums[i]
```

如果硬要用「选或不选」做 300，需要额外记录上一个选的数的下标，算法总体的空间复杂度为 O(n²)。

**对比总结**：

| 特征 | 选或不选 | 枚举选哪个 |
|:---|:---|:---|
| 典型题 | 416. 分割等和子集、0-1 背包 | 300. 最长递增子序列 |
| 元素关系 | 互相独立，顺序无关 | 相邻相关，需要比大小 |
| 状态 | `dfs(i, 剩余容量)` | `dfs(i)` = 以 i 结尾的最优解 |
| 转移 | 不选 / 选 | 枚举前一个元素 j |
| 复杂度 | O(n·sum) | O(n²) |

掌握了这两种模式，大部分子序列 DP 问题都能迎刃而解。
