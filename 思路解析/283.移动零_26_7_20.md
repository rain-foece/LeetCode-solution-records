# 移动零（Move Zeroes）题解

> 题目链接：[LeetCode 283. Move Zeroes](https://leetcode.cn/problems/move-zeroes/)

## 题目描述

给定一个数组 `nums`，编写一个函数将所有 `0` 移动到数组的末尾，同时保持非零元素的相对顺序。

请注意，必须在不复制数组的情况下原地对数组进行操作。

**示例 1：**

```
输入：nums = [0,1,0,3,12]
输出：[1,3,12,0,0]
```

**示例 2：**

```
输入：nums = [0]
输出：[0]
```

---

## 核心思路概览

本文将从三个递进的版本展开，逐步将空间复杂度从 O(n) 优化到 O(1)：

| 版本 | 方法 | 核心思想 |
|------|------|----------|
| 版本一 | 辅助数组 | 将非零元素收集到临时数组，再写回原数组 |
| 版本二 | 原地栈 | 用栈大小指针在原数组上"挤压"非零元素，省去辅助数组 |
| 版本三 | 双指针交换 | 发现 index 和 flag 之间全是 0，用交换代替覆盖，一次遍历完成 |

下面逐一分析。

---

## 版本一：辅助数组

### 思路

版本一是最简单的题解了，时间复杂度在 O(n)，空间复杂度也是 O(n)。思路很直接：重新开辟一个辅助数组，把非零元素全部按顺序收集进去，再覆盖回原数组的前段，最后把剩余位置填 0。

### 代码

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        vector<int> temp;                       // 辅助数组，收集非零元素
        for (int j : nums) {
            if (j != 0) {
                temp.push_back(j);              // 按顺序收集非零元素
            }
        }
        for (int i = 0; i < temp.size(); ++i) {
            nums[i] = temp[i];                  // 写回原数组前段
        }
        for (int i = temp.size(); i < nums.size(); ++i) {
            nums[i] = 0;                        // 剩余位置填 0
        }
    }
};
```

### 分析

这个版本是最直观的解法，三趟遍历，分别完成收集、回填、置零。

- **时间复杂度**：O(n)，三次独立遍历，常数因子为 3。
- **空间复杂度**：O(n)，需要一个与原数组等长的辅助数组。

**优点**：思路清晰，代码简单，适合入门理解。

**缺点**：额外开辟了 O(n) 的空间，不符合题目"原地操作"的要求。那么有没有办法优化呢？

---

## 版本二：原地栈

### 思路

我们发现，由于有零的存在，所有非零元素在新数组中的下标总是不大于在原数组中的。这样一来，只要我们按顺序遍历非零元素，可以类似于积压的方式在原数组中进行"位置挪移"。我们可以用一个变量 `index` 作为下一个非零元素应该放的位置，把非零元素进行"挤压"，最后把剩余位置全部变为 0，这在算法中叫做"原地栈思想"，而我们提到的 `index` 就是栈的大小。

### 代码

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int index = 0;                          // 栈大小，也是下一个非零元素应放的位置
        for (int x : nums) {
            if (x) {
                nums[index++] = x;              // 把 x 入栈，栈大小 +1
            }
        }
        fill(nums.begin() + index, nums.end(), 0);  // 剩余位置全部置 0
    }
};
```

### 分析

这个版本将辅助数组"搬进"了原数组内部。`index` 始终指向下一个非零元素应该写入的位置，遍历过程中非零元素被逐个"挤压"到数组前段，就像往一个栈里压入元素一样。

遍历结束后，`index` 记录了非零元素的总数，`[0, index)` 区间内是保持相对顺序的非零元素，`[index, n)` 区间全部填 0。

- **时间复杂度**：O(n)，一趟遍历 + 一次 fill。
- **空间复杂度**：O(1)，只用了 `index` 一个额外变量。

**优点**：空间从 O(n) 降到 O(1)，代码简洁优雅。

**缺点**：本着对代码负责的态度，我们需要用极端情况检查代码的效率。如果数组中的元素全为 0 时，我们遍历时需要检查一遍，而填充时又需要遍历一遍，这降低了效率。那么有没有办法在一次遍历时就完成这个问题呢？

## 版本三：双指针交换

### 思路

我们发现，如果我们把探索到的元素的下标设置为 `flag`（即 `right`），那么 `flag` 和 `index`（即 `left`）中间的区域究竟是什么呢？思考过后我们明白了，这个区域里的元素全部是已经入栈的非零元素或者 0！

下面证明一下：`index` 前面的元素全部是已经入栈的非零元素，这个毋庸置疑。但是 `index` 后面的呢？我们发现，假设有一个未入栈的非零元素在 `index` 和 `flag` 中间，这是不可能的，因为早在 `flag` 遍历到它时它就已经入栈了！

这让我们思考，能不能把 `index` 和 `flag` 中间的元素全部置 0 呢？这样 `flag` 遍历到最后，就可以省去第二次遍历置 0 这个环节。

如果要实现这个，我们肯定需要把这个区域内非零元素清除。为什么不在它往前挤压的时候就把本体清除呢？

另外，每次 `index` 所指的位置要么就是 0，要么就是已经入栈的非零。如果从头就把入栈元素"带走"，那么每次 `index` 都是 0！这样我们就可以直接在 `flag` 探测到非零元素时把 `flag` 和 `index` 交换，然后 `index` 后移（刚才证明了 `index` 和 `flag` 区间内全是 0，所以移动后 `index` 也是 0）。

特殊情况：如果整个数组全是非零，那么 `index` 和 `flag` "齐头并进"，不存在"0 区"。

### 代码

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int left = 0, right = 0;                // left：下一个非零元素应放的位置，right：当前探索位置
        while (right < nums.size()) {
            if (nums[right] != 0) {
                swap(nums[left], nums[right]);  // 把非零元素换到前面，0 被换到后面
                ++left;                         // 左边界后移
            }
            ++right;                            // 右指针继续探索
        }
    }
};
```

### 分析

这个版本的核心在于 `swap(nums[left], nums[right])`。当 `right` 遇到非零元素时，与 `left` 位置交换。由于 `[left, right)` 区间内全是 0（前面已证明），交换后 `left` 位置得到非零元素，`right` 位置变为 0，`left` 后移一位，区间性质不变。

整个过程可以看作两个指针的协作：
- `right` 负责探索，每次循环必定前进一步。
- `left` 只在遇到非零元素时才前进一步，始终指向"下一个非零元素应该去的位置"。

以 `nums = [0,1,0,3,12]` 为例：

| 步骤 | right | left | nums[right] | 操作 | 数组状态 |
|------|-------|------|-------------|------|----------|
| 初始 | 0 | 0 | — | — | `[0,1,0,3,12]` |
| 1 | 0 | 0 | 0 | 不交换，right++ | `[0,1,0,3,12]` |
| 2 | 1 | 0 | 1 | swap(0,1)，left++ | `[1,0,0,3,12]` |
| 3 | 2 | 1 | 0 | 不交换，right++ | `[1,0,0,3,12]` |
| 4 | 3 | 1 | 3 | swap(1,3)，left++ | `[1,3,0,0,12]` |
| 5 | 4 | 2 | 12 | swap(2,4)，left++ | `[1,3,12,0,0]` |

- **时间复杂度**：O(n)，严格一趟遍历，每个元素最多被访问一次。
- **空间复杂度**：O(1)，只用了两个指针变量。

**优点**：真正的一趟遍历，无论数组内容如何，时间复杂度稳定 O(n)。代码极简，双指针的思想优雅且普适。

---

## 总结

三个版本展示了移动零问题从"辅助空间"到"原地一次遍历"的优化路径：

1. **版本一**（辅助数组）：最直观，把非零元素收集起来再写回，空间 O(n)。
2. **版本二**（原地栈）：利用"新下标不大于旧下标"的性质，在原数组上模拟栈操作，空间降到 O(1)，但极端情况下需要两趟遍历。
3. **版本三**（双指针交换）：发现 `[left, right)` 区间全是 0 的关键性质，用交换代替覆盖，一次遍历完成，既省空间又省时间。

理解版本三的关键在于想清楚两个事实：为什么 `left` 和 `right` 之间全是 0？为什么交换后区间性质不变？一旦想通，整道题就豁然开朗了。
