# 缺失的第一个正数（First Missing Positive）题解

> 题目链接：[LeetCode 41. First Missing Positive](https://leetcode.cn/problems/first-missing-positive/)

## 题目描述

给你一个未排序的整数数组 `nums`，请你找出其中没有出现的最小的正整数。

请你实现时间复杂度为 O(n) 并且只使用常数级别额外空间的解决方案。

**示例 1：**

```
输入：nums = [1,2,0]
输出：3
```

**示例 2：**

```
输入：nums = [3,4,-1,1]
输出：2
```

**示例 3：**

```
输入：nums = [7,8,9,11,12]
输出：1
```

---

## 核心思路：原地哈希

这道题的关键约束是 O(n) 时间 + O(1) 空间。这意味着不能排序（O(n log n)），也不能用哈希表（O(n) 空间）。

那我们换个角度想：**答案的范围是多少？**

最坏情况下，数组里恰好是 `[1, 2, 3, ..., n]`，那缺失的是 `n + 1`。如果数组里有超出这个范围的数（负数、0、大于 n 的数），那缺失的正整数一定在 `[1, n]` 之间。所以答案只可能是 `1` 到 `n + 1` 之间的某个值。

既然答案的范围被锁定了，我们就可以把原数组本身当作一个「哈希表」来用——这就是**原地哈希**的核心思想：

> 让每个正整数 `x`（满足 `1 ≤ x ≤ n`）都**回到自己应该在的位置**，即下标 `x - 1`。遍历完成后，第一个 `nums[i] ≠ i + 1` 的位置，`i + 1` 就是缺失的正数。

---

## 代码

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        // 第一遍：原地哈希，把每个数放到它应该在的位置
        for (int i = 0; i < nums.size(); ++i) {
            while (nums[i] > 0 && nums[i] <= nums.size() &&
                   nums[nums[i] - 1] != nums[i])
                swap(nums[i], nums[nums[i] - 1]);
        }

        // 第二遍：找第一个位置不对的数
        for (int i = 0; i < nums.size(); ++i) {
            if (nums[i] != i + 1) {
                return i + 1;
            }
        }

        // 所有位置都对了，缺失的是 n + 1
        return nums.size() + 1;
    }
};
```

---

## 代码分析

### 为什么用 `while` 而不是 `if`？

这是整个算法最容易出错的地方。看这段：

```cpp
while (nums[i] > 0 && nums[i] <= nums.size() &&
       nums[nums[i] - 1] != nums[i])
    swap(nums[i], nums[nums[i] - 1]);
```

假设 `nums[i] = 5`，我们把它换到下标 4。但换过来的那个数可能也在 `[1, n]` 范围内，它也需要被换到正确的位置。用 `if` 只会换一次，用 `while` 会**持续交换**，直到当前位置的数不再需要换为止。

### `while` 的三个条件

| 条件 | 含义 |
|------|------|
| `nums[i] > 0` | 忽略负数和 0，它们不在答案考虑范围内 |
| `nums[i] <= nums.size()` | 忽略大于 n 的数，它们不可能在 `[1, n]` 的正确位置上 |
| `nums[nums[i] - 1] != nums[i]` | 目标位置已经有正确的数了，不需要交换（防止死循环） |

三个条件缺一不可。第三个条件特别重要：如果 `nums[i]` 已经在它应该在的位置了（比如 `nums[0] = 1`），再交换就是原地打转，必须跳过。

### 第二遍扫描

```cpp
for (int i = 0; i < nums.size(); ++i) {
    if (nums[i] != i + 1) {
        return i + 1;
    }
}
```

经过第一遍的原地哈希，理论上位置 `i` 上应该放着 `i + 1`。第一个不满足这个条件的位置，`i + 1` 就是缺失的最小正整数。

## 逐轮推演

以 `nums = [3, 4, -1, 1]` 为例，`n = 4`：

**第一遍：原地哈希**

| i | nums[i] | 满足条件？ | 操作 | 数组状态 |
|---|---------|-----------|------|----------|
| 0 | 3 | 3>0, 3≤4, nums[2]=-1≠3 ✅ | swap(0, 2) | `[-1, 4, 3, 1]` |
| | -1 | -1>0 ❌ | 退出 while | |
| 1 | 4 | 4>0, 4≤4, nums[3]=1≠4 ✅ | swap(1, 3) | `[-1, 1, 3, 4]` |
| | 1 | 1>0, 1≤4, nums[0]=-1≠1 ✅ | swap(1, 0) | `[1, -1, 3, 4]` |
| | -1 | -1>0 ❌ | 退出 while | |
| 2 | 3 | 3>0, 3≤4, nums[2]=3=3 ❌ | 退出 while | `[1, -1, 3, 4]` |
| 3 | 4 | 4>0, 4≤4, nums[3]=4=4 ❌ | 退出 while | `[1, -1, 3, 4]` |

**第二遍：扫描**

| i | nums[i] | 期望 i+1 | 判断 |
|---|---------|----------|------|
| 0 | 1 | 1 | ✅ 正确 |
| 1 | -1 | 2 | ❌ 缺失！返回 2 |

最终 `ans = 2`。

---

## 复杂度分析

- **时间复杂度**：O(n)。虽然内层有 `while` 循环，但每个数最多被交换一次（到达正确位置后就不会再被换走），所有 `while` 的总执行次数是 O(n)。
- **空间复杂度**：O(1)。只用了几个临时变量，在原数组上操作。

---

## 总结

原地哈希的本质是：**利用数组下标作为"哈希地址"，把每个数放到它应该在的位置（`nums[i]` 应该在下标 `i - 1`）**。遍历完成后，第一个位置不对的下标就是答案。

这和 [283. 移动零](283.移动零_26_7_20.md) 的「原地栈」思想一脉相承——都是把原数组本身当作数据结构，而不是开辟新的辅助空间。区别在于：

| 对比维度 | 41. 缺失的第一个正数 | 283. 移动零 |
|---------|-------------------|------------|
| 核心思想 | 原地哈希 | 原地栈 |
| 操作方式 | swap 把数换到正确位置 | 覆盖写入，把非零元素压到前面 |
| 循环方式 | `while` 持续交换直到位置正确 | `for` 一次遍历即可 |
| 关键约束 | 值必须在 `[1, n]` 范围内 | 区分零和非零 |

理解原地哈希的关键在于想清楚三个问题：**为什么答案一定在 `[1, n+1]` 之间？**（鸽巢原理）**为什么用 `while` 而不是 `if`？**（换过来的数可能也需要归位）**为什么第三个条件 `nums[nums[i]-1] != nums[i]` 不能省略？**（防止死循环）。一旦想通，这道题就豁然开朗了。
