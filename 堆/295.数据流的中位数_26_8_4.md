# 数据流的中位数（Find Median from Data Stream）题解

> 题目链接：[LeetCode 295. Find Median from Data Stream](https://leetcode.cn/problems/find-median-from-data-stream/)

## 题目描述

中位数是有序整数列表中的中间值。如果列表的大小是偶数，则没有中间值，中位数是两个中间值的平均值。

- 例如 `arr = [2,3,4]` 的中位数是 `3`。
- 例如 `arr = [2,3]` 的中位数是 `(2 + 3) / 2 = 2.5`。

实现 `MedianFinder` 类：

- `MedianFinder()` 初始化 `MedianFinder` 对象。
- `void addNum(int num)` 将数据流中的整数 `num` 添加到数据结构中。
- `double findMedian()` 返回到目前为止所有元素的中位数。与实际答案相差 `10⁻⁵` 以内的答案将被接受。

**示例：**

```
输入：
["MedianFinder", "addNum", "addNum", "findMedian", "addNum", "findMedian"]
[[], [1], [2], [], [3], []]
输出：
[null, null, null, 1.5, null, 2.0]

解释：
MedianFinder medianFinder = new MedianFinder();
medianFinder.addNum(1);    // arr = [1]
medianFinder.addNum(2);    // arr = [1, 2]
medianFinder.findMedian(); // 返回 1.5 ((1 + 2) / 2)
medianFinder.addNum(3);    // arr = [1, 2, 3]
medianFinder.findMedian(); // 返回 2.0
```

## 核心思路

数据流场景下，每次插入都排序显然不可行。我们需要一种数据结构，能够快速获取中间值。

**双堆**是经典解法：用两个堆把数据流切成两半：

- **小半堆 `s`**（大顶堆）：存放较小的一半元素，堆顶是这半的最大值。
- **大半堆 `b`**（小顶堆）：存放较大的一半元素，堆顶是这半的最小值。

维护一个关键约束：**`s` 的大小要么等于 `b`，要么比 `b` 多一个**。这样中位数要么是 `s` 的堆顶（奇数），要么是两个堆顶的平均值（偶数）。

插入时，新元素在两个堆之间"倒一手"，保证平衡：

- 两边相等时：新元素先入 `b`，再从 `b` 弹一个最小的给 `s`（`s` 多一个）。
- 两边不等时（`s` 多一个）：新元素先入 `s`，再从 `s` 弹一个最大的给 `b`（两边恢复相等）。

## 代码

```cpp
class MedianFinder {
    priority_queue<int, vector<int>, greater<>> b;   // 小顶堆：存较大的一半
    priority_queue<int> s;                            // 大顶堆：存较小的一半

public:
    MedianFinder() {}

    void addNum(int num) {
        if (s.size() == b.size()) {
            // 两边相等 → 新元素先进 b，b 再弹最小的给 s
            b.push(num);
            s.push(b.top());
            b.pop();
        } else {
            // s 多一个 → 新元素先进 s，s 再弹最大的给 b
            s.push(num);
            b.push(s.top());
            s.pop();
        }
    }

    double findMedian() {
        if (s.size() == b.size())
            return (s.top() + b.top()) / 2.0;   // 偶数：两堆顶平均
        else
            return s.top();                      // 奇数：s 堆顶
    }
};
```

## 代码分析

### 两个堆的含义

```cpp
priority_queue<int, vector<int>, greater<>> b;  // 小顶堆
priority_queue<int> s;                           // 大顶堆（默认）
```

C++ 中 `priority_queue` 默认是大顶堆，所以 `s` 是大顶堆，堆顶是较小一半中的最大值。`b` 用 `greater<>` 变成小顶堆，堆顶是较大一半中的最小值。

两个堆顶恰好是"中间"的两个元素（如果总数偶数），或者 `s` 的堆顶就是中位数（如果总数奇数）。

**关键约束**：`s.size() == b.size()` 或 `s.size() == b.size() + 1`。即 `s` 永远不比 `b` 少，且最多多一个。

### addNum：插入逻辑

```
         s (大顶堆)          b (小顶堆)
        [较小的一半]         [较大的一半]
        堆顶 = 最大值        堆顶 = 最小值
```

**情况一：`s.size() == b.size()`**

```cpp
b.push(num);
s.push(b.top());
b.pop();
```

此时两边相等，最终要让 `s` 多一个。新元素先放进 `b`，然后 `b` 弹出最小的元素给 `s`。这样 `s` 比 `b` 多一个，且 `b` 中的所有元素仍然 ≥ `s` 中的所有元素。

**为什么先入 `b` 再倒给 `s`？** 因为不确定 `num` 应该属于哪半。把 `num` 放入 `b`（较大半），`b` 自动弹出最小的那个，这个"最小的"一定是全局较小半中的最大值，完美放入 `s`。

**情况二：`s.size() > b.size()`**

```cpp
s.push(num);
b.push(s.top());
s.pop();
```

此时 `s` 多一个，最终要让两边相等。新元素先放进 `s`，然后 `s` 弹出最大的元素给 `b`。这样两边恢复相等，且 `b` 中所有元素仍然 ≥ `s` 中所有元素。

### findMedian：获取中位数

```cpp
if (s.size() == b.size())
    return (s.top() + b.top()) / 2.0;
else
    return s.top();
```

- 偶数：两个堆顶正好是中间的两个数，取平均。
- 奇数：`s` 多一个，堆顶就是中位数。

## 逐轮推演

以 `addNum(1), addNum(2), findMedian(), addNum(3), findMedian()` 为例：

| 操作 | s（大顶堆） | b（小顶堆） | 说明 |
|------|:---|:---|------|
| addNum(1) | `[1]` | `[]` | 相等，1→b→s |
| addNum(2) | `[1]` | `[2]` | 不等，2→s→b |
| findMedian() | — | — | s.top=1, b.top=2 → (1+2)/2=1.5 |
| addNum(3) | `[2, 1]` | `[3]` | 不等，3→s→b，s 堆顶为 2 |
| findMedian() | — | — | s.size≠b.size → s.top=2 |

---

再以 `addNum(5), addNum(15), addNum(1), addNum(3)` 为例：

| 操作 | s（大顶堆） | b（小顶堆） | 说明 |
|------|:---|:---|------|
| addNum(5) | `[5]` | `[]` | 相等，5→b→s |
| addNum(15) | `[5]` | `[15]` | 不等，15→s→b（s.top=15 弹给 b） |
| addNum(1) | `[5, 1]` | `[15]` | 相等，1→b→s（b.top=1 弹给 s） |
| addNum(3) | `[3, 1]` | `[5, 15]` | 不等，3→s→b（s.top=5 弹给 b） |

最终 `s = [3, 1]`（堆顶 3），`b = [5, 15]`（堆顶 5），中位数 = `(3+5)/2 = 4.0`。

---

## 复杂度分析

- **`addNum`**：O(log n)。每次最多 push 两次、pop 一次，堆操作都是 O(log n)。
- **`findMedian`**：O(1)。直接取堆顶。
- **空间复杂度**：O(n)，两个堆总共存储 n 个元素。

---

## 总结

这道题是堆的经典应用，核心是**用两个堆把数据流切成两半**：

1. `s`（大顶堆）存较小的一半，`b`（小顶堆）存较大的一半。
2. 插入时通过"倒一手"（先入一边再弹给另一边）维持平衡，无需判断 `num` 属于哪半。
3. 中位数始终在堆顶，O(1) 获取。

和 4. 寻找两个正序数组的中位数（分割线）相比，295 是动态版本——数据不断流入，双堆天然适合"维护中位数"的场景。和 215. 数组中的第K个最大元素（快速选择）相比，215 是静态的"找第 K 大"，295 是动态的"持续维护中位数"，堆的优势在于动态插入。
