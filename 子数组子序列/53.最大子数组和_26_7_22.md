# 最大子数组和（Maximum Subarray）题解

> 题目链接：[LeetCode 53. Maximum Subarray](https://leetcode.cn/problems/maximum-subarray/)

## 题目描述

给你一个整数数组 `nums`，请你找出一个具有最大和的连续子数组（子数组最少包含一个元素），返回其最大和。

**示例 1：**

```
输入：nums = [-2,1,-3,4,-1,2,1,-5,4]
输出：6
解释：连续子数组 [4,-1,2,1] 的和最大，为 6。
```

**示例 2：**

```
输入：nums = [1]
输出：1
```

**示例 3：**

```
输入：nums = [5,4,-1,7,8]
输出：23
```

---

## 核心思路

这道题的核心在于一个简单但关键的决策：**当遍历到 `nums[i]` 时，我该把它接到前面的子数组后面，还是另起炉灶？**

答案很直接：如果前面的子数组和是负数，那接上去只会拖后腿，不如从当前元素重新开始。如果前面的子数组和是正数，那接上去就有增益。

所以状态转移就是一个贪心选择：

```
now = max(now + nums[i], nums[i])
```

代码中我们把它展开成了 `if-else`，逻辑完全等价。

---

## 与滑动窗口最大值的区别

这道题和 [239. 滑动窗口最大值](../单调队栈/239.滑动窗口最大值_26_7_21.md) 都涉及「子数组」，但本质完全不同：

| 对比维度 | 53. 最大子数组和 | 239. 滑动窗口最大值 |
|---------|-----------------|-------------------|
| 窗口大小 | **不固定**，动态扩展/重置 | **固定为 k** |
| 核心操作 | 贪心决策：接续 or 重开 | 单调队列维护窗口内最大值 |
| 数据结构 | 无需额外结构 | 双端队列 `deque` |
| 时间复杂度 | O(n) | O(n) |
| 空间复杂度 | O(1) | O(k) |
| 关键思想 | 负数则断，正数则续 | 比我小的，在我出去前永无出头之日 |

**239 是窗口大小固定，要维护窗口内的最值**；**53 是窗口大小不固定，要决定窗口的起止位置**。一个是「给你一个框，框里找最大」，一个是「自己决定框多大，让框内和最大」。

## 代码

```cpp
class Solution {
public:
    int maxSubArray(vector<int>& nums) {
        int n = nums.size();
        int ans = -100001;                    // 答案，初始化为一个极小值
        int now = -100001;                    // 当前子数组和

        for (int i = 0; i < n; ++i) {
            if (now < 0) {
                now = nums[i];                // 前面的和是负数，另起炉灶
            } else {
                now += nums[i];               // 前面的和是正数，接上去
            }

            if (now > ans) {
                ans = now;                    // 更新全局最大
            }
        }
        return ans;
    }
};
```

---

## 代码分析

### 为什么 `now < 0` 就另起炉灶？

假设前面子数组的和是 -5，当前元素是 10。如果接上去，`now = -5 + 10 = 5`；如果另起炉灶，`now = 10`。显然 10 > 5，所以负数前缀应该果断丢弃。

更一般地，**任何负数前缀加上一个正数，结果一定小于这个正数本身**。所以 `now < 0` 时，`now + nums[i] < nums[i]`，另起炉灶总是更优。

### 全负数数组怎么办？

如果数组全是负数，比如 `[-3, -1, -2]`，算法会这样运行：

| i | nums[i] | now<0? | now | ans |
|---|---------|--------|-----|-----|
| 0 | -3 | 是 | -3 | -3 |
| 1 | -1 | 是 | -1 | -1 |
| 2 | -2 | 是 | -2 | -1 |

每次 `now < 0` 都会另起炉灶，最终答案是 -1（即最大的那个负数）。逻辑正确。

### 为什么 `ans` 和 `now` 初始化为 -100001？

题目中 `nums[i]` 的最小值是 -10^5，所以 -100001 比任何可能的值都小，确保第一次比较时 `ans` 会被正确更新。

## 逐轮推演

以 `nums = [-2,1,-3,4,-1,2,1,-5,4]` 为例：

| i | nums[i] | now<0? | now | ans | 说明 |
|---|---------|--------|-----|-----|------|
| 0 | -2 | 是 | -2 | -2 | 初始，另起炉灶 |
| 1 | 1 | 是 | 1 | 1 | 前值 -2<0，丢弃，重开 |
| 2 | -3 | 否 | -2 | 1 | 1>0，接上：1+(-3)=-2 |
| 3 | 4 | 是 | 4 | 4 | -2<0，丢弃，重开 |
| 4 | -1 | 否 | 3 | 4 | 4>0，接上：4+(-1)=3 |
| 5 | 2 | 否 | 5 | 5 | 3>0，接上：3+2=5 |
| 6 | 1 | 否 | 6 | 6 | 5>0，接上：5+1=6 |
| 7 | -5 | 否 | 1 | 6 | 6>0，接上：6+(-5)=1 |
| 8 | 4 | 否 | 5 | 6 | 1>0，接上：1+4=5 |

最终 `ans = 6`，对应子数组 `[4, -1, 2, 1]`。

---

## 复杂度分析

- **时间复杂度**：O(n)，一趟遍历。
- **空间复杂度**：O(1)，只用了 `ans` 和 `now` 两个变量。

## 总结

这道题虽然简单，但「负数则断，正数则续」的贪心思想很经典。它和 239 的对比体现了两种不同的子数组处理思路：

- **53**：窗口大小可变，核心是**决策**（接 or 不接）
- **239**：窗口大小固定，核心是**维护**（单调队列保最值）

理解这个区别，就能区分「最大子数组和」和「滑动窗口最值」这两类问题。
