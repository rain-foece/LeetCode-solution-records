# 和为 K 的子数组（Subarray Sum Equals K）题解

> 题目链接：[LeetCode 560. Subarray Sum Equals K](https://leetcode.cn/problems/subarray-sum-equals-k/)

## 题目描述

给你一个整数数组 `nums` 和一个整数 `k`，请你统计并返回该数组中和为 `k` 的子数组的个数。

子数组是数组中元素的连续非空序列。

**示例 1：**

```
输入：nums = [1,1,1], k = 2
输出：2
```

**示例 2：**

```
输入：nums = [1,2,3], k = 3
输出：2
```

---

## 核心思路概览

本文将从三个递进的版本展开，逐步将时间复杂度从 O(n²) 优化到 O(n)：

| 版本 | 方法 | 核心思想 |
|------|------|----------|
| 版本一 | 暴力枚举 | 两层循环枚举所有子数组起点和终点 |
| 版本二 | 前缀和 | 子数组和 = 两个前缀和之差，省去内层重复累加 |
| 版本三 | 前缀和 + 哈希表 | 边算前缀和边查哈希表，转化为两数之和问题 |

下面逐一分析。

---

## 版本一：暴力枚举

### 思路

我们很容易想到最暴力的解法：两层遍历，外层固定子数组起点，内层从起点向后累加，遇到和为 `k` 就计数。

### 代码

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        int n = nums.size(), ans = 0;

        for (int i = 0; i < n; ++i) {         // 枚举子数组起点
            int sum = 0;
            for (int j = i; j < n; ++j) {     // 枚举子数组终点
                sum += nums[j];               // 边扩展边累加
                if (sum == k) ++ans;          // 命中，计数 +1
            }
        }
        return ans;
    }
};
```

### 分析

最直观的解法，外层循环 O(n) 选起点，内层循环 O(n) 扩展终点并累加，每个子数组都被计算一次。

- **时间复杂度**：O(n²)，每个起点都遍历一次剩余元素。
- **空间复杂度**：O(1)。

**优点**：思路简单，代码好懂。

**缺点**：O(n²) 在大数据量下无法接受。有没有办法优化呢？

---

## 版本二：前缀和

### 思路

我们换个角度看问题。引入一个概念：设起点下标为 0 的子数组和称为「祖态」，起点下标从 1 开始的子数组和称为「中间态」。

那么，任意一个中间态子数组 `[i, j]` 的和，都可以表示为两个祖态的差：

```
sum(i, j) = prefix[j] - prefix[i-1]
```

其中 `prefix[x]` 表示 `nums[0] + nums[1] + ... + nums[x]`，即祖态。

这样一来，我们只需要先计算所有祖态，再去两两组合祖态，检查差值是否为 `k`，就得到了所有和为 `k` 的子数组——省去了内层循环中重复累加的开销。

### 代码

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        int n = nums.size(), ans = 0;
        vector<int> prefix(n + 1, 0);          // prefix[i] = nums[0..i-1] 的和

        for (int i = 0; i < n; ++i) {
            prefix[i + 1] = prefix[i] + nums[i]; // 计算所有祖态
        }

        for (int i = 0; i < n; ++i) {            // 枚举起点
            for (int j = i + 1; j <= n; ++j) {   // 枚举终点
                if (prefix[j] - prefix[i] == k) { // 祖态差 = 子数组和
                    ++ans;
                }
            }
        }
        return ans;
    }
};
```

### 分析

这一版把「边枚举边累加」变成了「先算前缀和，再组合」，内层循环不再需要累加，只需一次减法。

- **时间复杂度**：O(n²)，两层循环枚举起点和终点仍在。
- **空间复杂度**：O(n)，存储所有前缀和。

**优点**：思路更清晰，子数组和的计算变成了 O(1) 的减法。

**缺点**：时间复杂度还是 O(n²)，还是慢。还能再优化吗？

## 版本三：前缀和 + 哈希表（两数之和）

### 思路

当然可以！我们发现，如果一次性算完所有祖态，再去求组合方式还是很麻烦。

但注意到，计算祖态时我们是**自左向右**计算的，能不能边计算边组合呢？当然可以！

突然！！！我们注意到，两个祖态的计算，差为 `k`，这个神奇的 `k`。

**死去的两数之和又在攻击我！！！**

我们瞬间想到了哈希表。在遍历过程中，对于当前的前缀和 `add`，我们想知道前面有多少个前缀和等于 `add - k`。因为：

```
prefix[j] - prefix[i] = k
      ↑            ↑
   当前前缀和    前面某个前缀和
```

等价于：

```
prefix[i] = prefix[j] - k = add - k
```

所以问题转化为：遍历时，一边用哈希表记录每个前缀和出现的次数，一边查询 `add - k` 在哈希表中出现了多少次，累加到答案中。

和 [两数之和](https://leetcode.cn/problems/two-sum/) 的思路如出一辙：两数之和是找 `target - nums[i]`，而这题是找 `add - k`，只不过我们统计的是**出现次数**而非下标。

### 代码

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        int n = nums.size(), ans = 0;
        if (n == 0) return 0;

        unordered_map<int, int> hash;  // 键：前缀和，值：出现次数
        int add = 0;                   // 当前前缀和
        hash[0] = 1;                   // 空数组的前缀和为 0，出现 1 次

        for (int i = 0; i < n; ++i) {
            add += nums[i];            // 计算当前前缀和
            int target = add - k;      // 要找的前缀和 = 当前前缀和 - k

            if (hash.find(target) != hash.end()) {
                ans += hash[target];   // 之前有多少个前缀和等于 target，就有多少个子数组
            }

            ++hash[add];               // 当前前缀和计入哈希表
        }
        return ans;
    }
};
```

### 逐轮推演

以 `nums = [1, 2, 3], k = 3` 为例：

| 轮次 | i | nums[i] | add | target=add-k | hash 中 target? | ans | hash 更新后 |
|------|---|---------|-----|-------------|-----------------|-----|------------|
| 初始 | — | — | — | — | — | 0 | `{0:1}` |
| 1 | 0 | 1 | 1 | -2 | 无 | 0 | `{0:1, 1:1}` |
| 2 | 1 | 2 | 3 | 0 | 0 出现 1 次 | 1 | `{0:1, 1:1, 3:1}` |
| 3 | 2 | 3 | 6 | 3 | 3 出现 1 次 | 2 | `{0:1, 1:1, 3:1, 6:1}` |

最终 `ans = 2`，对应子数组 `[1,2]` 和 `[3]`。

再以 `nums = [1, -1, 0], k = 0` 为例，体会 `hash[0] = 1` 初始化的作用和负数的处理：

| 轮次 | i | nums[i] | add | target | hash 中 target? | ans | hash 更新后 |
|------|---|---------|-----|--------|-----------------|-----|------------|
| 初始 | — | — | — | — | — | 0 | `{0:1}` |
| 1 | 0 | 1 | 1 | 1 | 无 | 0 | `{0:1, 1:1}` |
| 2 | 1 | -1 | 0 | 0 | 0 出现 1 次 | 1 | `{0:2, 1:1}` |
| 3 | 2 | 0 | 0 | 0 | 0 出现 2 次 | 3 | `{0:3, 1:1}` |

最终 `ans = 3`，对应子数组 `[1,-1]`、`[0]` 和 `[1,-1,0]`。

### 分析

- **时间复杂度**：O(n)，一趟遍历，每次哈希表操作 O(1)。
- **空间复杂度**：O(n)，哈希表最多存储 n 个不同的前缀和。

**关键细节**：`hash[0] = 1`。为什么初始化时要给前缀和 0 记一次出现？因为当 `add == k` 时，`target = add - k = 0`，此时子数组 `[0, i]` 的和就是 `k`。如果不初始化 `hash[0] = 1`，这个子数组就会被漏掉。

---

## 总结

三个版本展示了和为 K 的子数组问题从「暴力」到「前缀和」再到「两数之和变体」的完整优化路径：

1. **版本一**（暴力枚举）：两层循环，边枚举边累加，O(n²) 时间，O(1) 空间。
2. **版本二**（前缀和）：引入祖态概念，子数组和 = 祖态差，省去内层累加，但仍是 O(n²)。
3. **版本三**（前缀和 + 哈希表）：在两数之和的思路启发下，边遍历边用哈希表统计，将问题转化为「当前前缀和 - k 出现过多少次」，一举降到 O(n)。

理解版本三的关键在于想清楚两点：**为什么需要 `hash[0] = 1`**（处理子数组从开头起的情况），以及**为什么哈希表存的是出现次数而非布尔值**（相同前缀和可能对应多个不同的子数组起点）。一旦想通，这道题就和两数之和一样简单了。
