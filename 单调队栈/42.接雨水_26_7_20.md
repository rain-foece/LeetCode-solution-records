# 接雨水（Trapping Rain Water）题解

> 题目链接：[LeetCode 42. Trapping Rain Water](https://leetcode.cn/problems/trapping-rain-water/)

## 题目描述

给定 `n` 个非负整数表示每个宽度为 `1` 的柱子的高度图，计算按此排列的柱子，下雨之后能接多少雨水。

![接雨水示意图](42_trapping_rain_water.png)

**示例 1：**

```
输入：height = [0,1,0,2,1,0,1,3,2,1,2,1]
输出：6
```

**示例 2：**

```
输入：height = [4,2,0,3,2,5]
输出：9
```

---

## 核心思路概览

本文将从三个递进的版本展开，后两个版本在空间和思维上各有突破：

| 版本 | 方法 | 核心思想 |
|------|------|----------|
| 版本一 | 前缀后缀最大值（DP） | 每个格子的水量 = min(左侧最大值, 右侧最大值) - 当前高度 |
| 版本二 | 双指针 + 就小原则 | 利用单调性，用两个变量代替两个数组，向中压缩 |
| 版本三 | 单调栈 | 按层计算，遇到高柱子时，回退清算中间凹陷处的积水 |

下面逐一分析。

---

## 版本一：前缀后缀最大值（DP 思想）

### 思路

对于每个单位宽度的柱子来说，它能接多少水呢？取决于它左右两侧最高柱子的较小者，减去自身高度。如果自身高度比两侧都高，那就接不到水。

这是一个很直观的「木桶原理」：一个格子能装的水，由它左右两边的「桶壁」决定，而桶壁的高度就是左右两侧的最大值，最终取较小的那个。

因此我们只需要预处理两个数组：
- `l[i]`：位置 `i` 左侧（含自身）的最大高度
- `r[i]`：位置 `i` 右侧（含自身）的最大高度

然后对于每个位置 `i`，水量 = `min(l[i], r[i]) - height[i]`。

### 代码

```cpp
class Solution {
public:
    int trap(vector<int>& height) {
        int n = height.size();
        vector<int> l(n);                     // l[i]：i 及左侧的最大高度
        vector<int> r(n);                     // r[i]：i 及右侧的最大高度

        l[0] = height[0];
        r[n - 1] = height[n - 1];

        // 一次遍历同时填充 l 和 r
        for (int i = 1; i < n; ++i) {
            l[i] = max(l[i - 1], height[i]);          // 向右更新左侧最大值
            r[n - 1 - i] = max(r[n - i], height[n - i - 1]); // 向左更新右侧最大值
        }

        int ans = 0;
        for (int j = 0; j < n; ++j) {
            ans += min(l[j], r[j]) - height[j];  // 木桶原理：取左右较小者
        }
        return ans;
    }
};
```

### 分析

这个版本是最基础的解法，思路清晰，三步走：预处理左侧最大值 → 预处理右侧最大值 → 逐个格子累加水量。

- **时间复杂度**：O(n)，三次遍历。
- **空间复杂度**：O(n)，两个长度为 n 的辅助数组。

**优点**：思路直接，代码好懂，是入门理解接雨水问题的最佳起点。

**缺点**：两个数组还是太占空间了，有没有办法省去这两个数组呢？

## 版本二：双指针 + 就小原则

### 思路

经过观察，我们发现两个关键性质：

**单调性**：随着我们向右扩展，左边最大值不可能减小！同理，向左扩展时，右边最大值也不可能减小！

**就小原则**：对于每个格子来说，它所能接的水取决于左右最大值中的较小者。这决定了我们压缩的方式。

有了这两个性质，我们就不需要记录每个位置的左右最大值了——只需要记录「当前已知的」左右最大值，然后从两侧向中间压缩。

具体来说，对于当前指针 `l` 或 `r` 所指的格子，只有两种情况：
- 情况一：`height[l]`（或 `height[r]`）比 `lm` 和 `rm` 都小，此时可以直接计算这个格子能接的水。
- 情况二：`height[l]`（或 `height[r]`）比 `lm` 或 `rm` 其中一个来得大，这时就要替换最大值了。从哪边扩展过来，就替换哪边。

举个例子：`lm = 9, rm = 10`。我们从左边扩展过来，那么从 `l` 到当前位置之间所有的格子都已经计算过了，所以用 `height[l]` 替换 `lm`。

每次比较 `lm` 和 `rm`，谁小就处理谁那一侧，然后往中间移动——这就是「就小原则」。

### 代码

```cpp
class Solution {
public:
    int trap(vector<int>& height) {
        int n = height.size(), ans = 0;
        int l = 0, r = n - 1;                     // 左右指针
        int lm = height[0], rm = height[n - 1];   // 左右已知最大值

        while (l < r) {
            if (height[l] > lm) lm = height[l];   // 更新左侧最大值
            if (height[r] > rm) rm = height[r];   // 更新右侧最大值

            if (lm <= rm) {
                ans += lm - height[l];  // 左侧较小，左端格子水量确定
                ++l;                    // 左指针右移
            } else {
                ans += rm - height[r];  // 右侧较小，右端格子水量确定
                --r;                    // 右指针左移
            }
        }
        return ans;
    }
};
```

### 分析

这个版本的精妙之处在于，它把版本一中「预先算好所有位置的最大值」变成了「边算边用」。

为什么 `lm <= rm` 时，`height[l]` 的水量就确定了？因为 `lm` 是 `height[l]` 左侧的最大值，而 `rm` 是右侧已知的最大值。既然 `lm` 已经小于等于 `rm`，那么 `height[l]` 的右侧最大值至少是 `rm`（可能更大），而左侧最大值就是 `lm`。所以 `height[l]` 的瓶颈就是 `lm`，水量 = `lm - height[l]`。

反过来，`lm > rm` 时，`height[r]` 的水量由 `rm` 决定，水量 = `rm - height[r]`。

每次只处理「瓶颈已确定」的那一侧，然后向中间收拢，直到两指针相遇。

- **时间复杂度**：O(n)，严格一趟遍历。
- **空间复杂度**：O(1)，只用了几个变量。

**优点**：空间从 O(n) 优化到 O(1)，且只需一趟遍历，代码优雅高效。

## 版本三：单调栈

### 思路

前两个版本的核心思想是「按列计算」——每个格子单独算自己能接多少水。但如果我们换一个角度来看这个问题呢？

不妨想象一下：下雨后，水会积在柱子之间的「凹陷」处。如果我们**从左往右**走，遇到高度递增的柱子时，水会从右边流走，存不住；遇到高度递减的柱子时，我们还没找到「右壁」，暂时不知道能存多少水。但当我们遇到一个比之前更高的柱子时，它就像一个「右壁」，把之前递减的柱子围成了一个水槽。

这个过程是不是很像**栈**？我们用一个栈来维护一个单调递减的序列。当遇到一个比栈顶更高的柱子时，说明找到了一个「右壁」，此时栈顶元素就是水槽的底部，栈顶的下一个元素就是水槽的「左壁」。于是这个水槽的宽度 = 右壁 - 左壁 - 1，高度 = min(左壁高, 右壁高) - 底部高，水量 = 宽度 × 高度。

注意，这里计算的是**横向一层**的水量，而不是一个格子的水量。每次弹出一个栈顶，就计算一层，这一层可能横跨多个格子。

### 代码

```cpp
class Solution {
public:
    int trap(vector<int>& height) {
        int n = height.size(), ans = 0;
        stack<int> s;                             // 单调递减栈，存下标

        for (int i = 0; i < n; ++i) {
            // 当前柱子比栈顶高，说明找到了一个"右壁"，可以结算积水
            while (!s.empty() && height[i] > height[s.top()]) {
                int top = s.top();                // 水槽底部
                s.pop();

                if (s.empty()) break;             // 没有左壁，无法积水

                int left = s.top();               // 水槽左壁
                int width = i - left - 1;         // 水槽宽度
                int h = min(height[i], height[left]) - height[top]; // 水槽高度
                ans += h * width;                 // 累加这一层的积水量
            }
            s.push(i);                            // 当前柱子入栈
        }
        return ans;
    }
};
```

### 逐轮推演

以 `height = [0,1,0,2,1,0,1,3,2,1,2,1]` 为例，演示单调栈的结算过程：

| 1 | 0 | 0 | `[0]` | 入栈 | — | 0 |

| | | | `[1]` | 入栈 | — | 0 |
| 3 | 2 | 0 | `[1,2]` | 入栈 | — | 0 |
| 4 | 3 | 2 | `[1,2]` | 2>0，弹出2，左壁=1 | 宽=1, 高=1-0=1 | 1 |
| | | | `[1]` | 2>1，弹出1，栈空 | — | 1 |
| | | | `[3]` | 入栈 | — | 1 |
| 5 | 4 | 1 | `[3,4]` | 入栈 | — | 1 |
| 6 | 5 | 0 | `[3,4,5]` | 入栈 | — | 1 |
| 7 | 6 | 1 | `[3,4,5]` | 1>0，弹出5，左壁=4 | 宽=1, 高=1-0=1 | 2 |
| | | | `[3,4]` | 1=1，不弹出 | — | 2 |
| | | | `[3,4,6]` | 入栈 | — | 2 |

### 分析

单调栈的视角与前两个版本完全不同：前两个版本是「纵向」按列计算，而单调栈是「横向」按层计算。每次遇到一个比栈顶高的柱子，就意味着找到了一个「右壁」，此时栈顶就是水槽底部，栈中下一个元素就是左壁，三者围成一个矩形的积水层。

- **时间复杂度**：O(n)，每个元素最多入栈和出栈各一次。
- **空间复杂度**：O(n)，最坏情况下栈中存 n 个元素（完全递减的数组）。

**优点**：思路新颖，从「按列」到「按层」的视角转换很有启发性，代码量不大。

**缺点**：思路不如前两个版本直观，需要理解栈的单调性维护和结算逻辑。

## 总结

三个版本展示了接雨水问题从「直观暴力」到「空间压缩」再到「视角转换」的三条路径：

1. **版本一**（前缀后缀最大值）：最直观，每个格子的水量 = min(左max, 右max) - 自身高度，空间 O(n)。
2. **版本二**（双指针 + 就小原则）：利用「左右最大值单调不减」和「就小原则」，用两个变量替换两个数组，空间降到 O(1)，一趟遍历完成。
3. **版本三**（单调栈）：转换视角，从「按列计算」变为「按层计算」，遇到高柱子时回退清算，同样 O(n) 时间。

理解版本二的关键在于理解为什么 `lm <= rm` 时 `height[l]` 的水量就确定了——因为左侧最大值已经是瓶颈，右侧哪怕有更高的柱子也改变不了这个事实。理解版本三的关键在于把栈想成一个「待定左壁」的队列，当右壁出现时，一次性结算中间所有凹陷层的水量。
