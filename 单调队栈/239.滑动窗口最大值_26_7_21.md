# 滑动窗口最大值（Sliding Window Maximum）题解

> 题目链接：[LeetCode 239. Sliding Window Maximum](https://leetcode.cn/problems/sliding-window-maximum/)

## 题目描述

给你一个整数数组 `nums`，有一个大小为 `k` 的滑动窗口从数组的最左侧移动到数组的最右侧。你只可以看到在滑动窗口内的 `k` 个数字。滑动窗口每次只向右移动一位。

返回滑动窗口中的最大值。

**示例 1：**

```
输入：nums = [1,3,-1,-3,5,3,6,7], k = 3
输出：[3,3,5,5,6,7]
解释：
滑动窗口的位置                最大值
---------------               -----
[1  3  -1] -3  5  3  6  7       3
 1 [3  -1  -3] 5  3  6  7       3
 1  3 [-1  -3  5] 3  6  7       5
 1  3  -1 [-3  5  3] 6  7       5
 1  3  -1  -3 [5  3  6] 7       6
 1  3  -1  -3  5 [3  6  7]      7
```

**示例 2：**

```
输入：nums = [1], k = 1
输出：[1]
```

---

## 核心思路

这个题涉及到元素的进出，跑不了栈和队列。仔细思考后这明显是队列。

依旧老套路细化问题。对于某一次窗口滑动，设窗口头元素为 `head`，即将进窗口的元素为 `index`。大的方面无非两种情况：

- **情况一**：`head` 元素不是窗口中最大的
- **情况二**：`head` 元素是窗口中最大的

每种大情况又可以细分：`index` 是否为窗口内最大元素。

我们想用队列表示元素的进出，但这远远不够，因为我们还要比较元素大小。

经过思考，我们发现一个关键性质：**如果 `index` 比队列中某些元素更大，那么在 `index` 出队前，那些比它小的元素都是"无用的"**——它们永远无法成为窗口中的最大值。

那我们就有了一个简单粗暴的策略：**每次只让比队尾元素更大的元素进队就行了！** 具体来说，在入队前，把队尾所有比 `index` 小的元素全部弹出，然后再让 `index` 入队。这样队列从头到尾始终保持**单调递减**，队首就是当前窗口的最大值。

这就是单调队列的核心思想。

## 代码

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> ans(n - k + 1);   // 窗口个数 = n - k + 1
        deque<int> q;                  // 双端队列，存下标

        for (int i = 0; i < n; i++) {
            // 1. 右边入：维护队列的单调递减性
            while (!q.empty() && nums[q.back()] <= nums[i]) {
                q.pop_back();          // 弹出所有比当前元素小的队尾
            }
            q.push_back(i);            // 当前元素入队（存下标，便于判断是否离开窗口）

            // 2. 左边出：检查队首是否已经滑出窗口
            int left = i - k + 1;      // 当前窗口的左端点
            if (q.front() < left) {    // 队首下标小于左端点，说明已离开窗口
                q.pop_front();
            }

            // 3. 记录答案：窗口形成后，队首即为最大值
            if (left >= 0) {
                ans[left] = nums[q.front()];
            }
        }

        return ans;
    }
};
```

## 算法分析

### 为什么存下标而不是存值？

队列中存的是下标，而不是值本身。原因很简单：我们需要判断队首元素是否已经滑出窗口。如果只存值，当窗口右移时，我们无法知道队首的值是否还属于当前窗口。存下标后，只需比较 `q.front() < left` 就能判断。

### 为什么队首一定是最大值？

因为我们在入队时，把所有比当前元素小的队尾都弹出了。这意味着队列从头到尾始终保持**严格单调递减**。队首是整个队列中最大的元素，而队列包含的元素都在当前窗口内，所以队首就是窗口最大值。

### 每个元素被操作多少次？

每个元素最多入队一次、出队一次（被弹出）。虽然内层有一个 `while` 循环，但每个元素被弹出的总次数不超过 1，所以整个算法的复杂度是 O(n) 而非 O(nk)。

## 复杂度分析

- **时间复杂度**：O(n)。每个元素最多入队一次、出队一次，内层 `while` 的总执行次数是 O(n)。
- **空间复杂度**：O(k)。队列中最多存储当前窗口内的元素，不超过 k 个。

## 总结

单调队列的精髓在于一句话：**比我小的，在我出去之前，你永远没有出头之日。**

所以每次入队时，把前面所有比自己小的都"踢出去"，队列始终保持单调递减，队首就是最大值。这种「维护单调性」的思想在算法中非常常见——单调栈也是同样的思路，只不过一个从队尾操作，一个从栈顶操作。

这道题是单调队列的经典入门题。理解它之后，类似的「滑动窗口最值」问题都可以用同样的思路解决。
