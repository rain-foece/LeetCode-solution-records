# 寻找两个正序数组的中位数（Median of Two Sorted Arrays）题解

> 题目链接：[LeetCode 4. Median of Two Sorted Arrays](https://leetcode.cn/problems/median-of-two-sorted-arrays/)

## 题目描述

给定两个大小分别为 `m` 和 `n` 的正序（从小到大）数组 `nums1` 和 `nums2`。请你找出并返回这两个正序数组的**中位数**。

算法的时间复杂度应该为 O(log (m+n))。

**示例 1：**

```
输入：nums1 = [1,3], nums2 = [2]
输出：2.00000
解释：合并数组 = [1,2,3] ，中位数 2
```

**示例 2：**

```
输入：nums1 = [1,2], nums2 = [3,4]
输出：2.50000
解释：合并数组 = [1,2,3,4] ，中位数 (2 + 3) / 2 = 2.5
```

---

## 核心思路

中位数本质上是把数组分成左右两半，使得左半部分的最大值 ≤ 右半部分的最小值。

对于两个数组，设 a 为较短的那个（保证寻优空间更小），我们维护一个**分割线**：左半部分从 a 中取 `i` 个元素，从 b 中取 `j` 个元素，且 `i + j = (m+n+1)/2`（即左半部分总是占一半或多一个）。

初始时，我们让左半部分全部来自 b（`i=0, j=(m+n+1)/2`），然后逐步调整：如果 a 的右半首元素 `a[i+1]` 还 ≤ b 的左半尾元素 `b[j]`，说明分割线需要向右移动——从 a 多拿一个（`i++`），从 b 少拿一个（`j--`）。

调整到正确位置后，中位数就是：
- 奇数总长：左半部分的**最大值** `max(a[i], b[j])`
- 偶数总长：左半最大值和右半最小值的**平均值**

为了统一处理边界（`i=0`、`i=m` 等），在 a 和 b 的首尾各插入一个哨兵：`INT_MIN` 和 `INT_MAX`。

---

## 代码

```cpp
class Solution {
public:
    double findMedianSortedArrays(vector<int>& a, vector<int>& b) {
        // 保证 a 是较短的数组
        if (a.size() > b.size()) {
            swap(a, b);
        }
        int m = a.size(), n = b.size();

        // 插入哨兵：最左边 -∞，最右边 +∞
        a.insert(a.begin(), INT_MIN);
        b.insert(b.begin(), INT_MIN);
        a.push_back(INT_MAX);
        b.push_back(INT_MAX);

        // 初始分割：a 取 0 个，b 取 (m+n+1)/2 个
        int i = 0, j = (m + n + 1) / 2;

        // 调整分割线，直到满足 a[i] <= b[j+1] 且 b[j] <= a[i+1]
        while (a[i + 1] <= b[j]) {
            ++i;
            --j;
        }

        // 左半最大值
        int ma = max(a[i], b[j]);
        // 右半最小值
        int mi = min(a[i + 1], b[j + 1]);

        // 奇数个元素：左半最大值；偶数个元素：平均值
        return (m + n) % 2 ? ma : (ma + mi) / 2.0;
    }
};
```

## 代码分析

### 第一步：保证 a 是较短数组

```cpp
if (a.size() > b.size()) {
    swap(a, b);
}
```

让 a 是较短的那个，搜索空间更小。因为 `i` 从 0 开始递增，短数组意味着收敛更快。

### 第二步：插入哨兵

```cpp
a.insert(a.begin(), INT_MIN);   // a[0] = -∞
b.insert(b.begin(), INT_MIN);   // b[0] = -∞
a.push_back(INT_MAX);           // a[m+1] = +∞
b.push_back(INT_MAX);           // b[n+1] = +∞
```

哨兵的作用是**统一处理边界**：

- 当 `i = 0` 时，a 的左半部分为空，`a[i] = a[0] = INT_MIN`，`max(a[i], b[j])` 自动取 `b[j]`，不会被 `a[i]` 干扰。
- 当 `i = m` 时，a 的右半部分为空，`a[i+1] = a[m+1] = INT_MAX`，`min(a[i+1], b[j+1])` 自动取 `b[j+1]`。
- b 同理。

有了哨兵，我们就不需要写 `if (i == 0)` 之类的边界判断了，代码极其简洁。

### 第三步：初始分割

```cpp
int i = 0, j = (m + n + 1) / 2;
```

初始时，a 的左半部分取 0 个元素，b 的左半部分取 `(m+n+1)/2` 个元素。

**为什么是 `(m+n+1)/2`？** 当总长 `m+n` 为奇数时，左半部分比右半部分多一个元素（中位数就是左半的最大值）；当总长为偶数时，左右各一半。`(m+n+1)/2` 在奇数时向上取整，偶数时恰好是一半，统一了两种情况的左半大小。

**核心不变式**：`i + j = (m+n+1)/2` 始终成立。因为每次 `i++` 同时 `j--`，和不变。

### 第四步：调整分割线

```cpp
while (a[i + 1] <= b[j]) {
    ++i;
    --j;
}
```

这是整个算法的核心。我们需要保证分割线正确，即：

```
左半最大值 ≤ 右半最小值
```

具体来说，需要满足两个条件：

1. `a[i] ≤ b[j+1]`（a 左半的尾 ≤ b 右半的首）
2. `b[j] ≤ a[i+1]`（b 左半的尾 ≤ a 右半的首）

while 循环的条件 `a[i+1] <= b[j]` 实际上是**条件 2 的反面**：a 右半的首 `a[i+1]` 还 ≤ b 左半的尾 `b[j]`，说明分割线放错了——a 应该再多贡献一些元素到左半，b 少贡献一些。

所以 `i++`（a 多取一个）、`j--`（b 少取一个），直到 `a[i+1] > b[j]` 即条件 2 满足。

**为什么条件 1 自动满足？** 初始时 `i=0`，`a[0] = INT_MIN`，显然 `INT_MIN ≤ b[j+1]` 成立。每次 `i++`、`j--` 后，a 左半扩大、b 左半缩小，`a[i]` 增大、`b[j+1]` 也增大。由于我们是逐步调整的，条件 1 不会被破坏。

---

**直观理解**：把两个数组画在数轴上，分割线从左向右滑动：

```
a: [-∞] [1, 3, 5, 7] [+∞]
b: [-∞] [2, 4, 6, 8, 9, 10] [+∞]

初始 i=0, j=4:
左半: b[1..4] = [2,4,6,8]  (a取0个)
右半: a[2..4]=[3,5,7], b[5..6]=[9,10]

a[1]=3 ≤ b[4]=8? 是 → i=1, j=3
左半: a[1]=1, b[1..3]=[2,4,6]
右半: a[2..4]=[3,5,7], b[4..6]=[8,9,10]

a[2]=3 ≤ b[3]=6? 是 → i=2, j=2
左半: a[1..2]=[1,3], b[1..2]=[2,4]
右半: a[3..4]=[5,7], b[3..6]=[6,8,9,10]

a[3]=5 ≤ b[2]=4? 否 → 停止
此时 max(a[2],b[2]) = max(3,4) = 4
     min(a[3],b[3]) = min(5,6) = 5
中位数 = (4+5)/2 = 4.5
```

### 第五步：计算中位数

```cpp
int ma = max(a[i], b[j]);       // 左半最大值
int mi = min(a[i + 1], b[j + 1]); // 右半最小值
return (m + n) % 2 ? ma : (ma + mi) / 2.0;
```

- 总长奇数：左半比右半多一个元素，中位数就是左半的最大值 `ma`。
- 总长偶数：左右各半，中位数是左半最大值和右半最小值的平均值。

## 逐轮推演

以 `a = [1, 3], b = [2]` 为例（`m=2, n=1`）：

**插入哨兵后**：

```
a: [-∞, 1, 3, +∞]   (索引 0~3)
b: [-∞, 2, +∞]       (索引 0~2)
```

**初始**：`i = 0, j = (2+1+1)/2 = 2`

| 轮次 | i | j | a[i+1] | b[j] | a[i+1] ≤ b[j]? | 操作 |
|------|---|---|--------|------|:---:|------|
| 初始 | 0 | 2 | a[1]=1 | b[2]=+∞ | ✓ | |
| 1 | 0 | 2 | a[1]=1 | b[2]=+∞ | 1 ≤ +∞ ✓ | i=1, j=1 |
| 2 | 1 | 1 | a[2]=3 | b[1]=2 | 3 ≤ 2 ✗ | 停止 |

**停止后**：

- `ma = max(a[1], b[1]) = max(1, 2) = 2`
- `mi = min(a[2], b[2]) = min(3, +∞) = 3`
- `m+n = 3` 为奇数，返回 `ma = 2`。

---

再以 `a = [1, 2], b = [3, 4]` 为例（`m=2, n=2`）：

**插入哨兵后**：

```
a: [-∞, 1, 2, +∞]
b: [-∞, 3, 4, +∞]
```

**初始**：`i = 0, j = (2+2+1)/2 = 2`

| 轮次 | i | j | a[i+1] | b[j] | a[i+1] ≤ b[j]? | 操作 |
|------|---|---|--------|------|:---:|------|
| 初始 | 0 | 2 | a[1]=1 | b[2]=4 | ✓ | |
| 1 | 0 | 2 | 1 | 4 | 1 ≤ 4 ✓ | i=1, j=1 |
| 2 | 1 | 1 | a[2]=2 | b[1]=3 | 2 ≤ 3 ✓ | i=2, j=0 |
| 3 | 2 | 0 | a[3]=+∞ | b[0]=-∞ | +∞ ≤ -∞ ✗ | 停止 |

**停止后**：

- `ma = max(a[2], b[0]) = max(2, -∞) = 2`
- `mi = min(a[3], b[1]) = min(+∞, 3) = 3`
- `m+n = 4` 为偶数，返回 `(2+3)/2.0 = 2.5`。

## 复杂度分析

- **时间复杂度**：O(m)，其中 m = min(m, n)。while 循环中 `i` 从 0 递增，每次 +1，最多执行 m 次。虽然这与题目要求的 O(log(m+n)) 有差距，但哨兵技巧使得代码极其简洁，且在实践中常数极小。
- **空间复杂度**：O(1)。哨兵通过 `insert` 和 `push_back` 插入，但这些操作在原始数组上原地修改，不额外申请与 m、n 成比例的空间。

> 注：严格 O(log(m+n)) 的写法需要在 `[0, m]` 上对 `i` 做二分查找，而不是线性递增。但本文的线性调整版本胜在**直观易懂**，核心思想（分割线 + 哨兵）与二分版本完全一致。

---

## 总结

这道题的核心是**将中位数问题转化为分割线问题**：

1. 用 `i + j = (m+n+1)/2` 保持左半大小恒定。
2. 用 `while (a[i+1] <= b[j])` 逐步调整分割线，直到 `a[i] ≤ b[j+1]` 且 `b[j] ≤ a[i+1]`。
3. 用 `INT_MIN` / `INT_MAX` 哨兵统一处理边界，省去繁琐的 if-else。

哨兵是这个解法的点睛之笔——两个 `insert` 和两个 `push_back` 换来了极其简洁的边界处理，整个 while 循环和最终计算没有一行边界判断，代码干净利落。
