# 判断栈序列

## 题目描述

给定两个整数序列 `pushed` 和 `popped`，每个序列的值都是**互不相同的**。当且仅当它们可能是在**最初为空**的栈上进行的一系列 push 和 pop 操作的结果时，返回 `true`；否则返回 `false`。

## 解题思路：模拟栈

核心思想是**模拟入栈和出栈的过程**：

1. 遍历 `pushed` 数组，依次将元素入栈
2. 每次入栈后，检查栈顶元素是否与当前 `popped` 指针所指的元素相同
3. 如果相同，则执行出栈操作，并移动 `popped` 指针
4. 重复上述过程直到无法再匹配
5. 最终若栈为空，说明序列合法

---

## 版本一：使用 STL stack（基础版）

```cpp
class Solution {
public:
    bool validateStackSequences(vector<int>& popped, vector<int>& pushed) {
        stack<int> stk;
        int j = 0, n = pushed.size();
        for (int i = 0; i < n; ++i) {
            stk.push(pushed[i]);              // 入栈
            while (!stk.empty() && stk.top() == popped[j]) {
                stk.pop();                     // 匹配则出栈
                ++j;
            }
        }
        return stk.empty();                    // 栈空则合法
    }
};
```

### 复杂度分析

| 指标 | 复杂度 |
|------|--------|
| 时间复杂度 | $O(n)$ — 每个元素最多入栈、出栈各一次 |
| 空间复杂度 | $O(n)$ — 最坏情况下需要额外存储 $n$ 个元素 |

> **说明**：这是最直观的写法，借助标准库的 `stack` 容器清晰地表达了"模拟栈"的语义。但缺点是需要额外的内存来存储栈中的元素。

## 版本二：原地模拟栈（进阶优化）

```cpp
class Solution {
public:
    bool validateStackSequences(vector<int>& pushed, vector<int>& popped) {
        int top = 0;          // 栈顶指针（同时也是栈的大小）
        int j = 0;            // popped 的索引指针

        for (int x : pushed) {
            pushed[top++] = x;               // 入栈：利用原数组前部作为栈空间
            while (top > 0 && pushed[top - 1] == popped[j]) {
                --top;                       // 出栈：移动栈顶指针即可
                ++j;
            }
        }
        return top == 0;                     // 栈空则合法
    }
};
```

### 复杂度分析

| 指标 | 复杂度 |
|------|--------|
| 时间复杂度 | $O(n)$ — 与版本一相同，每个元素最多处理两次 |
| 空间复杂度 | $O(1)$ — **仅使用了常数级别的额外变量** |

---

## 核心优化点解析

### 为什么空间复杂度能降到 $O(1)$？

版本二的关键洞察在于：

> **`pushed` 数组的前 $top$ 个位置天然就可以充当一个栈！**

具体来说：

- **入栈操作**：将新元素写入 `pushed[top]`，然后 `top++`
- **出栈操作**：只需 `top--`，无需真正删除数据（逻辑上该位置已不属于栈）
- **查看栈顶**：读取 `pushed[top - 1]`

```
pushed 数组的复用示意（假设 pushed = [1,2,3,4,5], popped = [4,5,3,2,1]）:

初始:  [1, 2, 3, 4, 5]   top=0
入1:   [1, 2, 3, 4, 5]   top=1   栈内容: [1]
入2:   [1, 2, 3, 4, 5]   top=2   栈内容: [1,2]
入3:   [1, 2, 3, 4, 5]   top=3   栈内容: [1,2,3]
入4:   [1, 2, 3, 4, 5]   top=4   栈内容: [1,2,3,4]  → 匹配popped[0]=4, 出栈!
       [1, 2, 3, 4, 5]   top=3   栈内容: [1,2,3]   → 匹配popped[1]=5? 不匹配
入5:   [1, 2, 3, 5, 5]   top=4   栈内容: [1,2,3,5]  → 匹配popped[1]=5, 出栈!
       ...以此类推
```

### 两种版本的对比总结

| 对比项 | 版本一 (STL stack) | 版本二 (原地模拟) |
|--------|---------------------|-------------------|
| 可读性 | 高，语义清晰 | 稍低，需要理解指针含义 |
| 空间开销 | $O(n)$ 额外空间 | $O(1)$ 额外空间 |
| 时间效率 | 相同 | 相同 |
| 适用场景 | 代码可读性优先 | 内存敏感场景 / 追求极致优化 |
