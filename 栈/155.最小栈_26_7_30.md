# 最小栈（Min Stack）题解

> 题目链接：[LeetCode 155. Min Stack](https://leetcode.cn/problems/min-stack/)

## 题目描述

设计一个支持 `push`、`pop`、`top` 操作，并能在常数时间内检索到最小元素的栈。

实现 `MinStack` 类：

- `MinStack()` 初始化堆栈对象。
- `void push(int val)` 将元素 `val` 推入堆栈。
- `void pop()` 删除堆栈顶部的元素。
- `int top()` 获取堆栈顶部的元素。
- `int getMin()` 获取堆栈中的最小元素。

**示例：**

```
输入：
["MinStack","push","push","push","getMin","pop","top","getMin"]
[[],[-2],[0],[-3],[],[],[],[]]

输出：
[null,null,null,null,-3,null,0,-2]

解释：
MinStack minStack = new MinStack();
minStack.push(-2);
minStack.push(0);
minStack.push(-3);
minStack.getMin();   --> 返回 -3
minStack.pop();
minStack.top();      --> 返回 0
minStack.getMin();   --> 返回 -2
```

---

## 核心思路

这道题的关键在于**如何在 O(1) 时间内获取最小值**。普通的栈 `pop` 之后，最小值可能已经被弹出了，无法快速恢复上一个最小值。

我们可以直接用两个数组，一个当作普通栈 `st`，一个当作最小数组 `preMin`。`preMin[i]` 表示前 `i+1` 个元素的最小值。

那很容易确定 `preMin[i] = min(preMin[i-1], st[i])`，当 `i = 0` 时 `preMin[0] = st[0]`。

这很明显是动态规划思想——每个位置的最小值可以从上一个位置推导出来。而 DP 往往是容易优化的：我们发现每一次只会用到 `preMin[i-1]`，所以完全可以省去 `preMin` 数组占用的空间。另外，C++ 允许我们直接用 `pair` 数据结构直接合并保存 `st` 和 `preMin`：

- `pair.first`：当前元素值
- `pair.second`：到当前位置为止的最小值

栈底放一个哨兵 `(0, INT_MAX)`，保证 `push` 时 `min(getMin(), val)` 不会因为栈空而出错，也使栈底最小值的语义自然成立（最小值初始为 `INT_MAX`）。

---

## 代码

```cpp
class MinStack {
    stack<pair<int, int>> st;

public:
    MinStack() {
        st.emplace(0, INT_MAX);     // 哨兵：值无意义，最小值为 INT_MAX
    }

    void push(int val) {
        st.emplace(val, min(getMin(), val));
    }

    void pop() {
        st.pop();
    }

    int top() {
        return st.top().first;
    }

    int getMin() {
        return st.top().second;
    }
};
```

---

## 代码分析

### 数据结构

```cpp
stack<pair<int, int>> st;
```

`pair<int, int>` 中：
- `first`：压入的值（对应普通栈的 `st[i]`）
- `second`：从栈底到当前位置的最小值（对应 `preMin[i]`）

### 哨兵初始化

```cpp
MinStack() {
    st.emplace(0, INT_MAX);
}
```

栈底压入一个哨兵 `(0, INT_MAX)`。`0` 无实际意义，纯粹占位；`INT_MAX` 作为最小值的初始值，保证 `push` 时 `min(INT_MAX, val) = val`，第一个元素的最小值就是它自身。

有了哨兵，`getMin()` 永远不会面对空栈，`pop()` 也不会把哨兵弹掉（因为哨兵始终在栈底，而题目保证不会对空栈调用 `pop`）。

### push

```cpp
void push(int val) {
    st.emplace(val, min(getMin(), val));
}
```

每次压入时，新元素的最小值 = `min(之前的最小值, 当前值)`。这正是 DP 的状态转移：`preMin[i] = min(preMin[i-1], st[i])`。

`emplace` 直接在栈上原地构造 `pair`，比 `push(make_pair(...))` 少一次拷贝。

### pop

```cpp
void pop() {
    st.pop();
}
```

直接弹出栈顶。由于哨兵的存在，栈永远不会空，所以不需要额外判空。

### top 和 getMin

```cpp
int top() {
    return st.top().first;
}

int getMin() {
    return st.top().second;
}
```

`top()` 返回栈顶元素的值（`first`），`getMin()` 返回当前最小值（`second`）。两者都是 O(1)。

## 逐轮推演

以 `["MinStack", "push(-2)", "push(0)", "push(-3)", "getMin", "pop", "top", "getMin"]` 为例：

| 操作 | 栈内容（first, second） | 说明 |
|------|:---|------|
| 初始化 | (0, INT_MAX) | 哨兵入栈 |
| push(-2) | (0, INT_MAX), **(-2, -2)** | min(INT_MAX, -2) = -2 |
| push(0) | (0, INT_MAX), (-2, -2), **(0, -2)** | min(-2, 0) = -2 |
| push(-3) | (0, INT_MAX), (-2, -2), (0, -2), **(-3, -3)** | min(-2, -3) = -3 |
| getMin() | — | 返回栈顶 second = -3 |
| pop() | (0, INT_MAX), (-2, -2), (0, -2) | 弹出 (-3, -3) |
| top() | — | 返回栈顶 first = 0 |
| getMin() | — | 返回栈顶 second = -2 |

可以看到，`pop` 后最小值自动恢复为 `-2`，因为 `pair` 把每个位置的最小值都"快照"下来了。

## 复杂度分析

- **时间复杂度**：所有操作均为 O(1)。
- **空间复杂度**：O(n)，每个元素用一个 `pair` 存储，常数因子为 2。

---

## 总结

这道题的精髓在于**把"最小值"和历史状态绑定**——每个元素入栈时，顺便记录"到当前为止的最小值"。这样 `pop` 之后，前一个元素身上的最小值自然恢复，无需额外计算。

从 DP 角度看，`preMin[i] = min(preMin[i-1], st[i])` 是一个简单的状态转移，且只依赖前一项，因此可以压缩到 O(1) 额外空间。`pair` 只是把两个栈合并成一个的语法糖，逻辑上等价于双栈方案。

这种"额外维护一个属性随元素入栈"的思路，在 239. 滑动窗口最大值（单调队列记录最大值）和 42. 接雨水（前缀最大值）中也有体现，本质都是空间换时间。
