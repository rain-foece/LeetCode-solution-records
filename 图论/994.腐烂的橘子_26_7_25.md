# 腐烂的橘子（Rotting Oranges）题解

> 题目链接：[LeetCode 994. Rotting Oranges](https://leetcode.cn/problems/rotting-oranges/)

## 题目描述

在给定的 `m × n` 网格 `grid` 中，每个单元格可以有以下三个值之一：

- 值 `0` 代表空单元格；
- 值 `1` 代表新鲜橘子；
- 值 `2` 代表腐烂的橘子。

每分钟，腐烂的橘子**周围 4 个方向上相邻**的新鲜橘子都会腐烂。

返回直到单元格中没有新鲜橘子为止所必须经过的最小分钟数。如果不可能，返回 `-1`。

**示例 1：**

```
输入：grid = [[2,1,1],[1,1,0],[0,1,1]]
输出：4
```

**示例 2：**

```
输入：grid = [[2,1,1],[0,1,1],[1,0,1]]
输出：-1
解释：左下角的橘子（第 2 行，第 0 列）永远不会腐烂，因为腐烂只会发生在 4 个方向上。
```

**示例 3：**

```
输入：grid = [[0,2]]
输出：0
解释：因为 0 分钟时已经没有新鲜橘子了，所以答案就是 0。
```

---

## 核心思路

这道题是经典的**多源 BFS**。初始时可能存在多个腐烂橘子，它们同时开始向外扩散，每分钟扩散一轮。我们需要统计扩散完所有新鲜橘子所需的轮数。

和 [200. 岛屿数量](200.岛屿数量_26_7_25.md) 的 DFS 不同，这道题必须用 BFS——因为腐烂是「逐层扩散」的，我们需要知道**第几分钟**腐烂到哪个橘子，这恰好对应 BFS 的层级。

关键的实现技巧：**用两个容器交替**。一个容器 `q` 存当前轮要扩散的腐烂橘子，另一个容器 `tmp` 存下一轮被腐蚀的新橘子。每轮结束后 `q = move(tmp)`，清空旧容器，开始新一轮。

## 代码

```cpp
class Solution {
    // 方向数组：上、下、左、右
    int D[4][2] = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

public:
    int orangesRotting(vector<vector<int>>& grid) {
        int n = grid.size(), m = grid[0].size();
        int fresh = 0;                          // 新鲜橘子计数

        vector<pair<int, int>> q;               // 当前轮要扩散的腐烂橘子
        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < m; ++j) {
                if (grid[i][j] == 1) ++fresh;
                else if (grid[i][j] == 2) {
                    q.push_back({i, j});        // 初始腐烂橘子入队
                }
            }
        }

        int ans = 0;
        while (fresh && !q.empty()) {
            ++ans;                               // 新的一轮
            vector<pair<int, int>> tmp;          // 下一轮要扩散的橘子

            for (auto &[x, y] : q) {
                for (int k = 0; k < 4; ++k) {    // 四个方向
                    int i = x + D[k][0];
                    int j = y + D[k][1];

                    if (i >= 0 && i < n && j >= 0 && j < m && grid[i][j] == 1) {
                        grid[i][j] = 2;          // 腐蚀
                        --fresh;                 // 新鲜橘子减一
                        tmp.push_back({i, j});   // 加入下一轮扩散队列
                    }
                }
            }
            q = move(tmp);                       // 下一轮变为当前轮
        }

        return fresh ? -1 : ans;                 // 还有新鲜橘子 → 不可能
    }
};
```

## 代码分析

### 方向数组：用数组编码方向的思想

这是本题最值得学习的技巧，也是很多图论遍历题都会用到的写法：

```cpp
int D[4][2] = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
```

这 4 对数字分别代表四个方向的**坐标偏移量**：

| 索引 | D[k] | 含义 | 坐标变化 |
|------|------|------|----------|
| k=0 | `{-1, 0}` | 上 | i 减 1，j 不变 |
| k=1 | `{1, 0}` | 下 | i 加 1，j 不变 |
| k=2 | `{0, -1}` | 左 | i 不变，j 减 1 |
| k=3 | `{0, 1}` | 右 | i 不变，j 加 1 |

使用时，用一个 `for` 循环遍历四个方向：

```cpp
for (int k = 0; k < 4; ++k) {
    int i = x + D[k][0];  // 新行号
    int j = y + D[k][1];  // 新列号
}
```

**为什么不用四个 `if` 分别写？** 对比一下：

```cpp
// 方式一：方向数组（推荐）
for (int k = 0; k < 4; ++k) {
    int i = x + D[k][0], j = y + D[k][1];
    if (i >= 0 && i < n && j >= 0 && j < m && grid[i][j] == 1) {
        // 处理...
    }
}

// 方式二：四个 if（不够优雅）
if (x > 0 && grid[x-1][y] == 1) { /* ... */ }
if (x < n-1 && grid[x+1][y] == 1) { /* ... */ }
if (y > 0 && grid[x][y-1] == 1) { /* ... */ }
if (y < m-1 && grid[x][y+1] == 1) { /* ... */ }
```

方向数组的优势：
- **代码量少**：一行循环代替四段重复代码
- **易扩展**：如果题目变成 8 方向（加上对角线），只需在 `D` 数组中加 4 个元素
- **统一边界检查**：`0 <= i < n && 0 <= j < m` 一视同仁

这个技巧在 [200. 岛屿数量](200.岛屿数量_26_7_25.md) 中也可以使用（那道题用了四个 `if`，正是为了让你对比两种写法）。

### 两个容器交替：实现逐轮推进

这是本题另一大核心技巧。由于题目要求「每分钟腐烂一次」，我们需要知道每轮扩散到了哪些橘子，而不能一股脑全扩散。

```cpp
while (fresh && !q.empty()) {
    ++ans;
    vector<pair<int, int>> tmp;      // 下一轮的新腐烂橘子

    for (auto &[x, y] : q) {         // 遍历当前轮的所有腐烂橘子
        // 四个方向扩散...
        tmp.push_back({i, j});       // 新腐烂的加入下一轮
    }

    q = move(tmp);                    // 下一轮变为当前轮
}
```

关键点：**不能边扩散边把新腐烂的橘子直接加入 `q`**，否则一轮中就会扩散很多轮，分钟数就错了。必须先把本轮所有腐烂橘子扩散完，收集到 `tmp` 中，一轮结束后再 `q = move(tmp)`。

这个技巧本质上就是 BFS 的「按层遍历」——每层对应一分钟。

### 初始状态处理

```cpp
int fresh = 0;
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < m; ++j) {
        if (grid[i][j] == 1) ++fresh;          // 统计新鲜橘子
        else if (grid[i][j] == 2) {
            q.push_back({i, j});                // 腐烂橘子作为 BFS 起点
        }
    }
}
```

两个细节：
- `fresh` 既用于判断是否还有新鲜橘子，也用于提前终止循环（`fresh == 0` 时 `while` 停止）
- 所有初始腐烂橘子同时入队，体现了**多源 BFS**——多个起点同时开始扩散

### 最终判断

```cpp
return fresh ? -1 : ans;
```

如果 `fresh > 0`，说明有橘子被隔离了（比如被 `0` 包围），无法被腐蚀，返回 `-1`。否则返回轮数 `ans`。

## 逐轮推演

以 `grid = [[2,1,1],[1,1,0],[0,1,1]]` 为例：

```
初始：
2 1 1
1 1 0
0 1 1

fresh = 6, q = [(0,0)]
```

| 轮次 | q（当前轮） | 扩散方向 | 新腐烂的橘子 | tmp（下一轮） | fresh 剩余 |
|------|-----------|---------|-------------|-------------|-----------|
| 初始 | `[(0,0)]` | — | — | — | 6 |
| 1 | `[(0,0)]` | 右、下 | `(0,1), (1,0)` | `[(0,1), (1,0)]` | 4 |
| 2 | `[(0,1), (1,0)]` | 各方向 | `(0,2), (1,1)` | `[(0,2), (1,1)]` | 2 |
| 3 | `[(0,2), (1,1)]` | 各方向 | `(2,1)` | `[(2,1)]` | 1 |
| 4 | `[(2,1)]` | 各方向 | `(2,2)` | `[(2,2)]` | 0 |

`fresh = 0`，循环结束，返回 `ans = 4`。

**网格变化过程：**

```
第 0 分钟：    第 1 分钟：    第 2 分钟：    第 3 分钟：    第 4 分钟：
2 1 1         2 2 1         2 2 2         2 2 2         2 2 2
1 1 0    →    2 1 0    →    2 2 0    →    2 2 0    →    2 2 0
0 1 1         0 1 1         0 1 1         0 2 1         0 2 2
```

## 复杂度分析

- **时间复杂度**：O(n × m)。每个格子最多入队一次、出队一次。
- **空间复杂度**：O(n × m)。两个容器 `q` 和 `tmp` 最多存储所有橘子。

## 总结

这道题是 BFS 的经典应用，有两个核心技巧值得记住：

1. **方向数组** `int D[4][2] = {{-1,0},{1,0},{0,-1},{0,1}}`：用数组编码四个方向，一行循环代替四段重复代码，易扩展、易维护。

2. **两个容器交替**：`q` 存当前轮，`tmp` 存下一轮，一轮结束后 `q = move(tmp)`。这是实现「逐轮推进」的标准写法，在需要记录「层数」或「轮次」的 BFS 中非常常见。

和 [200. 岛屿数量](200.岛屿数量_26_7_25.md) 对比：

| 对比维度 | 200. 岛屿数量 | 994. 腐烂的橘子 |
|---------|-------------|----------------|
| 遍历方式 | DFS（递归洪水填充） | BFS（多源逐轮扩散） |
| 核心操作 | 淹没整片连通区域 | 逐轮腐蚀相邻橘子 |
| 边界检查 | 四个 `if` 分别判断 | 方向数组 + 统一边界判断 |
| 计数方式 | 每发现一个 `'1'` 计数 | 每扩散一轮 +1 分钟 |
| 多源处理 | 不需要（DFS 一次处理一个岛） | 初始所有腐烂橘子同时入队 |
| 轮次控制 | 不适用 | 两个容器交替（q → tmp） |

两道题一个用 DFS 解决连通分量计数，一个用 BFS 解决多源扩散计时，是图论遍历的两种经典范式。方向数组的技巧在 BFS 中尤其常见，但在 DFS 中同样好用——把 200 题的四个 `if` 改成方向数组循环，代码会更简洁。
