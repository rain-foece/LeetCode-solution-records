# 课程表（Course Schedule）题解

> 题目链接：[LeetCode 207. Course Schedule](https://leetcode.cn/problems/course-schedule/)

## 题目描述

你这个学期必须选修 `numCourses` 门课程，记为 `0` 到 `numCourses - 1`。

在选修某些课程之前需要一些先修课程。先修课程按数组 `prerequisites` 给出，其中 `prerequisites[i] = [ai, bi]`，表示如果要学习课程 `ai` 则必须先学习课程 `bi`。

例如，先修课程对 `[0, 1]` 表示：想要学习课程 `0`，你需要先完成课程 `1`。

请你判断是否可能完成所有课程的学习？如果可以，返回 `true`；否则，返回 `false`。

**示例 1：**

```
输入：numCourses = 2, prerequisites = [[1,0]]
输出：true
解释：总共有 2 门课程。学习课程 1 之前，你需要完成课程 0。这是可能的。
```

**示例 2：**

```
输入：numCourses = 2, prerequisites = [[1,0],[0,1]]
输出：false
解释：总共有 2 门课程。学习课程 1 之前，你需要先完成课程 0；
并且学习课程 0 之前，你还应先完成课程 1。这是不可能的。
```

---

## 核心思路概览

这道题本质上是**检测有向图中是否存在环**。课程 = 节点，先修关系 = 有向边（`bi → ai`）。如果图中存在环，说明有循环依赖，无法完成所有课程。

本文将从两个版本展开：

| 版本 | 方法 | 核心思想 |
|------|------|----------|
| 版本一 | DFS + 三色标记 | 递归遍历，用颜色标记节点状态，发现回边即存在环 |
| 版本二 | BFS + 拓扑排序（Kahn 算法） | 从入度为 0 的节点出发，逐层剥离，统计能否遍历所有节点 |

---

## 版本一：DFS + 三色标记

### 思路

最容易想到的办法就是 DFS 遍历整张图，检测是否有环。但怎么检测呢？

用「染色」的方式来标记每个节点的状态。乍一看只需要两种颜色（遍历过 / 未遍历过），但仔细想想，遍历过也分为两种：**正在遍历中**（当前 DFS 路径上的节点）和**已遍历完**（该节点出发的所有路径都检查过了，没有环）。

所以我们需要**三种颜色**：

| 颜色 | 含义 |
|------|------|
| `0` | 未遍历 |
| `1` | 遍历中（当前 DFS 路径上，正在访问） |
| `2` | 已遍历完成（该节点出发的所有路径都已检查，无环） |

如果在 DFS 过程中遇到了颜色为 `1` 的节点，说明当前路径上出现了**回边**（back edge），即存在环。

### 代码

```cpp
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        // 建图：g[i] 表示修完课程 i 后可以修哪些课程
        vector<vector<int>> g(numCourses);
        for (auto &p : prerequisites) {
            g[p[1]].push_back(p[0]);       // bi → ai
        }

        vector<int> color(numCourses);     // 0=未遍历, 1=遍历中, 2=已完成

        // DFS 返回 true 表示存在环
        auto dfs = [&](this auto&& dfs, int x) -> bool {
            color[x] = 1;                   // 标记为"遍历中"

            for (int j : g[x]) {
                // 遇到遍历中的节点 → 回边，有环
                // 或者未遍历的节点递归下去发现了环
                if (color[j] == 1 || (color[j] == 0 && dfs(j)))
                    return true;
            }

            color[x] = 2;                   // 标记为"已完成"，无环
            return false;
        };

        // 遍历所有节点（图可能不连通）
        for (int i = 0; i < numCourses; ++i) {
            if (color[i] == 0 && dfs(i))
                return false;               // 发现环
        }

        return true;
    }
};
```

### 分析

#### 三色标记的精妙之处

为什么不能用两色？来看一个反例：

```
1 → 2 → 3
    ↑___↓
```

如果只有两色（0=未遍历，1=已遍历），从节点 1 出发：`1 → 2 → 3 → 回到 2`。此时 2 已被标记为「已遍历」，我们无法区分「2 是当前路径上的节点」还是「2 是之前某次遍历完成的节点」。如果误判为「之前遍历过」，就会漏掉这个环。

三色标记解决了这个问题：`1` 表示「正在当前路径上」，`2` 表示「之前已确认无环」。遇到 `1` 才是真正的回边，遇到 `2` 可以直接跳过。

#### 递归条件解析

```cpp
if (color[j] == 1 || (color[j] == 0 && dfs(j)))
    return true;
```

这个条件等价于：

```
如果 (j 正在遍历中) 或 (j 未遍历 且 从 j 出发发现了环)：
    返回 true（存在环）
```

注意 `color[j] == 0 && dfs(j)` 中的短路求值：只有 `color[j] == 0` 时才会调用 `dfs(j)`，避免了重复遍历。

#### 为什么需要遍历所有节点？

图可能不连通。比如有两组互不相关的课程，第一组没环、第二组有环。如果只从节点 0 开始 DFS，就会漏掉第二组的环。所以外层循环遍历所有节点，每个未遍历的节点都作为 DFS 起点。

## 版本二：BFS + 拓扑排序（Kahn 算法）

### 思路

另一个角度：如果能完成所有课程，就存在一个合法的学习顺序。这个顺序就是**拓扑排序**。

Kahn 算法的核心是：不断移除**入度为 0** 的节点（即没有前置依赖的课程），每移除一个就把它的后继节点的入度减一。如果最终能移除所有节点，说明无环；否则剩余的节点构成了环。

### 代码

```cpp
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        vector<vector<int>> g(numCourses);
        vector<int> indegree(numCourses);    // 入度：有多少门前置课程

        for (auto &p : prerequisites) {
            g[p[1]].push_back(p[0]);         // bi → ai
            ++indegree[p[0]];                // ai 的入度 +1
        }

        queue<int> q;
        for (int i = 0; i < numCourses; ++i) {
            if (indegree[i] == 0)             // 没有前置依赖的课程入队
                q.push(i);
        }

        int visited = 0;                      // 成功学习的课程数
        while (!q.empty()) {
            int u = q.front(); q.pop();
            ++visited;

            for (int v : g[u]) {
                if (--indegree[v] == 0)       // 前置依赖全部满足
                    q.push(v);
            }
        }

        return visited == numCourses;         // 全部学完 = 无环
    }
};
```

### 分析

Kahn 算法的直觉很简单：**先学不需要前置的课程，学完后它们的后续课程就少了一个依赖。不断重复，直到学完所有课程或卡住**。

如果 `visited == numCourses`，说明所有课程都能按顺序学完。如果 `visited < numCourses`，说明剩下的课程互相依赖形成环，无法完成。

和版本一的 DFS 对比：

| 对比维度 | DFS + 三色标记 | BFS + 拓扑排序 |
|---------|--------------|--------------|
| 遍历方式 | DFS 递归 | BFS 队列 |
| 环检测 | 遇到颜色 1 的节点 | visited < numCourses |
| 空间复杂度 | O(n) 递归栈 | O(n) 队列 |
| 额外数组 | color（3 种状态） | indegree（入度计数） |
| 能否输出顺序 | 需要额外记录 | 天然输出拓扑序 |

两种方法都能 O(n + m) 完成，选择哪种主要看个人喜好。BFS 版本不需要递归，没有栈溢出风险；DFS 版本的三色标记思想在更复杂的图论问题中也是常用技巧。

## 逐轮推演

### 版本一：DFS + 三色标记

以 `numCourses = 4, prerequisites = [[0,1],[1,2],[2,3],[3,1]]` 为例：

```
图结构：1 → 0
       ↑ ↘
       3 ← 2
环：1 → 2 → 3 → 1
```

**DFS 从节点 0 开始：**

| 步骤 | 当前节点 | color 变化 | 遇到 | 操作 |
|------|---------|-----------|------|------|
| 1 | 0 | 0→1 | — | 进入 0，无后继，标记为 2 |
| 2 | — | 0→2 | — | 0 完成，无环 |
| 3 | 1 | 0→1 | — | 进入 1，后继有 0 和 2 |
| 4 | — | — | 0 是颜色 2 | 跳过（已确认无环） |
| 5 | — | — | 2 是颜色 0 | 递归进入 2 |
| 6 | 2 | 0→1 | — | 进入 2，后继有 3 |
| 7 | — | — | 3 是颜色 0 | 递归进入 3 |
| 8 | 3 | 0→1 | — | 进入 3，后继有 1 |
| 9 | — | — | 1 是颜色 1！ | **发现回边，有环！** |

返回 `false`。

### 版本二：BFS + 拓扑排序

同样的例子，初始入度：

```
节点 0：入度 1（来自 1）
节点 1：入度 1（来自 3）
节点 2：入度 1（来自 1）
节点 3：入度 1（来自 2）

没有入度为 0 的节点！队列为空，visited = 0 < 4，返回 false。
```

---

## 复杂度分析

两个版本的时间和空间复杂度相同：

- **时间复杂度**：O(n + m)，其中 n 是课程数，m 是先修关系数。每个节点和每条边最多被访问一次。
- **空间复杂度**：O(n + m)，邻接表存储图占用 O(n + m)，辅助数组（color 或 indegree + queue）占用 O(n)。

---

## 总结

这道题是拓扑排序的经典入门题。核心是**检测有向图中的环**，两种方法各有千秋：

- **DFS 三色标记**：需要理解为什么必须用三种颜色（`1` 表示当前路径上的节点，`2` 表示已确认无环的节点），这是很多图论环检测问题的基础。
- **BFS 拓扑排序**：更直观——不断移除入度为 0 的节点，最后剩下的是环。代码简洁，不需要递归，还能顺便输出拓扑序。

和 [200. 岛屿数量](200.岛屿数量_26_7_25.md) 的 DFS 洪水填充、[994. 腐烂的橘子](994.腐烂的橘子_26_7_25.md) 的 BFS 多源扩散一样，这道题再次体现了 DFS 和 BFS 在图论中的两种经典应用场景——一个深入探索结构，一个逐层推进扩散。
